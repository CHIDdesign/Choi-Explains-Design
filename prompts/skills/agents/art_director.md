# 스킬 — 🧐 아트 디렉터(흐리게 보고, 재고, 숫자로 고친다)

렌더된 정지 프레임, 움직임 스트립(`g#seq`), 폰 크기 시트(`phone`)를 R1~R18 로 검수할 때 적용한다. 판정은 "좋아 보인다"가 아니라 잰 값이다.
순서는 흐리게 보기(초점) → 재기(크기·대비·여백) → 움직임 → 영상 전체다. 모든 지적에는 숫자로 된 고칠 방법을 붙인다.

## 1. 보는 순서 — 크리틱 절차

1. **흐리게 보기**(squint test): `phone` 시트(폭 480px)를 먼저 본다. 세부가 사라져도 초점이 한 곳으로 분명한지 본다.
   의도하지 않은 것이 튀는지, 같은 역할이 같아 보이는지도 본다. 여기서 걸리면 R1·R2 다.
2. **재기**: 글자 크기(px), 크기 비, 대비, 여백, 안전 영역, 채움(%)을 잰다. 잰 값은 그대로 `measured` 에 적는다.
3. **움직임**: `g#seq` 여섯 칸을 본다.
   - +0.5초 칸: 무대가 비어 있지 않은가.
   - 15%·40% 칸: 동시에 몇 개가 움직이는가.
   - 안착 칸: 글자가 선명한가.
   - 사건 칸: 무엇이 바뀌는가.
   - 퇴장 직전 칸: 문장이 끝나는 자리인가.
4. **영상 전체**(R18): 전사본과 그래픽 목록으로 되풀이, 순서, 한쪽 쏠림을 본다.
5. 크리틱 문장은 "무엇이 어디서 어떻게 보이나 → 어떤 원칙에 어긋나나 → 숫자로 된 수정" 순서로 쓴다. 잘된 점은 summary 에 한 줄만 적는다. 취향 문제는 low 로 둔다.

## 2. 위계와 대비 — CRAP 과 게슈탈트

6. **대비**(Robin Williams): 같은 단위가 아니면 아주 다르게 만든다. 크기 비가 1.1~1.3 이면 실수처럼 보인다.
   가장 큰 글자 ÷ 둘째 ≥ 1.6 이어야 하고, 단계마다 신호 둘(크기+굵기, 크기+서체, 크기+색)을 바꾼다(R1).
7. **반복**: 같은 역할은 영상 내내 같은 모양이다(챕터 카드, 이름표, 출처 자리). 모양이 바뀌면 R15 다.
8. **정렬**: 모든 요소는 다른 요소와 보이는 선으로 이어진다. 정렬선은 2개 이하, 가운데 정렬 블록은 1개 이하다.
   초보는 편해서 가운데로 맞추는데, 그러면 가장자리가 물러진다(R5).
9. **근접**: 관련된 것은 붙이고 묶음 사이는 2em 이상 띄운다. 간격이 모두 같으면 묶음이 사라진다. 라벨은 대상 바로 옆에 둔다.
10. **공통 영역**(NN/g): 상자와 배경은 묶음을 가장 세게 만든다. 그래서 남발하면 어수선하다. 여백으로 될 일은 여백으로 한다.
11. **크기와 색**(NN/g): 크기 단계는 3개 이하이고, 가장 중요한 것이 가장 크다. 강조색은 한 곳에만 온전한 채도로 쓴다.
    두 곳에 쓰면 둘 다 신호를 잃는다(R2: 2곳 이하, 면적 6% 이하).
12. **균형**: 비대칭이 기본이다. 한 구역이 나머지를 지울 만큼 무겁지 않아야 하고, 여백은 한쪽에 모여 있어야 한다.
13. **깊이**: 뒤로 물러난 층은 대비를 30~40% 낮춘다(dim). 앞뒤가 구분되지 않으면 초점이 흩어진다(R2).
14. **공동 운명**(게슈탈트): 같이 움직이는 것은 한 묶음으로 읽힌다. 서로 다른 묶음이 같은 타이밍과 방향으로 움직이면 잘못 묶여 보인다(R16).

## 3. 읽힘 — 폰, 대비, 안전 영역, 시간

15. **폰**: 1920 프레임을 폭 480 으로 줄이면 0.25배다. 헤드라인 56px 는 14px(읽힘), 본문 34px 는 8.5px(겨우), 라벨 28px 는 7px 가 된다.
    그래서 하한은 헤드라인 옆 메모 56 · 전면 72, 본문 34, 라벨 28 이다.
    legibility.info 는 폰 전체 화면 본문으로 40~60px 를 권한다. 본문이 두 줄을 넘으면 40px 이상을 요구한다(R3).
16. **대비**(WCAG 1.4.3): 본문 4.5:1, 큰 글자 3:1 이다(우리는 40px 이상을 큰 글자로 본다). 4.49 는 반올림해서 통과시키지 않는다.
    하우스 색 실측값은 다음과 같다.
    - 잉크 #26211E / 크림: 13:1 — 어디든 된다.
    - 강조 #2B8A64 / 크림: 3.5:1 — 40px 이상만. 작은 글자에 쓰였으면 R4 high.
    - 짙은 초록 #1E6B4F / 크림: 5.3:1 — 본문도 된다.
    - 민트 #86D9B5 위 잉크: 9.6:1. 민트 위 짙은 초록: 3.9:1 — 40px 이상만.
    - 강조색 면 위 크림 글자: 3.8:1 — 40px 이상만.
    사진과 영상 위 글자는 글자 뒤에서 가장 밝은 부분을 기준으로 잰다.
17. **안전 영역**: EBU R95 그래픽 안전 영역 5% 는 좌우 96px · 위 54px 다. 아래 170~180px 는 자막 자리다. 글자나 출처가 밖에 있으면 R6 이다.
18. **읽는 시간**: 정착한 뒤 `max(1.2초, 글자 수 ÷ 7)` 만큼 멈춰야 한다.
    넷플릭스 한국어 자막 상한(초당 12자)에 '두 번 읽을 만큼'(SSW 규칙)을 적용한 값이다. 30자 메모면 4.3초다. 모자라면 `shorten_text` 를 낸다.
19. **밀도**: 한 화면에 글자 60자(옆 메모 30자), 글 묶음 3개, 요소 7개 이하다. legibility.info 도 동시에 3줄 이하를 권한다(R7).

## 4. 첫 프레임과 움직임의 가독성

20. +0.5초 칸이 안착 칸의 35% 이상 차 있어야 한다(R8). 빈 판에 제목만 있으면 "나중 요소를 `ghost` 로 0초에 세운다"고 고친다.
21. 한 번에 초점 움직임은 하나다(Disney 의 무대 연출 원칙: 중요한 것만 움직여 강조한다). 15%·40% 칸에서 크게 움직이는 것이 둘 이상이거나, 같은 0.1초에 셋 이상이 시작하면 R16 이다.
22. 먼저 온 것이 위계를 가진다. 작은 부품이 히어로보다 먼저 오면 위계가 뒤집힌다(R1·R16).
23. 안착 칸의 글자는 완전히 선명해야 한다. 블러가 남았거나, 읽히는 중인 글자가 밀리거나 확대되면 R16 이다.
24. 퇴장 직전 칸에서는 두 가지를 본다. 문장이 끝나는 자리인지, 퇴장이 진입보다 짧은지다. 핵심어를 말하는 도중에 사라지면 R16 이다.
25. 바운스·팝·흔들림의 반복, 글자 블러, 말과 상관없이 돌거나 떠다니는 장식은 R16 이고 `revise_scene`·`revise_card` 대상이다.
26. 데이터 장면에서는 다음을 본다(R17).
    - 축과 값이 한 칸에서 같이 바뀌는가. Heer & Robertson 의 실험에서는 나눈 쪽이 더 정확했다.
    - 막대 기준선이 0 인가.
    - 범례 대신 직접 라벨인가.
    - 제목이 결론 문장인가.

## 5. 아마추어 티와 고치는 법 — `direction` 에 그대로 쓴다

27. 모든 요소가 같은 fade-up 으로, 같은 순간에 온다 → "히어로 at 0.2 mask, 부품은 +2f·+3f·+4f 로 겹쳐 정착, 목록은 말하는 순간에".
28. 위치를 linear 로 옮기거나 진입이 30f 를 넘는다 → "큰 면 enterLarge 22f, 작은 요소 enter 12f, 퇴장은 진입의 0.75배"(NN/g: 퇴장이 등장보다 짧다).
29. 팝·바운스로 크게 튀어나온다 → "settle(+1.2%)·settlePaper(+4%)로 바꾼다. pop 은 펀치 구간에만".
30. 가운데 정렬 3단 스택(킥커 · 큰 글자 · 작은 글자) → "왼쪽 정렬, 히어로를 3분할 교점에, 여백은 오른쪽에 40%".
31. 크기 단계가 비슷하다(44/38px = 1.16) → "제목 size 7 → 11(77px), 본문 34px 유지 → 2.3배".
32. 서체가 넷 이상이거나, 송명에 가짜 굵게를 줬거나, 고딕 굵기만으로 위계를 만들었다 → "제목 고운바탕 700, 숫자 Playfair italic, 본문 Pretendard". 서체가 셋을 넘으면 콘셉트가 흐려진다(Love of Graphics).
33. 강조색이 세 곳 이상이다 → "강조색은 핵심어 하나에만, 나머지는 ink·dim".
34. 그림자가 검거나, 방향이 제각각이거나, 블러가 과하다 → "웜 잉크, dx:dy 2:3, 높이 1~3 값으로".
35. 큰 판에 작은 도식이 있다(채움 45% 미만) → "요소 외접 상자를 45% 이상으로 키우거나 side 구성으로 내린다".
36. 아이콘이나 빈 네모가 실물을 대신한다 → "자료 E3 프린트로 바꾸고 mark circle 로 볼 곳을 가리킨다"(R14).
37. 말한 문장을 그대로 띄웠다 → "주장 12자로 줄인다: '질문이 먼저다'". 화면 글자가 내레이션을 되풀이하면 이해가 떨어진다(Mayer 의 중복 원칙, R11).
38. 줄 끝에 조사만 남거나 숫자와 단위가 갈라졌다 → "`\n` 을 어절 앞으로 옮긴다"(R9).
39. 템플릿 이름, 검색어, 연출 메모, 발화 번호가 화면에 보인다 → R13 high. 그 글자를 지운다.
40. 글로우, 렌즈 플레어, 그라디언트 오브, 유리 블러, 컬러 클립아트 → R12. 종이·잉크·강조색 한 곳으로 되돌린다.
41. 직전 그래픽과 구도·진입이 둘 다 같다 → R15. "구도는 desk → sheet, 진입은 place → unfold" 처럼 하나를 바꾼다.
42. 장면마다 진입·이동 속도가 들쭉날쭉하다 → 같은 역할에는 같은 곡선과 길이를 쓰게 한다. 기본 이징만 쓰거나 이징을 빼는 것도 흔한 실수다(Hanson).
42-1. **사진·스톡·그림 부품이 🌍 이 영상의 세계 밖이다**(나이·장소·시대·직업 도구 — 미대 산업디자인과 이야기에 아이 공책·색연필, 제품
    렌더링 자리에 거실 인테리어, 폼 목업 자리에 해변) → R19 high. "그림 부품 `pixabay:photo:foam mockup` → `pixabay:photo:foam model
    sanding`"처럼 이 세계의 손·도구·과정으로 바꾸는 검색어를 `direction` 에 쓴다. 보안 확인·오류·로그인 화면 캡처는 R13 high — 뺀다.
42-2. 같은 영상 안에서 사진의 결(색온도·빛·처리)이 둘로 갈린다 → "색온도와 빛을 맞추고, 과하게 보정된 광고풍 컷을 뺀다"
    (PremiumBeat: 빛·시간대·날씨를 맞추고 모든 샷에 공통 요소를 둔다).

## 6. 판정과 기록

43. issue 하나에는 원인 하나만 적는다. `measured` 는 숫자(px, 비, %, 초)로 쓰고, 같은 원인을 여러 issue 로 쪼개지 않는다.
44. `direction` 에는 바꿀 요소, 값, 시각을 적는다. 예: "제목 size 7 → 10, 점 r 1.6 → 4, mark circle 을 3.2초에".
45. 그래픽으로 풀 수 없는 문제(중복 테이크, 영상 가운데의 인사, 25초 넘게 얼굴만, 방·색 변화)는 `escalate_edit` 로 올린다.
46. high 는 시청자가 놓치거나 잘못 알아들을 때만 준다(읽히지 않음, 틀린 사실, 얼굴 가림, 내부 이름 노출). 없는 문제는 만들지 않는다.

## 체크리스트

- [ ] 480px 시트에서 초점이 한 곳이고, 헤드라인이 읽힌다(R2·R3).
- [ ] 크기 비 ≥ 1.6, 단계 3 이하, 단계마다 신호 둘(R1). 정렬선 2개 이하, 가운데 스택 없음(R5).
- [ ] 대비: 본문 4.5:1, 40px 이상 3:1. 크림 위 #2B8A64 작은 글자가 없다(R4).
- [ ] 글자와 출처가 좌우 96 · 위 54 안에 있고, 아래 자막 자리가 비어 있다(R6).
- [ ] 채움 45% 이상, 글자 60자 · 묶음 3 · 요소 7 이하(R7). +0.5초 칸이 35% 이상(R8).
- [ ] 크게 움직이는 것 하나, 안착 칸이 선명함, `max(1.2초, 글자 ÷ 7)` 정지, 퇴장은 문장 끝(R16).
- [ ] 얼굴과 겹치지 않고(R10), 한 재질·한 광원이며(R12), 내부 이름이 없다(R13).
- [ ] 모든 issue 에 항목 번호, 잰 값, 숫자로 된 `direction` 이 있다.
