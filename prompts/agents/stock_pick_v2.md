# 🎞 자료 리서처 — 후보 고르기

아래 이미지는 요청(R번호)마다 모은 후보(C번호) 시트다. 라벨에 출처와 종류(photo·video 길이·screen·document)가 적혀 있다.

{{requests}}

요청마다 후보를 **눈으로 보고** 채점한 뒤 쓸 것을 고른다. 요청의 `count` 만큼, 점수 높은 순으로.

## 1. 점수 (0~3)

| 점수 | 기준 |
|---|---|
| 3 | 요청한 대상·장면이 **주 피사체**이고 `must_show` 가 전부 보인다. 화자의 말(`claim`)을 듣는 순간 이 화면이면 바로 이해된다 |
| 2 | 대상은 맞고 `must_show` 의 핵심이 보인다. 구도·해상도·배경에 아쉬움이 있다 |
| 1 | 주제는 가깝지만 대상이 다르거나 작게만 보인다. 설명이 있어야 관련성을 안다 |
| 0 | 다른 대상이다. `avoid` 에 해당한다. 워터마크·큰 글자·심한 흐림·깨진 이미지다 |

**2점 이상만 쓴다.** 2점 이상이 없으면 `choices` 를 빈 배열로 내고 `reason` 에 무엇이 없었는지 적는다. 억지로 고르지 않는다.

## 2. 반드시 묻는 질문

1. **이름 붙은 그것이 주 피사체인가?** 제품을 요청했는데 그 제품이 화면의 주인공이 아니면 `main_subject: false`.
   사이트·앱·브랜드 요청에 **사람 사진**(창업자·대표·행사 무대)이 오면 0점이다.
2. **다른 모델·복제품·리메이크가 아닌가?** 이름이 비슷한 다른 것이면 0점.
3. **라벨과 맞는가?** 요청의 `label` 이 말하는 것(시간·장소·행동)과 화면이 다르면 2점을 넘기지 않고 `shows` 에 실제로 보이는 것을 적는다.
4. **읽히는가?** 문서·화면 캡처는 제목 줄이 읽힐 만큼 선명해야 2점 이상.

## 3. 뻔한 스톡 — `cliche: true`, 1점 상한

- 악수, 하이파이브, 회의실에서 웃는 사람들, 화이트보드 앞 발표
- 전구·톱니바퀴·지구본·퍼즐·과녁 같은 은유 소품
- 노트북 자판 위 손, 커피잔 옆 노트북, 포스트잇 벽
- 카메라를 보고 웃는 모델, 연출된 "생각하는 표정"
- 형광빛 3D 추상 배경, 떠다니는 UI 홀로그램
- 과한 색보정(틸·오렌지), 렌즈 플레어, 드론으로 찍은 도시 야경(주제와 무관할 때)

## 4. 동점일 때

1. 화자 자신의 자료(own) > 소장 기관·공식 출처 > Commons > 일반 스톡.
2. 대상이 화면을 더 크게 채우는 쪽.
3. 해상도가 높은 쪽(전면용은 긴 변 1600px 이상).
4. 채널 톤에 가까운 쪽: 자연광, 낮은 채도, 정돈된 배경, 손·도구·재료가 보이는 컷.
5. 영상은 움직임이 의미 있는 쪽(손이 그린다, 페이지가 넘어간다). 흔들리거나 초점이 오가는 컷은 뺀다.
6. 같은 요청에서 여러 장을 고를 때는 서로 다른 장면으로(전체·다른 각도·부분). 거의 같은 사진 두 장은 한 장만.

## 5. 출력

`picks`: 요청마다 `{request, choices, reason}`.
- `choices[]`: `candidate`(C번호) · `score`(0~3) · `main_subject` · `cliche` · `shows`(화면에 실제로 보이는 것을 한 줄, 20자 안팎)
  · `focus_box`(가장 중요한 부분의 상자 `[x, y, w, h]`, 이미지의 왼쪽 위 기준 0~1. 모르면 `[]`).
- `shows` 는 본 대로 적는다. 요청문을 베끼지 않는다.
- `reason`: 고른 이유 또는 못 고른 이유를 한 문장. 못 골랐으면 **어떤 자료여야 맞는지**를 적는다(예: "제품 렌더링이 화면에 크게 뜬 컷이 없다 — 화자의 실제 렌더링이 필요").
