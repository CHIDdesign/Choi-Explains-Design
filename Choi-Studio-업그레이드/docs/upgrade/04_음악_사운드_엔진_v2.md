## 2. 원칙

1. **한 영상 = 한 스코어.** 주제(theme) 하나와 그 변주(bed·air)·종지(tag)만 쓴다. 챕터가 바뀌어도 곡은 바뀌지 않는다. 바뀌는 것은 편성과 크기다.
2. **음악은 논증의 구조를 따른다.** 음악이 들어오고 나가는 자리는 훅·챕터 전환·사례·결론 같은 구조의 표지다. 이유를 적을 수 없는 큐는 넣지 않는다.
3. **침묵도 큐다.** 정의·실험 설명·고백·결론 문장은 음악 없이 간다. 목표 점유율은 롱폼 40~60%(이번 실행 100%).
4. **끝점부터 정한다.** 모든 큐는 시작·끝·끝내는 방법을 가진다. 끝은 마디 끝이나 종지다.
5. **목소리가 기준이다.** 음악·효과음 레벨은 목소리 스템의 실측 라우드니스에 상대값으로 건다.
6. **숏폼은 롱폼의 스코어를 물려받는다.** 같은 키트의 bed 나 air 를 쓴다. `upbeat`·`corporate` 로 떨어지는 기본값은 없다.
7. **맞는 곡이 없으면 음악 없이 간다.** 아무 곡이나 고르는 폴백(`library.py:215`)을 없앤다.
8. **젠틀하게.** 박 맞춤은 음악의 위상을 옮기는 데 그친다. 컷과 말에 묶인 그래픽은 움직이지 않는다.

## 3. 큐 시트 모델

### 3.1 스키마(`studio/agents/schemas.py` 에 추가)

```python
SUITES = ["felt", "analog", "brush", "air"]
CUE_ROLES = ["theme", "bed", "air", "reprise"]
CUE_ENTRIES = ["downbeat", "fade_in"]
CUE_EXITS = ["ending", "fade_bar", "into_next"]

# 🎼 음악 감독 — 큐 시트(어디서 들어오고 나가는지, 어디가 침묵인지)
MUSIC = _obj({
    "suite": {"type": "string", "enum": SUITES},
    "suite_reason": STR,        # 이 영상의 말투·논지와 왜 맞는지 한 줄
    "fit_score": INT,           # 0~10. 7 미만이면 air 만 쓰거나 음악 없이 간다(게이트 D6)
    "describe": STR,            # 주제곡을 묘사하는 영어 한 줄(키트 매칭·생성 프롬프트)
    "tempo_bpm": INT,           # 원하는 템포. 0 = 박 없음
    "cues": {"type": "array", "items": _obj({
        "id": STR,              # "m1", "m2" …
        "start_seg": INT,       # -1 = 영상 맨 앞(오프닝 하이라이트 포함)
        "end_seg": INT,         # -1 = 영상 끝(엔드카드 포함)
        "role": {"type": "string", "enum": CUE_ROLES},
        "energy": INT,          # 0~5
        "entry": {"type": "string", "enum": CUE_ENTRIES},
        "exit": {"type": "string", "enum": CUE_EXITS},
        "why_in": STR,
        "why_out": STR,
    })},
    "silences": {"type": "array", "items": _obj({"start_seg": INT, "end_seg": INT, "why": STR})},
    "hero": {"type": "array", "items": _obj({
        "seg": INT, "kind": {"type": "string", "enum": ["ident", "tonal"]}, "why": STR})},
    "shorts": _obj({"role": {"type": "string", "enum": ["bed", "air", "none"]}, "energy": INT, "note": STR}),
    "notes": STR,
})
```

- `_obj` 가 `additionalProperties=false` 와 전체 `required` 를 붙인다. 빈 값은 빈 배열·빈 문자열·0 으로 낸다.
- 역할의 뜻: `theme` 주제를 온전한 편성으로 · `bed` 같은 곡의 성긴 변주(리드·드럼 없음) · `air` 같은 조성의 거의 안 들리는 바닥 · `reprise` 엔딩에서 주제 재현.
- 레벨은 역할이 아니라 **말의 유무**가 정한다. `theme`·`reprise` 는 말이 없을 때만 또렷해진다(§6.3).

## 4. 선택 — 키트 하나를 고른다

라이브러리의 단위는 곡이 아니라 **키트**다. 키트 = 같은 곡의 `theme`·`bed`·`air`·`tag` 네 판(박 격자 공유). 스위트(felt·analog·brush·air)마다 키트 2~3개를 둔다([04b](04b_사운드_라이브러리_v2.md)).

```
후보 = 음악 감독이 고른 suite 의 키트 중 license.class ∈ {A, B, C} 이고 approved 인 것
score = 0.35 * match(describe, kit)        # P1: describe 낱말과 kit.tags 의 겹침(자카드). P2: CLAP 코사인
      + 0.25 * tempo_fit                    # exp(-(log2(kit.bpm / tempo_bpm) / 0.15)^2). tempo_bpm=0 이면 pulse=="none" 1.0, 아니면 0.5
      + 0.15 * (1 - |energy_mean - kit.energy| / 5)
      + 0.25 * (1 - 최근 5편 중 이 키트를 쓴 횟수 / 5)
tie-break: random.Random(sha1(job_id))
```

- `score < 0.6` 이거나 `fit_score < 7` 이면 그 스위트의 `air` 판만 쓴다. 그것도 없으면 음악 없이 간다(게이트 D6).
- 숏폼은 롱폼이 고른 키트를 그대로 쓴다. 롱폼을 만들지 않는 작업이면 같은 점수로 고른다.
- 사용 이력은 `user/music_history.json` 에 남긴다.
- 후보가 스위트당 2~3개라 점수는 순서만 정한다. 취향 판단은 입고 때 운영자 승인이 맡는다.

## 5. 길이 맞추기 — 마디 경계 리타깃

키트의 분석 사이드카가 `downbeats[]`, `loop{in,out}`, `ending{start}` 를 준다. 큐마다 "한 번의 연주"를 만든다.

```
입력: 큐 길이 T, 구간 intro=[0, loop.in) · body=[loop.in, loop.out) · ending=[ending.start, 끝)
1. 시작: role 이 theme/reprise 이고 entry=downbeat 이면 intro 부터. 그 밖은 loop.in 부터.
2. 끝: exit=ending 이면 ending 구간을 붙인다. fade_bar·into_next 는 붙이지 않는다.
3. 남은 길이 need = T − (쓴 intro) − (쓴 ending).
4. body 를 need 를 넘지 않는 가장 긴 마디 수만큼 채운다. 한 바퀴보다 길면 loop.out → loop.in 으로 돈다.
5. 모자란 길이(1마디 미만)는 시작을 그만큼 늦춘다. 박 앵커가 켜져 있으면 ±2% atempo 로 먼저 맞춘다(§7).
6. 이음매: 다운비트 위 80 ms 등전력 크로스페이드. 곡의 끝과 처음을 직접 잇지 않는다.
7. 같은 영상에서 두 번째로 나오는 큐는 body 의 다른 마디에서 시작한다(같은 도입이 반복되지 않게).
```

- 판 바꾸기(`into_next`, theme↔bed↔air): 네 판이 같은 박 격자를 쓰므로 **재생 위치를 유지한 채** 한 마디 동안 선형 크로스페이드한다. 같은 소재라 가운데가 −6 dB 인 선형이 맞다.
- 분석이 없는 곡(박 신뢰도 낮음, 루바토)은 루프하지 않는다. 곡 길이 안에서만 쓰고 넘치면 `fade_bar` 로 끝낸 뒤 침묵한다.
- 구현: `studio/sound/retarget.py`(신규, numpy). 루프 점 탐색은 입고 때 한 번 한다(자체 구현 또는 PyMusicLooper, MIT).

## 6. 믹스 체인

지금의 구조(numpy 에서 10 ms 게인 곡선을 곱하고 60초 조각으로 합산, 최종은 선형 게인 + 리미터)는 유지한다. 바꾸는 것은 기준·곡선·전처리·산출물이다.

### 6.1 버스

```
voice.wav (기존 레시피) ──────────────────────────────────────────┐
room tone (원본의 가장 조용한 2~4초를 루프, 목소리 − 34 LU) ──────┤
music: 키트 판 → 전처리(full / carved) → 리타깃 → 큐·레벨 곡선 ───┼→ 합(float32) → 24bit WAV → 마스터
sfx: 전처리 → 단기 라우드니스 정규화 → 꼬리 제한 → 배치 ──────────┘
```

- 스템을 따로 쓴다: `work/stem_music_k.wav`, `work/stem_sfx_k.wav`. 게이트 D 가 잔차 계산 없이 바로 잰다.
- 중간 파일은 16bit 에서 24bit 로 바꾼다(낮은 레벨의 베드와 페이드 꼬리).

### 6.2 기준: 목소리 실측 라우드니스

```
V = ebur128(voice_wav).I          # 이번 실행: −21.8 (롱) / −20.8 (숏)
music_gain_dB(t) = (V + rel(t)) − lufs_bed(판)
```

- `lufs_bed` 는 루프 구간 단기 라우드니스의 중앙값이다(인트로가 조용한 곡의 편차 제거). 지금의 통합값 정규화(`mix.py:202`)를 바꾼다.
- 목소리 스템이 −16 ±1 LUFS 에 못 미치면 경고를 남긴다. 이번처럼 −21.8 이면 마스터 리미터가 피크를 약 7 dB 누른다. 목소리 쪽 대책(피크가 높을 때의 처리)은 목소리 체인의 일이다.

### 6.3 상태별 상대 레벨 `rel`(LU, 목소리 기준)

| 상태 | 롱폼 | 숏폼 | 조건 |
|---|---|---|---|
| bed(말 아래) | −20 | −18 | 큐 안, 말 있음 |
| 쉼 | −17 | −16 | 1.2초 넘는 쉼 |
| feature | −8 | −8 | `theme`·`reprise` 큐에서 말이 1.5초 넘게 없는 곳(타이틀·카드·엔드카드) |
| air | −28 | −26 | `air` 큐 |
| 큐 밖·침묵 | 무음 | 무음 | |

근거: 공개 가이드의 말 아래 −18~−25 dB, 덕 깊이 6~12 dB, 줄마다 15~20 dB 떨어지면 자동화가 들린다는 경고(리서치 §B.2.1). 이번 실행의 13.4 / 15.5 LU 는 이 범위 밖이다.

### 6.4 곡선(numpy, 10 ms 해상도)

```python
act = speech_mask(voice_wav, min_gap=1.2)            # 10 ms RMS > −42 dBFS, 1.2초 미만 쉼만 메운다(지금의 ±0.5초 팽창 대신)
rel = np.where(act > 0.5, BED, GAP)                   # 큐 안에서만
rel[feature_mask] = FEATURE                           # theme/reprise 큐의 말 없는 1.5초 이상 구간
fast = smooth(shift(rel, -0.275), hann(0.35))         # 내려갈 때: 0.35초 코사인, 말 시작 0.1초 전에 도착
slow = smooth(shift(rel, +1.55), hann(1.5))           # 올라올 때: 말 끝 0.8초 뒤부터 1.5초 코사인
env_db = np.minimum(fast, slow)
amp = cue_window(cues)                                # 큐 시작·끝의 진폭 램프(0~1)
w_carve = smooth(act, hann(0.35))                     # 말이 있을 때만 carved 판을 섞는다
music = (carved * w_carve + full * (1 - w_carve)) * 10 ** ((V + env_db - lufs_bed) / 20) * amp
```

- `smooth` 는 정규화한 Hann 창과의 합성곱이다. 1차 필터(`mix.py:146-150`)를 대체한다.
- 큐 시작: `downbeat` 는 다운비트에서 바로(15 ms 페이드), `fade_in` 은 한 마디 코사인.
- 큐 끝: `fade_bar` 는 마지막 한 마디 코사인, `ending` 은 종지 구간 그대로.
- 지금의 `swells`·`dips`·`switch_at` 은 없어진다. 스웰은 feature 상태가, 딥은 침묵이, 교체는 판 바꾸기가 대신한다.

### 6.5 음악 전처리(FFmpeg, 큐가 쓰는 판마다 두 벌)

```bash
# full — carved 와 지연을 맞추려고 평탄한 FIR 을 통과시킨다
ffmpeg -i cue.wav -af "aresample=48000,highpass=f=60:p=2,firequalizer=gain_entry='entry(0,0);entry(24000,0)':delay=0.02" -c:a pcm_s24le cue_full.wav

# carved — 말 대역을 덜어낸 판
ffmpeg -i cue.wav -af "aresample=48000,highpass=f=60:p=2,firequalizer=gain_entry='entry(0,0);entry(500,0);entry(1000,-2.5);entry(2500,-5);entry(4000,-3);entry(6000,0);entry(24000,0)':delay=0.02,stereotools=mlev=0.84" -c:a pcm_s24le cue_carved.wav
```

실행해서 확인한 것(FFmpeg n9.0.2):
- 두 출력은 서로 샘플 단위로 정렬된다(교차상관 지연 0). 원본 대비 둘 다 960샘플(20 ms) 늦다. numpy 에서 앞 960샘플을 버린다.
- carved − full 의 대역 차(가운데 정위 성분 기준): 1 kHz −4.0 dB, 2.5 kHz −6.3 dB, 4 kHz −4.5 dB, 그 밖 −1.5 dB(`mlev=0.84`).
- **필요할 때만 켠다.** 이번 롱폼의 피아노 곡들은 1~4 kHz 여유가 24~28 dB 였다. 첫 믹스에서 그 값이 22 dB 미만일 때만 carved 를 섞고(D1b), 그래도 모자라면 bed 를 2 dB 내린다. 목소리 보정과 같은 "재고 나서 필요한 만큼만" 원칙이다.

### 6.6 마스터

```bash
# 1) 측정
ffmpeg -hide_banner -nostdin -i mix.wav -af "loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json" -f null -
# 2a) 선형으로 갈 수 있을 때
-af "loudnorm=I=-14:TP=-1.5:LRA=<측정 LRA+1>:measured_I=<..>:measured_TP=<..>:measured_LRA=<..>:measured_thresh=<..>:offset=<..>:linear=true,aresample=48000"
# 2b) 피크가 넘칠 때 — 선형 게인 + 4배 업샘플 리미터
-af "volume=<gain>dB,aresample=192000,alimiter=limit=0.841:attack=5:release=80:level=false,aresample=48000"
```

- `mix.loudness_args`(`mix.py:323-350`)의 구조 그대로다. 바꾸는 것은 목표 피크 −1.0 → −1.5 dBTP(AAC 인코딩 여유)와 리미터 앞 업샘플(필터 문서의 권고)이다.
- `dynaudnorm` 과 `loudnorm` 동적 모드는 쓰지 않는다. 조용한 구간을 끌어올려 말과 음악의 비를 되돌린다.
- 이번 믹스에 2b 를 그대로 돌리면 −14.3 / −14.2 LUFS 가 나온다(D7 통과).

참고 — numpy 를 고치기 전에 귀로 방향을 확인하는 FFmpeg 단독 체인(실행 확인, 청취 검증 안 함):

```bash
ffmpeg -i voice.wav -i music.wav -filter_complex "
[1:a]aresample=48000,highpass=f=60:p=2,volume=-18dB,acrossover=split=800 4500:order=4th[lo][mid][hi];
[0:a]asplit=3[v][sc1][sc2];
[mid][sc1]sidechaincompress=threshold=0.02:ratio=3:attack=30:release=500:knee=6:detection=rms[midd];
[lo][midd][hi]amix=inputs=3:normalize=0[mb];
[mb][sc2]sidechaincompress=threshold=0.02:ratio=1.5:attack=60:release=900:knee=6[md];
[v][md]amix=inputs=2:normalize=0:duration=first[out]" -map "[out]" -c:a pcm_s24le proto.wav
```

### 6.7 룸톤

- 원본 목소리에서 말이 없는 구간 중 가장 조용한 2~4초를 뽑아 등전력 크로스페이드로 루프를 만든다.
- 영상 전체에 목소리 − 34 LU 안팎으로 깐다. 음악이 없는 구간이 늘어나므로 컷 이음새의 끊김을 이것이 메운다.

## 7. 박 앵커 — 젠틀하게

옮기는 것은 음악의 위상뿐이다. 화면은 말에 묶이지 않은 사건만 최대 2프레임 움직인다.

```
앵커(가중치): 타이틀·챕터 카드·엔드카드 등장 3 · 하이라이트 조각 경계와 정리 보드 2 · 말이 쉬는 동안의 전면 그래픽 1
큐마다: 첫 가중치 3 앵커에 곡의 다운비트를 맞춘다(offset = 앵커 − 다운비트).
        다운비트 후보 = intro 시작, loop.in, 구간 경계. stretch 후보 = 0.98~1.02.
        score = Σ w·exp(−(거리/0.05)²) − 0.5·|stretch−1|·100
화면 쪽: 가중치 2 이상이고 말에 묶이지 않은 사건만 가까운 박으로 ±2프레임. 2마디에 하나까지.
```

- 말에 맞춘 그래픽·자막·콜아웃·컷은 건드리지 않는다. 효과음은 박이 아니라 화면 사건에 붙는다.
- 침묵의 끝과 복귀는 마디 단위로 양자화한다.
- 박·다운비트는 입고 때 한 번 계산한다(Beat This!, 코드·가중치 MIT). `bpm_conf` 가 낮은 곡은 이 단계를 건너뛴다.
- 템포 조정은 FFmpeg `atempo`(0.5~100)로 ±2% 안에서만 한다. `rubberband` 필터는 앱 번들에 들어 있지만 라이브러리가 GPL 이다.

| 5 | (선택) 로컬 생성 모델이 설치됨 | `air` 판 하나만 생성해 게이트를 통과하면 쓴다([04b](04b_사운드_라이브러리_v2.md) 6절) |

- 작업 중에는 내려받지 않는다. 라이브러리 준비는 설치 단계와 운영자 큐레이션에서 한다.
- `synth.py` 는 음악을 만들지 않는다. 지금처럼 효과음만 맡고, 그 소리도 새 팔레트로 바꾼다([04c](04c_효과음_팔레트_v2.md) 7절).

## 12. 확인하지 못한 것

- 곡이 어떻게 들리는지는 재지 못한다. 모든 판정은 수치와 Gemini 의 숏폼 청취에 기댄다. 롱폼 청취 결과가 오면 1절을 갱신한다.
- §6.3 의 상대 레벨, §4 의 가중치, D1b·D8 의 임계값은 출발값이다. 운영자가 승인한 영상 3편의 실측으로 다시 잡는다.
- FFmpeg 체인은 n9.0.2 에서만 돌려 봤다. FFmpeg 7 에서는 실행 검증 안 함.
- 템포·온셋 수는 자체 검출기 기준이다. `analyze.py` 를 Beat This!·librosa 로 바꾸면 절대값이 달라지므로 게이트 임계값을 같이 다시 잰다.
- 목소리가 −16 LUFS 에 못 미치는 문제(피크 높은 원본)는 이 문서의 범위 밖이다. 음악 쪽은 기준을 실측에 묶어 영향을 없앤다.
