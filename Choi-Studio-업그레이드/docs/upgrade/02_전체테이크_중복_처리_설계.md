# 02. 전체 테이크 중복 처리 — "같은 대본을 두 번 찍은 원본"을 버그가 아니라 자산으로

> 진단: [`00_테스트영상_진단.md`](00_테스트영상_진단.md) 1절. 이 문서는 그 P0 버그의 수정 설계다.
> 다른 모든 개선(이미지·음악·모션)보다 먼저 고쳐야 한다 — 이게 남아 있으면 무엇을 얹어도 영상의 절반이 맨얼굴이다.

## 1. 지금 벌어지는 일

원본을 여러 개 넣으면 `studio/media/sources.py group_sources`가 둘 중 하나로 가린다.

| 판정 | 조건 | 처리 |
|---|---|---|
| 동시 촬영(다시점) | 소리 상관·창별 일치 | 한 묶음, 앵글 교차 |
| 따로 찍음 | 그 밖 전부 | **넣은 순서대로 이어 붙임** |

"따로 찍음"에는 사실 성격이 전혀 다른 세 경우가 섞여 있다.

| | 내용 | 올바른 처리 |
|---|---|---|
| A. 이어 찍기 | 파일 1 = 대본 앞부분, 파일 2 = 뒷부분 | 이어 붙임(지금 동작) |
| B. 부분 다시 찍기 | 파일 2에 앞 파일의 몇 문장을 다시 말함 | 문장별로 더 좋은 쪽(지금은 120초 창 때문에 놓침) |
| **C. 전체 다시 찍기** | **파일 1 = 대본 전체, 파일 2 = 대본 전체(다른 구도·다른 날)** | **한 번만 나와야 한다.** 다른 쪽은 대체 테이크·다른 앵글 |

이번 테스트가 C였다. 그런데 다음 세 군데가 C를 모른다.

1. `align.py _mark_retakes_by_script` — 후보 창이 "앞 10개 발화 · 120초". 주석: `# 2분 이상 떨어진 반복은 의도적 반복으로 본다`.
2. `align.py _match_all` — 대본 커서가 끝까지 간 뒤 2차 테이크의 첫 문장을 만나면 `self._align(un, 0, n)`(대본 전체)로 맞추긴 하지만,
   `cursor = max(cursor, b)`라 커서가 뒤로 돌아가지 않는다. "대본을 처음부터 다시 읽기 시작했다"는 사건이 기록되지 않는다.
3. `pipeline.py:884-897` — 감독의 `drop` 중 `u.script_span and u.score >= 80`이면 무조건 거절. **같은 대본 구간을 덮는 다른 발화가 남아 있는지 보지 않는다.**

## 2. 설계 원칙

1. **대본 충실의 정의를 바로잡는다.** "대본의 각 문장이 최종본에 **정확히 한 번** 나온다." 0번도 안 되고 2번도 안 된다.
   (화자가 대본에 같은 문장을 일부러 두 번 써 둔 경우만 예외 — 그건 대본에 두 번 있으므로 대본 구간이 다르다.)
2. **'읽기 회차(pass)'를 1급 개념으로 만든다.** 전사본을 대본 위치로 그렸을 때 톱니 모양이 생기면(끝까지 갔다가 처음으로 돌아감) 회차가 바뀐 것이다.
3. **버리지 않고 쓴다.** 전체를 두 번 찍었다면 그건 NG가 아니라 **B캠**이다. 문장별로 더 좋은 쪽을 고르면 자연스럽게 앵글이 바뀌고, 지는 쪽도 인서트로 쓸 수 있다.
4. **조용히 넘어가지 않는다.** 회차를 감지했으면 로그·리포트·GUI에 "대본 전체를 2번 읽은 것으로 보고 한 편으로 합쳤습니다"라고 적는다.

## 3. 알고리즘

### 3-1. 회차 감지 — `studio/text/passes.py`(신규)

입력: `_match_all`이 끝난 발화 목록(`script_span`, `score`), 대본 길이 `N`(정규화 글자 수).

```python
@dataclass
class ReadPass:
    idx: int
    utts: list[int]          # 발화 id(시간순)
    lo: int; hi: int         # 덮은 대본 구간(정규화 인덱스)
    coverage: float          # (덮은 글자 수) / N
    source: int              # 묶음(파일) 번호 — 한 회차가 한 파일이면 그 번호, 섞였으면 -1

def detect_passes(utts, N, *, back_jump=0.35, min_cov=0.25) -> list[ReadPass]:
    """대본 위치가 크게 뒤로 돌아가는 지점에서 회차를 끊는다.
    back_jump: 지금까지의 최대 위치에서 대본 길이의 35% 이상 뒤로 가면 '다시 읽기 시작'.
    단, 뒤로 간 뒤 3개 이상 발화가 그 근처에서 이어 전진해야 한다(한 문장만 다시 말한 건 리테이크).
    min_cov: 대본의 25% 미만만 덮는 조각은 회차가 아니라 부분 다시 찍기 — 앞 회차에 붙인다."""
```

- 묶음(파일) 경계는 강한 힌트다: 파일이 바뀌는 지점 ±1 발화에서 뒤로 점프가 있으면 `back_jump`를 0.2로 낮춘다.
- 회차가 1개면 지금과 똑같이 동작한다(회귀 없음).

### 3-2. 회차가 2개 이상일 때 — 두 가지 모드

| 모드 | 조건 | 동작 |
|---|---|---|
| **best-pass(기본)** | 회차들의 커버리지가 모두 ≥ 0.8 | 회차 하나를 '주 테이크'로 고르고, 다른 회차는 **문장 단위 보강·교체**에만 쓴다 |
| stitch | 어느 회차도 0.8 미만(중간에 끊고 이어 찍음) | 지금의 문장별 리테이크 해결을 **거리 제한 없이** 적용 |

**주 테이크 고르기** — 회차별 점수(기존 `take_score` 재료를 회차 단위로 평균):

```
pass_score = 0.35·대본 일치(평균 score) + 0.20·완결(끝까지 말한 문장 비율)
           + 0.15·유창성(추임새·되풀이 적음) + 0.10·발음 확신도
           + 0.10·화면 품질(visual: 초점·노출·정면·얼굴 크기) + 0.10·음질(SNR)
           − 실수 벌점(이름·숫자·고유명사가 대본과 다른 문장마다 −3)
```

- 동점이면 **나중 회차**를 고른다(대개 다시 찍은 쪽이 더 낫다).
- 총괄 감독이 이미 판단을 냈으면(팀 메모·`drop`이 한 회차 전체를 가리킴) 그것을 우선한다 → 3-4.

**문장 단위 교체** — 주 테이크의 문장 중 다음에 해당하면 다른 회차의 같은 문장으로 바꾼다.
- 주 테이크에서 그 문장이 빠졌거나 잘렸다(`_complete_sentences` 실패).
- 다른 회차의 `take_score`가 15점 이상 높다.
- 대본과 다른 낱말이 있다(이름·숫자).

교체가 일어나면 그 문장은 다른 파일(= 다른 구도)에서 온다. 이것은 **앵글 컷**으로 처리한다 — `angle_cut_times`에 넣어 소프트 컷을 하지 않고 새 샷으로 시작한다(지금 다시점 교차와 같은 문법).

### 3-3. 지는 회차를 B캠으로 쓰기(선택 — `JobSpec.alt_take_cutaways`, 기본 켬)

전체 회차가 두 개 있고 구도가 다르면, 주 테이크만 쓰는 것보다 **가끔 다른 구도로 넘어가는 편이 훨씬 프로처럼 보인다.**
단 두 회차는 동시 촬영이 아니라 입 모양이 맞지 않으므로 **소리째 넘어가야 한다**(영상만 바꾸는 컷어웨이 금지).

- 넘어가는 단위: 문장 또는 문단 전체(소리 + 영상을 같이 바꿈).
- 넘어가는 곳: 챕터 시작, 논점 전환(`moments.kind == "shift"`), 전면 그래픽에서 얼굴로 돌아오는 순간 — 어차피 화면이 바뀌는 자리.
- 조건: 두 회차의 그 문장 `take_score` 차이가 10점 이내(더 나쁜 테이크로 넘어가지 않는다), 한 번 넘어가면 최소 20초 유지, 영상당 최대 `챕터 수 + 2`회.
- 음질 차이: 회차별 `VoiceRecipe`를 따로 적용하고, 넘어가는 지점에서 룸톤을 0.2초 교차한다(`mix.py`).
- 색: 카메라(파일)별 `grade_N.cube`는 이미 있다. 여기에 **샷 매칭**(두 구도의 피부 L\*a\*b\* 중앙값 차이를 ΔE ≤ 3으로)을 추가한다 → [`07_영상_룩_v2.md`](07_영상_룩_v2.md).

두 구도의 색·배경 차이가 너무 크면(이번 테스트처럼 누런 벽 vs 주황 방) 넘어가기를 끄고 주 테이크만 쓴다:
`ΔE(배경 중간톤) > 12`이면 `alt_take_cutaways = False`로 떨어뜨리고 리포트에 이유를 적는다.

### 3-4. 감독의 삭제 요청 — 거절 조건 고치기(`pipeline.py:884`)

지금:
```python
if u.script_span and u.score >= 80:
    refused.append(...); continue
```

바꿈:
```python
if u.script_span and u.score >= 80 and not covered_elsewhere(u, self.utts, drop_ids):
    refused.append(...); continue
```

```python
def covered_elsewhere(u, utts, drop_ids, *, need=0.85) -> bool:
    """u 의 대본 구간이, 남아 있을(kept 이고 drop 대상이 아닌) 다른 발화들로 85% 이상 덮이면 True.
    → 지워도 대본 문장이 사라지지 않으므로 감독의 요청을 받아들인다."""
```

- 이것만 고쳐도 이번 테스트는 정상이 된다(감독이 1차 테이크 전체를 drop했고, 2차 테이크가 대본을 다 덮으므로).
- 반대 방향 안전장치: drop을 다 적용한 뒤 `_coverage()`를 다시 재서 떨어졌으면 가장 최근에 받아들인 drop부터 되돌린다.

### 3-5. 리테이크 창(`align.py _mark_retakes_by_script`)

```python
# 지금
for i in range(max(0, j - 10), j):
    if uj.start - ui.end > 120: continue

# 바꿈
same_pass = pass_of[ui.id] == pass_of[uj.id]
if same_pass and uj.start - ui.end > 120:      # 같은 회차 안의 먼 반복 = 의도적 반복(지금 규칙 유지)
    continue
# 회차가 다르면 거리 제한 없음 — 같은 대본 구간이면 같은 문장의 다른 테이크
```

그리고 `range(max(0, j - 10), j)`는 회차가 다를 때 쓸 수 없으므로, **대본 구간으로 색인**한다
(`span → [발화]` 구간 트리 또는 정렬 + 이분 탐색). 발화 200개 규모라 O(n²)도 무방하다.
