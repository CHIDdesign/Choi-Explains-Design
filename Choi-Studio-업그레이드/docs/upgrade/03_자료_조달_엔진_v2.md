## 2. 원칙

1. **주장 → 증거.** 화자가 대상·사례·출처·생김새를 말하면 그 문장 안에 그것이 보인다. 꾸밈용 자료는 넣지 않는다.
2. **빼지 않고 대체한다.** 틀린 사진보다 없는 게 낫다는 원칙은 유지한다. 다만 "없음"은 빈 화면이 아니라
   사다리의 다음 칸(다른 소스 → 코드로 그린 것 → 타이포 자료 카드)이고, 어느 칸에서 끝났는지 기록한다.
3. **화자 자료가 1순위.** 본인의 과제물·스케치·화면이 어떤 스톡보다 강한 증거다.
4. **라벨은 주장, 캡션은 사실.** 검색어·연출 메모·내부 이름은 화면에 나가지 않는다.
5. **자산마다 등급과 크레딧.** 등급이 크기·시간·가공 범위를 제한한다([정책](저작권_위험등급_정책.md)).
6. 채널 톤 유지: 젠틀한 편집, 대본 충실, 크림 종이·웜 잉크·주황 시그널 하나.

| need | 언제 | 1순위 → 대체 순서 | 기본 트리트먼트 |
|---|---|---|---|
| `own_material` | "제 과제", "작년에 만든", "이 장표" — 화자 자신의 것 | ④ 자료 폴더 → 채널 자산 라이브러리 → `code_drawn`(재현) → 자료 카드 | hero · sequence · annotate |
| `entity` | 인물·작품·제품·브랜드·장소·기관 이름 | Wikidata QID → Commons 분류/depicts·문서 내 이미지(`shot` 에 맞는 것) → 오픈 액세스 미술관 → Openverse(상업·변형 허용) → 자료 카드 | archive_card · hero · grid |
| `primary_source` | 논문·책·기사·실험·통계의 출처 | 서지 해석(Crossref) → **출처 카드**(자체 제작) + 문서 첫 화면 캡처(C 등급) → 그림은 재현(`code_drawn`) | doc_highlight · archive_card |
| `screenshot` | 웹사이트·앱·서비스 화면("핀터레스트부터 열면") | Playwright 캡처(과거 시점은 Wayback) → 로고(P154) + 화면 구조 재현 → 자료 카드 | browser_frame |
| `code_drawn` | 원리·구조·과정·실험 설계 | 모션 DSL/HTML 카드/원리 카탈로그. 검색하지 않는다 | (모션 디자이너) |
| `stock` | 과정·맥락·분위기("이렇게 만든다") | 스톡 허브 → 탈락 시 **재검색 1회**(must_show 완화) → 화자 얼굴로 둔다 | pip · full(2.5~4초) |
| `none` | 고백·의견·결론 | — | 얼굴 |

- 실행 순서는 [13](13_에이전트_팀_v2.md) 2-2 를 따른다: 자료 리서처 → 조달 → 확보 목록(`work/evidence.json`) → 모션 디자이너. `code_drawn` 요청은 원리 카탈로그(`assets/make/principles.py`)에 있으면 바로 만들고, 없으면 확보 목록과 함께 모션 디자이너에게 `claim`·`must_show` 로 넘긴다.
- **이번 대본에 대입**: 과제물·"거꾸로 채운 프로세스 장표" = `own_material`(폴더가 비면 재현 도식), 두 논문 = `primary_source`,
  핀터레스트 = `screenshot`, 더블 다이아몬드·고착 실험 설계 = `code_drawn`, "스케치북 넘기기" = `stock`.
  홍익대학교 = `entity`(place, 1장). "제품 렌더링 한 장"(R2·R4 탈락) = `own_material` 이 맞다 — 스톡에는 화자의 렌더링이 없다.
- `entity` 의 **`shot`**: `subject`(그 물건) · `screen`(서비스 화면) · `logo` · `portrait` · `detail` · `context`.
  사이트·앱·제품을 말했는데 인물 사진이 나오는 것은 오류다(M2). `kind=site_app` 이면 `shot` 은 `screen` 또는 `logo` 만 허용한다.
- `primary_source` 산출물(이번 두 논문으로 실측):
  - Crossref `query.bibliographic` → Jansson & Smith, "Design fixation", *Design Studies* 12(1), 3–11, 1991, DOI `10.1016/0142-694X(91)90003-F`(Elsevier).
    Leahy·Daly·McKilligan·Seifert, "Design Fixation From Initial Examples: Provided Versus Self-Generated Ideas", *J. Mech. Des.* 142(10), 2020, DOI `10.1115/1.4046446`(ASME).
  - OpenAlex `open_access` → 2020 논문은 `bronze`(무료 열람, 재사용 라이선스 없음). 1991 논문은 Crossref 에 Elsevier TDM 라이선스만 있고 OpenAlex 검색 상위에서는 찾지 못했다 → 둘 다 **C 등급**으로 다룬다.
  - 그래서 기본 산출물은 ① 서지 메타로 조판한 **출처 카드**(제목·저자·저널·연도·DOI — 사실 정보, 자체 제작) ② DOI 랜딩 첫 화면 캡처 + 한 문장 밑줄(C 등급, 4~6초 — 출판사 사이트가 캡처를 막으면 ①만 쓴다) ③ 실험 설계의 코드 재현이다. 논문 속 그림 자체는 기본 끔(`allow_figure_quote`).
  - `best_oa_location.license` 가 `cc-by`/`cc0` 이면 PDF 첫 쪽·그림을 A 등급으로 쓴다.

5  화면 캡처(Playwright/Wayback) · 문서 첫 화면 · 프레스 킷(허용 목록)             C / B
6  인용: 비자유 대표 이미지 · 책 표지 · 논문 그림 (allow_quote 일 때)               C
7  일반 스톡(Pixabay·Pexels·Unsplash·Coverr) — need=stock 일 때만

- need 가 시작 칸을 정한다: `own_material` 0 → 4 → 8, `entity` 0 → 1 → 2 → 3 → 6 → 8, `primary_source` 4 → 5 → 6,
  `screenshot` 5 → 1(로고) → 4 → 8, `stock` 7 → (재검색) → 없음.
- 미확인 소스(Rijksmuseum·Getty·NGA·Europeana·LoC·한국 API)는 권리·명세를 확인한 뒤 2·3번 칸에 더한다(리서치 문서 "검증 상태").

## 6. 스키마 변경

### 6-1. `studio/agents/schemas.py`

모든 object 는 `_obj()`(additionalProperties=false + 전체 required)로 만든다. 선택 항목은 빈 문자열·빈 배열로 채운다.

```python
VISUALS = ["none", "template", "motion", "evidence", "keyword",
           "stock_video", "stock_photo", "photo"]        # 뒤 셋은 저장된 계획 호환용 — 프롬프트에서는 evidence 만 안내

NEEDS = ["own_material", "entity", "primary_source", "screenshot", "code_drawn", "stock"]
EV_ROLES = ["proof", "example", "context", "process", "mood"]
EV_KINDS = ["person", "work", "product", "brand", "site_app", "place", "organization", "publication", "other"]
EV_SHOTS = ["subject", "screen", "logo", "portrait", "detail", "context", "first_page", "figure", "cover"]
TREATMENTS = ["hero", "full", "pip", "sequence", "grid", "stack", "cutout", "archive_card",
              "doc_highlight", "browser_frame", "detail_zoom", "annotate", "compare_pair"]
TIERS = ["A", "B", "C"]
FALLBACKS = ["type_card", "code_drawn", "stock", "face"]

EVIDENCE = _obj({
    "items": {"type": "array", "items": _obj({
        "start_seg": INT, "end_seg": INT, "start_word": STR,
        "claim": STR,                    # 이 자료가 뒷받침하는 화자의 말(40자 이내)
        "need": {"type": "string", "enum": NEEDS},
        "role": {"type": "string", "enum": EV_ROLES},
        "subject": _obj({
            "name_ko": STR, "name_en": STR,              # 대본 표기 / 원어 표기(모르면 "")
            "kind": {"type": "string", "enum": EV_KINDS},
            "shot": {"type": "string", "enum": EV_SHOTS},
            "creator_en": STR, "year": STR, "qid": STR,  # 모르면 ""
        }),
        "source": _obj({                 # primary_source·screenshot 일 때만, 아니면 전부 ""
            "citation": STR,             # "Jansson & Smith (1991) Design fixation. Design Studies 12(1)"
            "doi": STR, "url": STR,
            "as_of": STR,                # "2012-03" — 과거 시점 화면
            "locator": STR,              # 밑줄 칠 문장·그림 번호
        }),
        "stock": _obj({"kind": {"type": "string", "enum": ["video", "photo"]}, "query_en": STR, "query_ko": STR}),
        "local_file": STR,               # own_material: 자료 폴더의 파일명(없으면 "")
        "must_show": STR, "avoid": STR,
        "count": INT,                    # 1~5
        "label": STR,                    # 화면 제목(14자 이내, 주장의 한 조각). 없으면 ""
        "caption": STR,                  # 사실 캡션(24자 이내: 연도·작가·출처). 없으면 ""
        "treatment": {"type": "string", "enum": TREATMENTS},
        "focus": STR,                    # detail_zoom·annotate 대상(말로)
        "annotations": {"type": "array", "items": _obj({
            "type": {"type": "string", "enum": ["circle", "arrow", "underline", "bracket", "label"]},
            "target": STR, "text": STR, "at_word": STR})},
        "pair": _obj({"name_ko": STR, "name_en": STR, "label": STR}),   # compare_pair 가 아니면 전부 ""
        "tier_max": {"type": "string", "enum": TIERS},
        "fallback": {"type": "string", "enum": FALLBACKS},
        "priority": INT,                 # 1(필수) ~ 3
        "sequence_id": STR,              # 05 문서: 속한 시퀀스("" = 단발)
    })},
    "notes": STR,
})

EVIDENCE_PICK = _obj({
    "picks": {"type": "array", "items": _obj({
        "request": INT,
        "choices": {"type": "array", "items": _obj({
            "candidate": INT,
            "score": INT,                                 # 0~3 (게이트 B6 는 2 이상만 쓴다)
            "main_subject": {"type": "boolean"},
            "cliche": {"type": "boolean"},
            "shows": STR,                                 # 실제로 보이는 것 한 줄
            "focus_box": {"type": "array", "items": NUM},  # [x, y, w, h] 0~1, 없으면 []
        })},
        "reason": STR,
    })},
})
```
- `none`(얼굴로 둠)은 enum 에 없다 — 항목을 내지 않는 것이 `none` 이다. 쓰지 않는 enum 칸은 중립값으로 채운다(`subject.kind="other"`, `shot="context"`, `stock.kind="photo"`).
- `STOCK`·`STOCK_PICK`·`PHOTO_KINDS` 는 한 버전 동안 남긴다(저장된 `plan.json` 재실행용). `__all__` 에 새 이름을 더한다.
- 숏폼 PD 의 그래픽은 `SHORTS_PLAN` 을 그대로 쓴다. 숏폼은 `Pipeline._short_graphics` 가 그 구간의 롱폼 증거를 가져가므로, 숏폼 PD 프롬프트에서 스톡 요청(`broll`)은 "그 구간에 롱폼 증거가 없을 때만"으로 줄인다(이번 실행의 NC-ND 사진이 이 경로였다).

## 9. 되메우기 루프 — 게이트 B1·B2·B6 과 연결

`stage_assets` 끝에서 `studio/gate.py` 의 B 게이트를 부른다(08 문서의 정의를 그대로 쓴다).

```
assets_round(1)  →  B6: 2점 미만 자산 교체(다음 후보 → 사다리 다음 칸 → 자료 카드)
                 →  B2: 챕터마다 전면(풀블리드 또는 hero ≥ 화면의 55%) 증거 1회 이상?
                        아니면 그 챕터에서 해상도·점수가 가장 높은 자산을 hero 로 승격(promote_hero)
                 →  B1: 실물 이미지 시간 비율 ≥ 15%?  (목표 25~30%)
                        아니면 리서처 2차 호출 — 입력: 부족한 챕터, 증거 없는 claim 목록, 1차에서 탈락한 요청과 사유,
                        라이브러리·자료 폴더에 남은 자산 목록. 출력: EVIDENCE(추가분만)
assets_round(2)  →  B6 · B2 · B1 재검 → 그래도 미달이면 warn(리포트 맨 위) + GUI 안내
```
- 2차 호출은 **한 번만**. 스톡 탈락(M7)은 여기서 need 를 바꿔 다시 낸다(예: `stock` → `own_material`/`code_drawn`).
