## 1. [P0·버그] 같은 대본을 두 번 찍은 원본이 통째로 두 번 들어갔다

### 무슨 일이 있었나
- 원본 2개: `IMG_9597.MOV`(10.0분) · `IMG_9596.MOV`(9.5분). 같은 대본을 **다른 자리·다른 구도에서 처음부터 끝까지 한 번씩** 찍은 것.
- `log.txt:6` — 소리 싱크 검사: `상관 -0.24 … → 따로 찍음`. 동시 촬영이 아니므로 "나눠 찍은 것"으로 보고 **넣은 순서대로 이어 붙임**(묶음 1 + 묶음 2).
- 전사본: S0–S94 = 1차 테이크, S95–S199 = 2차 테이크.
- 총괄 감독은 정확히 알아챘다(리포트 팀 메모): "S0–S94는 통째로 drop, 2차 테이크만 쓴다. 최종 길이는 약 6분 23초".
- 그런데 파이프라인이 **"대본 문장은 빼지 않는다"** 규칙으로 감독의 삭제 요청 28건을 거절했다(`편집리포트.md` "삭제 거절: S0 … S29").
- 결과: 원본 19:35 → 롱폼 **12:44**. 감독이 계획한 길이의 정확히 두 배.

### 화면에서 보이는 증상
| 시각 | 화면 |
|---|---|
| 00:00–00:11 | 오프닝 하이라이트(2차 테이크, 주황빛 방) |
| **00:12–06:48** | **1차 테이크 전체. 그래픽 0개.** 정면 구도·누런 벽·침대와 기타 가방이 보이는 방. 자막만 있음(검토 시트 1~8) |
| 06:48 | 영상 한가운데서 **타이틀 카드**가 나오고 "안녕하세요"로 다시 시작 |
| 06:48–12:44 | 2차 테이크. 그래픽 41개 중 39개가 여기에 몰려 있음(나머지 2개는 하이라이트) |

- 리포트 통계: `face_ratio 0.953 · max_face_run 396.8초 · face_runs_over_25s 1`.
  얼굴만 나오는 화면이 95%, 가장 긴 맨얼굴 구간이 **6분 37초**다. 사용자가 느낀 "컷편집만 한 느낌"은 과장이 아니라 사실이다.
- 1차 테이크 끝에는 이름을 잘못 말한 "지금까지 최현준이었습니다"가 그대로 남아 있다(아트 디렉터 지적 `captions2 [high]`).
- 두 테이크는 방 구도·색이 완전히 다르다(1차 = 누런 녹색 벽, 2차 = 강한 주황). 한 영상 안에서 화면 톤이 둘로 갈린다.

### 코드 원인(셋이 겹쳤다)
1. **`studio/text/align.py` `_mark_retakes_by_script`** — 리테이크 후보를 "바로 앞 10개 발화 · 120초 이내"에서만 찾는다.
   ```python
   for i in range(max(0, j - 10), j):
       if uj.start - ui.end > 120:  # 2분 이상 떨어진 반복은 의도적 반복으로 본다
           continue
   ```
   10분 뒤에 다시 말한 2차 테이크는 "의도적 반복"으로 분류돼 둘 다 남는다. 리포트의 "리테이크 제거 3개"가 그 증거.
2. **`studio/pipeline.py`** — 편집 감독의 `drop` 중 대본 문장(score ≥ 80)은 무조건 거절한다. "그 문장이 **다른 곳에 한 번 더 살아 있는지**"를 보지 않는다.
   대본 충실 규칙의 목적은 "대본 문장이 **한 번은** 나오게"인데, 구현은 "대본과 맞는 발화는 **전부** 지키기"가 됐다.
3. **`studio/media/sources.py` `group_sources`** — 동시 촬영이 아니면 곧바로 "이어 붙이기"다. "같은 내용을 두 번 찍음(대체 테이크)"이라는 세 번째 경우가 없다.

### 안전망도 뚫렸다
- 아트 디렉터가 1라운드에서 `[high] 대본 전체가 두 번 들어갔다`고 정확히 지적했지만 `action: none`(그래픽 수정 수단밖에 없어서)으로 끝났고, 파이프라인은 그대로 렌더했다.
- "얼굴만 397초", "길이가 감독 계획의 2배" 같은 수치가 로그에 찍혔는데도 **멈추는 관문(품질 게이트)이 없다**.

## 2. [P0] 실물 이미지가 전체의 3.5% — "이미지 자료가 너무 없다"

그래픽 표(리포트 "그래픽" 절)를 종류별로 세면:

| 종류 | 개수 | 비고 |
|---|---|---|
| 글자 카드(keyword 8 · compare 3 · recap 3 · card 3 · chapter 3 · list 1 · title 1 · lower_third 1) | 23 | 전부 타이포그래피 |
| 도식(double_diamond 5 · process 2 · cycle 1) | 8 | 선 + 글자 |
| 모션 장면 | 5 | 점·원·화살표 + Pixabay 클립아트 |
| **스톡(broll)** | **4** | 전부 얼굴 옆 작은 액자(pip) |
| **자료 사진(photo)** | **1** | 얼굴 옆 작은 액자(pip) |

- 실제 사진·영상이 화면에 있는 시간: 4.3 + 7.3 + 6.9 + 4.3 + 3.7 = **26.5초 / 764초 = 3.5%**. 전면(풀스크린) 이미지는 **0회**.
- 플레이북 목표는 "B-roll·사진 30%"(`prompts/playbook/01_longform.md` 1-2)인데 실제는 그 1/9.

### 들어간 이미지도 틀렸거나 무의미하다
| 시각 | 화면 라벨 | 실제 이미지 | 문제 |
|---|---|---|---|
| 09:49 | 핀터레스트 | `Silbermann_at_SXSW.jpg` — 행사 무대에 앉은 남자 둘 | 위키백과 '핀터레스트' 문서의 **대표 이미지가 CEO 사진**. "핀터레스트부터 열면 비슷해진다"는 말과 무관. 필요한 건 핀터레스트 **화면** |
| 09:10 | 스케치북 넘기기 | 새를 그리는 손 | 라벨이 **검색어 그대로**. 넘기는 장면도 아님 |
| 10:22 | 책상 위 서류 더미 | 흑백 서류 더미 | 라벨이 검색어. 주장("이론이 서류가 됐다")이 안 보임 |
| 11:52 | 책 펼치고 메모하기 | 책상 위 손 | 라벨이 검색어 |
| 12:10 | 밤늦게 노트북 작업하는 학생 | **낮에** 메모하는 손(StartupStockPhotos) | 라벨과 사진이 다름. 전형적인 무료 스톡 |
| 07:55 | (모션) 렌더링 한 장 | 노란 기하 도형 3D 배경 | "제품 렌더링"으로 검색한 Pixabay 사진. 제품이 아님 |
| 09:37 | (모션) 고착 실험 | 초록 로고가 박힌 컬러 커피컵 클립아트 | 칠판·크림 선 화면에 **컬러 클립아트**. 실험의 실제 자극(Jansson & Smith의 예시 스케치)이 아님 |
| 11:25 | (모션) 간극 | 컬러 책 더미·책상 클립아트 | 같은 문제(아트 디렉터도 "톤이 다르다"고 적음) |

### 코드·프롬프트 원인
1. **고유명사가 없으면 사진 경로가 아예 없다.** `photos`는 "위키백과에 문서가 있는 고유명사"만 받는다(`prompts/agents/stock.md`).
   이번 대본은 개인 경험담이라 고유명사가 홍익대·핀터레스트 둘뿐 → 사진 2장이 상한. (홍익대 사진은 받았지만 최종 그래픽 표에 없다.)
2. **위키백과는 '대표 이미지 1장'만 본다**(`studio/broll/wikipedia.py lookup`). 문서 안의 다른 이미지·커먼즈 카테고리·제품 화면은 보지 않는다. 그래서 '핀터레스트' = CEO 사진.
3. **개념·논문·실험을 보여 줄 수단이 없다.** 이 영상의 핵심 근거는 논문 두 편(Jansson & Smith 1991, Leahy 외 2020)인데,
   논문 첫 쪽·실험 자극 그림·저널 표지 같은 **1차 자료**를 가져오는 경로가 없어 점 6개짜리 도식으로 대체됐다.
4. **구한 자료도 중간에 샌다.** 롱폼 깔때기: 요청 11(사진 2 + 스톡 9) → 확보 8(스톡 3건은 비전 선택에서 탈락, 재검색 없음) → 아트 디렉터 뒤 7 → **화면 5**.
   홍익대 사진과 노트 스케치 스톡은 받아 놓고도 타이밍 단계에서 다른 그래픽(타이틀 카드·도식 3연속)에 밀려 **삭제**됐다(`director/plan.py resolve_overlaps` — 사진·스톡의 우선순위가 6으로 가장 낮다).
   검색처는 Pixabay + Openverse 둘뿐이었다(`진단.md`: Pexels·Unsplash·Coverr 키 없음).
5. **스톡 라벨 = 검색어, 사진 라벨 = 내부 분류.** `studio/agents/studio.py merge_plan` 이 스톡의 `title` 에 `query_ko`, `body` 에 `purpose`(연출 메모), 사진의 `body` 에 `kind`(`brand`)를 넣고 렌더러가 그대로 찍는다.
   아트 디렉터는 g35~g38 의 검색어 라벨을 지적하고 새 제목까지 냈지만 **반영 0건** — `stage_qa` 가 `high`·`medium` 만 반영하는데 이 지적들은 `low` 였다.
6. **레이아웃이 전부 pip.** `stock.md`가 "pip를 가장 많이"라고 지시한다. 사진이 화면의 1/9 크기로만 나오니 "자료를 봤다"는 인상이 남지 않는다.
7. **화자 본인의 자료를 받는 입구가 약하다.** 이 영상에서 가장 강한 이미지는 화자의 **실제 과제물·스케치·거꾸로 채운 프로세스 장표**인데, 입력은 주제·영상·대본 셋뿐이다(`images_dir`는 있지만 GUI에서 안 보인다).
8. **라이선스 구멍.** 숏폼용으로 고른 Openverse 사진이 **CC BY-NC-ND 2.0**(비영리·변경 금지)이었다. 이번에는 타이밍에서 빠져 화면에 나오지 않았지만, `studio/stock/openverse.py` 가 라이선스 필터 없이 검색하므로 다음에는 나올 수 있다(이번 작업의 Openverse 후보 17건 중 8건이 NC/ND).

## 3. [P1] 화면이 전부 "슬라이드" — AI틱함의 시각적 원인

검토 시트에서 직접 본 것:

1. **한 영상에 재질이 아홉 가지.** 검은 무대 + 둥근 화자 판 + 크림 보드(챕터 1·2) / 차가운 회색 구겨진 종이 + 찢어진 액자(챕터 3·4) / **순백 전면 카드**(09:55 "예시 없으면 자유로울까?") / 거의 검정 전면 카드(09:00 "효율") / 흰색에 가까운 전면 카드(10:32) / 잉크 챕터 카드(07:27·09:07)와 **다르게 생긴** 회색 종이 챕터 카드(10:20) / **주황 전면 와이프**(09:05) / 재질 없이 영상 위에 뜬 굵은 흰 글씨. 6분 안에 이만큼 바뀐다. 하이브리드 스킨이 "변주"가 아니라 "일관성 없음"으로 읽힌다(표와 코드 위치는 [06](06_모션_그래픽_v2.md) 1-1).
2. **죽은 공간과 작은 글자.** 09:22·09:35·11:25(종이 콜라주 챕터) — 화자는 왼쪽 위 작은 액자, 도식 상자는 프레임 면적의 27%, 화자 액자 아래 약 706×380px 은 아무것도 쓰지 않는 사각지대다. 도식 글자는 스펙에서 계산하면 라벨 24~32px(제목 45~48px)로, 폰 세로 화면에서는 5~6.5pt 다. 08:45·10:45 에는 화자만 작아지고 옆이 통째로 비는 프레임도 있다.
3. **같은 템플릿의 반복.** double_diamond 5회, compare 3회, recap 3회, keyword 8회. 구조가 같고 글자만 바뀐다 → "템플릿에 글자를 부은" 느낌.
4. **빈 화면이 2~3초씩 뜬다.** 09:55 순백 화면에 검은 줄 하나, 09:00 검은 화면 왼쪽에 "효율" 한 단어, 10:32 흰 화면에 작은 글자 한 줄. 원인은 **0프레임에 아무것도 깔려 있지 않고 모든 요소가 말에 맞춰 하나씩 오기 때문**이다(09:55 카드의 막대는 7.0초에야 온다 — `plan.json` 타이밍).
5. **실물이 아니라 기호.** "리서치·스케치·고민"을 빈 네모 셋으로(07:52), "첫 아이디어"를 주황 점 하나로(09:22) 그렸다. 디자인 채널인데 디자인물이 한 번도 안 나온다.
6. **얼굴 옆 키워드가 사진 캡션 자리에 떠 있다.** 09:17 "왜 이걸 골랐지?", 11:47 "그래서, 이 채널" — 굵은 흰 글씨 + 주황 한 단어. 숏폼 자막 문법이 롱폼 얼굴 위에 그대로 얹혔다.

## 부록 A. Gemini 시청 결과(소리 포함)

> 이 절은 Google Gemini가 영상 전체를 보고 들은 뒤 답한 내용을 옮긴 것이다(Claude가 직접 들은 것이 아니다).
> 위 본문의 수치·화면 관찰은 리포트·검토 시트·실측에서 나온 것이고, 음악의 장르·악기·어울림 평가는 여기에 의존한다.

### A-1. 숏폼(55초) — Gemini가 보고 들은 것

**배경음악**
- 장르·악기: 캐주얼·브이로그풍의 경쾌한 업비트 팝(어쿠스틱 기타/신스 아르페지오, 전자 클랩, 가벼운 킥). 약 118~122 BPM, 밝고 가벼운 톤.
- 안 어울리는 이유: 화자는 진지하고 성찰적인 어조로 연구를 설명하는데 음악은 "일상 브이로그·쇼핑 팁"에 쓸 법한 장난스러운 멜로디다.
  멜로디가 뚜렷해 00:20~00:45의 내레이션을 계속 방해한다.
- 00:30(반전 "그런데 2020년에…")과 00:44(결론)에서 음악이 낮아지거나 멈추는 연출이 없어 긴장이 생기지 않는다.
- 어울릴 방향: 앰비언트, 차분한 로파이, 미니멀한 네오클래시컬·일렉트로닉 펄스.

**효과음**
- 카드가 바뀔 때마다 pop·whoosh·click 계열. 고음역의 가벼운 UI 소리가 반복돼 학술적인 내용의 신뢰감을 깎는다고 평가.
  (Gemini는 8~10회로 셌지만 믹스 기록은 5개다 — 횟수는 로그가 정확하다.)

**화면**
- 55초 내내 "위 카드 40% + 아래 얼굴 60%" 고정 구도가 한 번도 안 바뀐다. 카메라 배율 변화도 없다고 보았다.
- 실제 이미지·스톡: **0회 0초**(컵 아이콘 하나뿐).
- 카드 머리의 `motion`(00:05, 00:16)·`card`(00:33) 글자를 "템플릿 기본 레이어명 노출"로 지적 — 본문 3절 8번과 일치.
- 흰 카드와 검은 카드가 맥락 없이 섞인다(00:00 흰색 → 00:05 검정 → 00:30 흰색 → 00:33 흰색 → 00:51 어둡게).
- 00:33~00:50 논문 카드의 글자가 세로 화면에서 읽을 수 없을 만큼 작다(`JOURNAL OF MECHANICAL DESIGN` 출처 표기가 "노이즈처럼" 보임).
- 한두 낱말씩 바뀌는 자막이 위 카드와 시선을 다툰다.
- 위 그래픽은 디지털 흑/백인데 아래 영상은 가정집 조명 톤이라 위아래가 따로 논다.

**Gemini가 꼽은 잘된 점**(살려야 할 것): 첫 문장 훅의 선택, "첫 아이디어만 켜지고 대안 자리는 비어 있는" 도식의 발상, A/B 그룹 대조 구성, 결론 문장에서 끝나는 구간 선택.

> 주의: Gemini의 처방 중 "1.15~1.2배 펀치인", "딥 붐·테이프 스톱 효과음", "인물 누끼 뒤로 글자 지나가기"는 이 채널이 이미 받은 피드백
> ("훅훅 튀어 정신없다")과 충돌한다. 처방은 그대로 받지 않고 각 설계 문서에서 채널 톤에 맞게 걸렀다.

### A-2. 롱폼(12:44)

Gemini 시청을 얻지 못했다. 1.5GB 원본은 업로드가 너무 느려 중단했고, 480p 사본(21MB)으로 다섯 번 시도했지만 매번 Gemini 서버 과부하(HTTP 503)로 실패했다.
롱폼의 음악은 **귀로 들은 평가가 없다.** 대신 4절의 실측(곡 타임라인 복원, LU 레벨, 템포)이 근거다. 숏폼과 같은 라이브러리·같은 선택 로직이므로 A-1 의 평가가 방향으로는 그대로 적용된다.
나중에 다시 받으려면: `/watch <롱폼 파일>` (Gemini 가 한가한 시간에), 또는 `--engine local`(프레임 + 받아쓰기, 소리 평가는 안 됨).
