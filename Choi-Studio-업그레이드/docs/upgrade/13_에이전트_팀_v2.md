## 1. 지금의 흐름과 빈 곳

```
전사 → 정렬 → 🎬 감독 → [✂️ 편집 ∥ 🎨 모션 ∥ 🎞 자료 ∥ 🔤 자막 ∥ 📱 숏폼 ∥ ✍️ 카피] → merge_plan
     → 컷 → [편집 검사 ∥ 자료 사진 → 스톡 ∥ 효과음 준비] → 🧐 검수(스틸 12장) → 렌더(∥ 믹스) → 마스터
```

테스트 영상에서 드러난 빈 곳:

| 빈 곳 | 결과 |
|---|---|
| 감독이 본 **전사본의 구조적 이상**(대본 2회)을 코드가 받는 필드가 없다 — `notes_for_team` 자유 글에만 적힘 | 감독은 알았는데 파이프라인은 몰랐다 |
| 전문가 여섯이 **한 번만** 호출된다. 자료가 모자라도, 스톡이 탈락해도 다시 묻지 않는다 | 요청 9 → 화면 4 |
| 자료 리서처가 **모션 디자이너와 서로 모른다**(동시에 돈다) | 사진이 올 자리에 글자 카드가 먼저 들어가 사진이 밀려난다(우선순위 6 < 8) |
| 음악을 정하는 에이전트가 없다 | 무드 낱말 하나 + 무작위 |
| 아트 디렉터가 **도착한 스틸 12장**만 본다 | 타임라인 문제(중복·공백·리듬)와 모션 문제를 볼 수 없다 |
| 검수가 `revise` 여도 렌더는 진행된다 | `[high]` 를 달고 완성 |

## 2. v2 흐름

```
전사 → 정렬 → [회차 감지]                                   ← 02

      → [게이트 A0: 감독의 integrity vs 코드의 회차 감지 대조]
      → 1차 전문가: [✂️ 편집 ∥ 🎞 자료(증거 계획) ∥ 🔤 자막 ∥ 📱 숏폼 ∥ ✍️ 카피]
      → 🎞 자료 조달(사다리) → 확보 목록                     ← 03
      → 2차 전문가: 🎨 모션(확보된 자료를 받고 설계)          ← 2-2
      → merge_plan → 컷 → [게이트 A]                         ← 08
      → 🎼 음악 감독(편집 시각이 정해진 뒤 큐 시트)            ← 04
      → [게이트 B → 부족분만 🎞·🎨 재호출(최대 1회)]
      → 🧐 검수 1: 조판(모든 그래픽, 스트립 프레임) [게이트 C] ← 06c
      → 렌더(∥ 믹스 → [게이트 D])
      → 🧐 검수 2: 타임라인(검토 시트 전체) [게이트 E]         ← 05b
      → 마스터 → 내보내기(검토 필요 딱지)
```

### 2-1. 감독 브리프에 `integrity` 를 더한다(자유 글 → 필드)

감독은 전사본 전체를 읽는 유일한 에이전트다. 이번에도 문제를 정확히 봤다. 그 판단을 코드가 읽을 수 있게 한다.

```python
# studio/agents/schemas.py BRIEF 에 추가
"integrity": _obj({
    "passes": INT,                       # 대본을 처음부터 끝까지 읽은 횟수(보통 1)
    "main_pass_segs": _obj({"start_seg": INT, "end_seg": INT}),   # 주 테이크 범위(passes=1 이면 전체)
    "drop_ranges": {"type": "array", "items": _obj({"start_seg": INT, "end_seg": INT, "reason": STR})},
    "expected_sec": INT,                 # 주 테이크만 썼을 때 예상 길이(초)
    "issues": STR_LIST,                  # 그 밖의 구조적 이상(이름을 잘못 말함, 인사가 두 번 등)
}),
```

- `director.md` 에 한 문단: "전사본에 같은 대본이 두 번 이상 들어 있으면 `passes`·`main_pass_segs`·`drop_ranges` 로 낸다. 자유 글 메모에만 적지 않는다."
- 파이프라인: `integrity.drop_ranges` 는 편집 감독의 낱개 `drop` 과 달리 **범위 삭제**로 처리하고, `covered_elsewhere`(02 문서 3-4)를 통과하면 대본 문장이어도 받아들인다.
- 게이트 A0: 코드의 `detect_passes()` 결과와 감독의 `passes` 가 다르면 로그에 둘 다 적고 **코드 쪽을 따르되**, 감독의 `main_pass_segs` 가 코드가 찾은 회차 중 하나와 80% 이상 겹치면 그 회차를 주 테이크로 한다.
- `plan.py normalize_long` 에서 `integrity` 를 보존한다(CLAUDE.md 규칙: 새 키는 정규화에서 살려야 재실행 때 안 사라진다).

### 2-2. 자료가 먼저, 모션이 나중

지금은 자료 리서처와 모션 디자이너가 동시에 돈다. 그래서 모션 디자이너는 **무슨 사진이 확보됐는지 모르고** 글자 카드를 설계한다.

- 순서를 바꾼다: 자료 리서처(증거 계획) → 조달 → **확보 목록**(`work/evidence.json`: id · 대상 · 종류 · 해상도 · 썸네일 · 라이선스 등급)을 만든 뒤 모션 디자이너를 부른다.
- 모션 디자이너의 지시문에 확보 목록과 **컨택트 시트 1장**(썸네일 격자)을 준다. "이 자료를 주인공으로 장면을 짠다. 자료가 있는 문장에 글자 카드를 먼저 놓지 않는다."
- 시간 비용: 자료 조달(지금 약 2분 20초)이 모션 디자이너(지금 약 5분 20초) 앞으로 온다. 병렬이 직렬로 바뀌어 **약 2~3분 늘어난다.**
  그동안 GPU·CPU 는 프록시 인코딩을 하고 있으므로 전체 시간은 그보다 덜 늘어난다. 캐시(`stock.json`)가 있으면 재실행은 영향 없다.
- 대안(시간을 못 늘릴 때): 동시에 돌리되, 조달이 끝난 뒤 모션 디자이너를 **부분 재호출**한다 — "자료가 확보된 문장 N개의 그래픽만 다시". 출력 토큰이 더 든다.

### 2-3. 되돌아오는 길(게이트 → 부분 재호출)

재호출은 **부족분만** 묻는다. 지시문 끝에 다음 블록을 붙인다.

```
## 이번 호출은 보충이다
아래 구간·항목만 낸다. 이미 낸 것은 다시 내지 않는다.
- [B1] 03:10–04:40(S41–S58): 증거 이미지 0개. 이 구간의 문장 중 대상·사례를 말하는 것: S44 "…", S51 "…"
- [B6] g17 '핀터레스트': 확보한 사진이 대상의 주 피사체가 아님(무대에 앉은 사람 둘). 화면 캡처 또는 로고로.
```

| 게이트 실패 | 누구를 다시 | 최대 |
|---|---|---|
| A6·A7(그래픽 없는 구간·긴 맨얼굴) | 🎞 자료 → 🎨 모션(그 구간만) | 1회 |
| B1·B2·B6(이미지 부족·부적합) | 🎞 자료 | 1회 |
| B3·B4·B5(라벨 위생) | 에이전트 없이 규칙으로 수리, 안 되면 ✍️ 카피에게 라벨만 | 1회 |
| B7(템플릿 반복) | 🎨 모션(지정한 그래픽만 다른 형식으로) | 1회 |
| C(조판) | 🎨 모션 수정 / 🃏 카드 수정(지금과 같음) | 라운드 설정대로 |
| D6(음악 적합) | 🎼 음악 감독(차순위) | 1회 |
| E(타임라인) | 재호출 없음 — 검토 필요 딱지 | — |

## 4. 예산

이번 테스트의 실제 사용량(편집 리포트): 호출 13회 · 출력 79,141 토큰(모션 디자이너 37,327이 절반).

| 추가 호출 | 예상 출력 토큰 | 비고 |
|---|---|---|
| 🎼 음악 감독 | 2~4천 | 큐 10개 안팎 |
| 🎞 자료 리서처(증거 계획으로 확대) | +3~5천 | 지금 2,020 |
| 🎞 보충 1회 | 1~2천 | 게이트 실패 때만 |
| 🎨 모션 보충 1회 | 5~10천 | 게이트 실패 때만 |
| 🧐 타임라인 검수 | 3~5천 + 이미지 16~20장 입력 | 검토 시트는 이미 만든다 — 렌더 뒤 재사용 |
| 합계 | 평소 +10~15% · 최악 +35% | Pro/Max 구독 한도 안. 한도에 걸리면 `agent_models` 로 🎼·보충 호출만 Sonnet 으로 |

- 시스템 프롬프트는 플레이북 4개 + 스킬 노트 3개가 늘어 약 250~300줄 길어진다. 감독 호출이 캐시를 만들고 나머지가 읽는 구조는 그대로다.
  이번 리포트에서 `캐시 읽기` 가 거의 0으로 찍힌 것(모션 수정 1회만 31,971)은 **Claude Code 경로에서 캐시가 호출 사이에 공유되지 않고 있다**는 뜻일 수 있다 —
  `claude -p` 는 호출마다 새 세션이다. 프롬프트가 길어질수록 이 비용이 커지므로, 늘리기 전에 `studio/director/claude_code.py` 의 캐시 동작을 한 번 확인한다.

## 5. 실패에 강하게 — 지금 원칙 유지

- 새 에이전트가 실패해도 영상은 나온다: 🎼 실패 → 규칙 기반 큐(주제곡 1곡, 훅·챕터·엔딩에서만 올림), 타임라인 검수 실패 → 게이트 수치만으로 판정.
- 보충 호출이 실패하면 그 게이트는 `warn` 으로 내려가고 리포트 맨 위에 적힌다.
- 규칙 기반 폴백(`studio/director/fallback.py`)에도 `integrity` 를 채운다(`detect_passes` 결과 그대로).
