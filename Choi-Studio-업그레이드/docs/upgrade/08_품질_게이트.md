# 08. 품질 게이트 — "이상하면 렌더하지 않는다"

> 진단: [`00_테스트영상_진단.md`](00_테스트영상_진단.md). 이번 테스트는 로그에 `얼굴 화면 비율 95% · 얼굴만 이어진 최장 397초`가 찍혔고
> 아트 디렉터가 `[high] 대본 전체가 두 번 들어갔다`고 적었는데도 20분을 들여 렌더했다.
> 오토파일럿은 "사람이 안 봐도 된다"가 아니라 **"사람이 볼 필요가 있을 때 멈춰서 알려 준다"**여야 한다.

## 1. 구조

```
컷 확정(_make_edit) ─▶ [게이트 A: 구조]  ─ 실패 → 자동 수리 1회 → 재검 → 그래도 실패면 중단 + 사유
기획·자료 확보 뒤   ─▶ [게이트 B: 화면]  ─ 실패 → 담당 에이전트 재호출(부족분만) → 재검
렌더 props 확정 뒤  ─▶ [게이트 C: 조판]  ─ 실패 → 해당 그래픽 수정·대체
믹스 뒤             ─▶ [게이트 D: 음향]  ─ 실패 → 믹스 파라미터 보정 후 재믹스
최종 mp4            ─▶ [게이트 E: 완성본] ─ 실패해도 결과는 내되 '검토 필요' 딱지 + 리포트 맨 위
```

- 새 모듈 `studio/gate.py`: 검사 함수는 전부 **순수 함수**(입력 = plan·props·stats·파일, 출력 = `GateResult`). 파이프라인이 단계 사이에서 부른다.
- 각 검사는 `level: "block" | "repair" | "warn"`을 가진다.
  - `block` — 자동 수리가 안 되면 렌더하지 않고 멈춘다(GUI에 사유 + "그래도 만들기" 버튼).
  - `repair` — 정해진 수리 루틴을 한 번 돌리고 재검. 실패하면 `warn`으로 강등해 진행.
  - `warn` — 진행하되 리포트 맨 위 "검토 필요"에 적는다.
- 결과는 `work/gate.json` + `편집리포트.md` 첫 절 "품질 게이트"(통과/수리/경고 표).

```python
@dataclass
class GateResult:
    id: str                 # "A1_duration"
    ok: bool
    level: str              # block | repair | warn
    measured: dict          # {"long_sec": 764, "planned_sec": 383}
    message: str            # 사람에게 보여 줄 한 줄
    repair: str = ""        # 수리 루틴 이름
```

## 2. 게이트 A — 구조(컷 확정 직후, 렌더 전)

| id | 검사 | 기준 | level | 수리 |
|---|---|---|---|---|
| A1 | 길이 vs 대본 | `편집 길이 ≤ 대본 글자 수 / 화자 발화 속도 × 1.25`. 발화 속도는 이 영상의 실측(글자/초) | block | 회차 감지 재실행([02](02_전체테이크_중복_처리_설계.md)) |
| A2 | 길이 vs 감독 계획 | 감독이 적은 예상 길이(브리프 `expected_sec` 신설)의 0.8~1.25배 | block | A1과 같음 |
| A3 | 대본 문장 중복 | 같은 대본 구간(겹침 ≥ 60%)을 덮는 kept 발화가 2개 이상인 구간 = 0 | block | 더 낮은 `take_score` 쪽을 리테이크로 |
| A4 | 대본 커버리지 | ≥ 0.95 | block | `_restore_uncovered` |
| A5 | 인사·끝인사 위치 | "안녕하세요"·"…였습니다"·"구독" 류가 영상의 첫 10% / 마지막 10% 밖에 있으면 실패 | repair | 그 발화가 중복 회차면 A3로, 아니면 warn |
| A6 | 그래픽 분포 | 영상을 10등분했을 때 **그래픽이 0개인 구간이 없어야** 한다 | block | 모션·자료 에이전트를 그 구간만 다시 호출 |
| A7 | 맨얼굴 최장 구간 | `max_face_run ≤ 25초`(플레이북 절대 상한). 25~40초는 repair, 40초 초과는 block | repair/block | 그 구간에 콜아웃·자료·소제목 바 보충 요청 |
| A8 | 얼굴 화면 비율 | `0.35 ≤ face_ratio ≤ 0.70` | repair | 낮으면 그래픽 감축, 높으면 보충 |
| A9 | 타이틀 카드 위치 | 본편 시작 후 40초 안 | block | 타이틀 발화 재지정 |
| A10 | 원본 묶음 사용률 | 원본이 여럿인데 한 묶음에서 쓴 길이가 그 묶음의 10% 미만이거나, 전 묶음을 거의 전부(>90%) 다 썼는데 A1이 실패 | warn | 리포트에 "원본 2개가 같은 내용으로 보입니다" |

이번 테스트에 대입하면: A1(대본 6분 20초 분량인데 12분 44초) · A3(95문장 중복) · A5(영상 한가운데 "안녕하세요") · A6(10등분 중 앞 5칸이 0개) · A7(397초) · A8(0.953) · A9(타이틀 06:48) — **7개가 동시에 실패**한다. 하나만 있었어도 잡혔다.

## 6. 게이트 E — 완성본(선택: 비전·청취 모델)

렌더가 끝난 뒤 검토 시트(2.5초 간격)를 아트 디렉터에게 **전체 영상 단위로** 보여 준다(지금은 그래픽 스틸 12장만 본다).
질문은 그래픽 품질이 아니라 **영상 전체의 인상**이다.

1. 같은 장면이 두 번 나오는가(중복 테이크)?
2. 60초 넘게 화면이 안 바뀌는 구간이 있는가?
3. 디자인 채널인데 실제 디자인물·자료가 몇 번 보이는가?
4. 화면 재질·색이 중간에 바뀌는가?
5. 화면에 뜻 모를 라벨·영어 낱말이 있는가?

`ok: false`면 결과 폴더 이름과 GUI 결과 화면에 **검토 필요**를 붙인다. 업로드 자동화가 붙더라도 이 딱지가 있으면 올리지 않는다.

## 7. 아트 디렉터의 권한 확장

지금 `QA.action`은 그래픽 수정뿐이다(`none | shorten_text | change_layout | drop | revise_scene | revise_card`).
편집 문제를 발견해도 `none`밖에 못 낸다. 다음을 추가한다.

```python
"action": [..., "escalate_edit"],      # 편집·컷 문제 — 게이트 A를 다시 돌린다
"scope": ["graphic", "captions", "edit", "audio", "source"],
"blocking": BOOL,                       # true 면 렌더 전에 반드시 해결
```

`escalate_edit` + `blocking: true`가 오면 파이프라인은 게이트 A를 다시 돌리고, 통과하지 못하면 멈춘다.
