# 모션 예제 후보 10개 — 오늘의 MotionSpec 으로 쓴 것

> 상태(2026-10-02): **전부 `clean_spec` 통과 · 타이밍 린트 0건 · 렌더 검증 필요.**
> CLAUDE.md 규칙대로 렌더해서 눈으로 확인한 장면만 `prompts/examples/motion_examples.json` 에 넣는다. 이 문서는 그 전 단계의 후보다.

## 왜 새 예제인가

`motion_examples.json` 의 예제는 3개(`proximity` · `form_function` · `usability_stat`)다. 실제 작업(20261001_2028)에서 모션 디자이너가 낸 장면 5개는
이 셋의 구조(가운데 제목 + 작은 도형 + 아래 설명)를 닮았고, 타이밍 린트에서 장면마다 5~12건이 걸렸다(`docs/upgrade/06c_모션_검수_파이프라인.md` 5장).
아래 10개는 **같은 영상의 같은 구간**을 코드 변경 없이 더 낫게 짤 수 있다는 것을 보이는 후보다. 8개는 그 구간의 실제 길이와 단어 시각을 그대로 썼다.

## 이 예제들이 지키는 것

수치의 출처는 `docs/upgrade/06_모션_그래픽_v2.md` 4-1 · 6-4, `prompts/skills/motion_craft.md`, `06c` 3장이다.

| 규칙 | 값 |
|---|---|
| 0프레임 무대 | 첫 요소 0.3초 안, 0.5초 시점에 요소 2개 이상 + 잉크 35% 이상(`ghost` 가 아직 없으므로 흐린 윤곽 도형을 자리 표시로 쓴다) |
| 채움 | 요소의 외접 상자 ≥ 상자의 45%, 잉크 면적 ≥ 16%, 가장 큰 요소 ≥ 8% |
| 글자 | 제목 `size` 9, 라벨 4.6 이상(높이 644 상자에서 29px, 700 상자에서 32px). `faint` 색 글자 없음 |
| 동시 등장 | 0.1초 안에 둘까지, 0.5초 안에 세 묶음까지 |
| 읽는 시간 | 글이 안착한 뒤 다음 글까지 `0.4 + 글자 수 ÷ 12`초, 마지막 움직임 뒤 `max(1.2, 마지막 글의 글자 수 ÷ 7)`초 정지 |
| 말과의 동기 | 글자는 그 낱말이 나온 뒤 0.5초 안에 안착(실제 단어 시각으로 검사) |
| 히어로 무브 | 크게 움직이는 구간은 장면에 하나 |
| 강조색 | 한 화면에 한 곳. 제목 `highlight` 와 주황 도형을 같이 쓰지 않는다 |
| 쓰지 않은 것 | `pop` · `ease: "back"` · 컬러 클립아트(`pixabay:vector` · `illustration` · `cutout`) · `bar.label`(18px 로 그려진다) |

**오늘 문법으로 '등장 뒤에도 움직이게' 하는 법**: `keys` 는 첫 키 시각까지 **서서히** 보간한다(요소의 `at` 에서 출발). 가만히 있다가 움직이게 하려면
키를 둘 쓴다 — `{"t": 4.4, "opacity": 1}`(여기까지 유지) + `{"t": 4.9, "opacity": 0.35}`(도착). 실제 스펙 `g23` 의 `keys: [{"t": 2.8, "opacity": 0.3}]` 은
0.5초부터 2.3초에 걸쳐 흐려지는 것으로 렌더된다(`MotionScene.tsx sampleKeys`).

**요소 배열의 순서가 곧 겹침 순서**다(`at` 과 무관). 뒤에 깔릴 판·종이는 배열 앞에, 그 위의 글자는 뒤에 둔다.

**상자**: 지금 split 구성의 모션 상자는 종이 챕터 860×644, 보드 1069×644 다. `06` 의 책상 구성이 들어오면 1048×700 이 된다. 세 상자 모두에서 린트 0건을 확인했다.
