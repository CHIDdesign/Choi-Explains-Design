## 2. 구조 — 스위트 › 키트 › 판

| 층 | 뜻 | 개수 |
|---|---|---|
| 스위트(suite) | 악기·음색의 계열. 채널의 음색 팔레트 | 4개 |
| 키트(kit) | **곡 하나.** 한 영상의 스코어가 된다 | 스위트당 2~3개, 전체 6~10개 |
| 판(version) | 같은 곡의 편성 차이. 박 격자를 공유한다 | 키트당 `theme`·`bed`·`air`·`tag` |

| 스위트 | 악기 | 템포 | 어울리는 영상 |
|---|---|---|---|
| `felt` | 펠트 피아노(근접 녹음, 페달·해머 소리), 약한 테이프·룸 노이즈 | 60~76 BPM 또는 루바토 | 고백·사색·개념. 채널 기본 |
| `analog` | 따뜻한 아날로그 패드, 느린 아르페지오, 드럼 없음 | 70~90 | 구조·시스템·현대 디자인 |
| `brush` | 브러시 드럼, 업라이트 베이스, 로즈 | 78~92 | 사례·일화가 많은 편, 가벼운 숏폼 |
| `air` | 박 없는 드론·텍스처 | — | 밀도 높은 설명, 음악을 거의 원하지 않는 편 |

| 판 | 내용 | 쓰이는 곳 |
|---|---|---|
| `theme` | 온전한 편성. 2~4음 모티프가 있다 | 말이 없는 자리(타이틀·카드·엔드카드), 오프닝 |
| `bed` | 리드 선율·드럼을 뺀 성긴 변주 | 말 아래 |
| `air` | 같은 조성의 패드·잔향만 | 거의 들리지 않는 바닥, 숏폼 |
| `tag` | 종지 3~6초 | 엔딩, 숏폼 끝 |

- 판이 없으면 엔진이 대신한다. `bed` 가 없으면 `theme` 에 말 대역 컷을 늘 켜고 2 dB 내린다. `air` 가 없으면 `theme` 을 800 Hz 로우패스하고 8 dB 내린다. `tag` 가 없으면 곡의 마지막 마디를 쓴다.
- 채널 아이덴트(2~4초)는 키트 밖에 하나 둔다. 스위트의 조성에 맞게 옮긴 판을 같이 넣는다.

## 4. 운영자 큐레이션 절차(한나절)

목표: 키트 6~8개(felt 2 · analog 2 · brush 1~2 · air 1~2). 처음에는 `theme` 판만 있어도 엔진이 돈다.

| 단계 | 시간 | 할 일 |
|---|---|---|
| 0 | 15분 | 자기 영상에서 말이 이어지는 20초를 잘라 반복 재생해 둔다. **후보는 언제나 이 목소리 아래에서 작게 틀어 듣는다.** 곡만 따로 들으면 좋게 들리는 곡이 말 아래에서는 싸운다 |
| 1 | 2시간 | 아래 "어디서"와 "찾는 말"로 후보 20~30개를 모은다. "10초 탈락"에 걸리면 바로 넘긴다 |
| 2 | 30분 | 남은 10~12개를 받고, **받는 순간** 증빙을 저장한다: 라이선스 화면 캡처나 약관 문구, 곡 주소, 날짜, 플랜 이름 → `assets/sound/licenses/<id>.txt` |
| 3 | 20분 | `python scripts/sound_ingest.py <파일> --suite felt` 를 돌린다. 게이트 표(§5)에서 떨어진 이유를 본다 |
| 4 | 40분 | 스크립트가 만든 미리듣기 3종(말 아래 bed 20초 · 카드 feature 6초 · 엔딩 8초)을 듣고 승인한다(`approved_by`) |
| 5 | 15분 | 조성을 확인해 `key` 를 채운다(곡 페이지의 표기나 악기로 확인). 스위트 안에서 조성이 겹치지 않아도 된다. 한 영상은 키트 하나만 쓴다 |

**어디서(권리가 깨끗한 순서)**

1. **YouTube 오디오 라이브러리**(YouTube 스튜디오 › 오디오 보관함). YouTube 가 Content ID 주장이 걸리지 않는다고 밝히는 유일한 곳이다 — https://support.google.com/youtube/answer/3376882 . 장르·분위기·길이·저작자 표시 여부로 거른다(필터 이름은 화면 기준, 미확인). 저작자 표시가 필요 없는 곡은 권리 A, 필요한 곡은 C 다. 프로그램으로 받는 길은 없다.
2. **채널을 등록해 주장을 풀어 주는 유료 구독.** Epidemic Sound, Artlist, Uppbeat, Soundstripe, 국내는 BGM팩토리·셀바이뮤직이 채널 등록 방식을 쓴다(리서치 §B.5). 한 달 구독으로 받은 곡을 구독이 끝난 뒤 새 영상에 써도 되는지는 제공처마다 다르다(미확인). 확인해서 `valid_until` 에 적는다. 스템이나 "멜로디 없는 판"을 주는 곳이면 `bed` 판을 바로 얻는다(제공 여부 미확인).
3. **로컬 생성**(§6). 조성·템포를 지정할 수 있어 키트 만들기에 맞다.
4. **의뢰.** 아이덴트와 대표 키트 하나는 의뢰가 가장 확실하다. 계약서를 증빙으로 넣는다.
5. Pixabay·Mixkit·Bensound·Incompetech 같은 무료 스톡은 권리 D 이거나 자동 수집이 약관에 걸린다. 쓰려면 곡 페이지에서 Content ID 표시를 확인하고 손으로 받는다.

## 5. 입고 게이트(`scripts/sound_ingest.py`)

| 검사 | 통과 기준 | 이번 라이브러리에서 |
|---|---|---|
| 권리 등급 | `license.class` 가 A·B·C 이고 `proof` 파일이 있다 | 12곡 중 A~C 는 Mixkit 2곡뿐(증빙 없음) |
| Content ID | `content_id` 가 `none` 이거나, B 등급이면 `safelisted` | Registered 6곡 + 사전 등록 1곡 |
| 과압축 | `lufs_i` ≤ −13 그리고 `lra` ≥ 4. 트루 피크는 기록만 한다(MP3 는 디코드하면 0 dBTP 근처가 흔하다) | −13 LUFS 보다 큰 5곡, LRA 4 미만 2곡(Wallpaper 1.4, Lo-Fi 04 2.0) 탈락 |
| 밀도 | 초당 온셋: `bed` ≤ 2.0, `theme` ≤ 3.5(brush 는 4.5), `air` ≤ 0.5 | 피아노 3곡이 2.8~5.5 |
| 템포 | 박이 있으면 56~92 BPM(brush 는 96 까지). 배수 혼동은 사람이 확인 | 약 128, 105, 99 탈락 |
| 말 대역 | 1~4 kHz 에너지 비율: `bed` ≤ 3%, `theme` ≤ 6% | Digital Synergy 5.9%, Forest Mist Whispers 9.2% |
| 보컬 | 없음(사람이 확인. P2 에서 CLAP 으로 보조) | — |
| 루프 | 마디 경계 루프 점수 ≥ 0.85, 길이 ≥ 16마디. 없으면 `loop: null`(루프하지 않는 곡으로 표시) | — |
| 엔딩 | 마지막 온셋 뒤 감쇠 ≥ 2초, 또는 `tag` 판 | "…_Fadeout" 류는 종지가 없다 |
| 앞 무음 | `lead_silence_s` 기록(엔진이 건너뛴다) | Coverless book 5.6초 |
| 청취 승인 | `approved_by` 가 채워져 있다 | — |

- 권리 등급:
  - **A** 주장 위험이 없다: 직접 제작·의뢰, 로컬 생성(모델 라이선스가 상업 이용을 허용하고 프롬프트·시드를 기록), YouTube 오디오 라이브러리의 저작자 표시 불필요 곡, CC0.
  - **B** 채널 등록으로 풀린다: 유료 구독. `valid_until` 필수.
  - **C** 크레딧이 필요하다: CC BY, 저작자 표시 곡. `attribution` 문구가 업로드 정보에 그대로 나간다.
  - **D** Content ID 에 등록돼 이의 제기가 필요하다: 기본으로 끈다.
  - **X** 비상업·변경 금지·출처 불명: 입고하지 않는다.
- 기준 검출기(임계값은 이 검출기의 값이다): 22.05 kHz 모노, STFT 2048/512 Hann, `log1p(100·|S|)` 의 양의 차분 합을 온셋 강도로 쓴다. 온셋 = 국소 최대이면서 앞뒤 0.5초 중앙값의 1.5배 + 0.15σ 초과, 최소 간격 60 ms. 템포 = 온셋 강도 자기상관에 96 BPM 중심 로그 정규 가중, 45~200 BPM. Wallpaper 를 92.3 BPM 으로 읽었다(공개 값 92~93).
- 박·다운비트·루프 점은 P1 에서 Beat This!(코드·가중치 MIT)와 자체 루프 탐색(또는 PyMusicLooper, MIT)으로 채운다. madmom·Essentia 모델은 비상업 라이선스라 쓰지 않는다.
- 판 만들기(P2): Demucs(MIT)로 `drums`·`bass`·`other` 를 나눠 `bed` = 드럼을 뺀 판, `air` = `other` 를 로우패스한 판을 만든다. 4스템 분리는 선율과 패드를 구분하지 못하므로 "선율만 빼기"는 정확하지 않다.
- 임계값은 출발값이다. 운영자가 승인한 키트들의 분포로 다시 잡는다.

## 6. 생성 음악 — 키트를 만드는 또 하나의 길

| | 로컬: ACE-Step 1.5 | API: ElevenLabs Music |
|---|---|---|
| 권리 | 저장소·가중치 MIT. 모델 카드가 생성물의 상업적 이용을 허용한다고 적는다. 학습 데이터는 "라이선스 곡 + 퍼블릭 도메인·로열티 프리 + MIDI 합성"이라는 자체 선언 | 유료 플랜은 온라인 상업 이용 허용(영화·TV·라디오·스튜디오 게임 제외), 라이브러리화·재판매 금지 |
| 제어 | `bpm`(30~300), `keyscale`, `duration`(10초~10분), 가사란에 `[Instrumental]`, 참조 오디오, repaint·extend. 스템(extract·lego·complete)은 base·XL 모델만 | `prompt` 또는 `composition_plan`(섹션 3~120초), `music_length_ms`, `force_instrumental`, `seed`, 스템 분리 엔드포인트 |
| 실행 | Windows 네이티브(포터블 패키지, REST·Python API). 2B turbo 가 VRAM 6~8 GB 이하, XL 은 12 GB 이상 | `POST /v1/music`, 분당 0.15달러 |
| 고유성 | 로컬 시드라 남과 겹칠 일이 적다 | 약관이 "다른 사용자에게 같거나 비슷한 결과가 나올 수 있다"고 적는다 |
| 출처 | https://github.com/ace-step/ACE-Step-1.5 · https://huggingface.co/ACE-Step/Ace-Step1.5 | https://elevenlabs.io/docs/api-reference/music/compose · https://elevenlabs.io/eleven-music-model-specific-terms |

쓰는 방식:
- **영상마다 생성하지 않는다.** 스위트마다 한 번에 10개쯤 만들고 §5 게이트와 청취 승인을 거쳐 2~3개만 키트로 남긴다. 생성은 작곡가를 고용하는 일의 대용이다.
- 키트 하나를 만들 때는 `bpm`·`keyscale` 을 고정하고 `describe` 를 프롬프트로 쓴다. `theme` 을 먼저 만들고 `bed`·`air` 는 스템이나 Demucs 로 파생한다(박 격자가 같아야 한다).
- `generation` 에 모델·프롬프트·시드·파라미터를 남긴다. 이것이 A 등급의 증빙이다.
- 로컬 대안: Stable Audio 3 Medium(최대 380초, 피크 VRAM 5~6.5 GB, 연 매출 100만 달러 미만 무료 상업 이용, BPM·조성 파라미터 없음) — https://github.com/Stability-AI/stable-audio-3 . Small-Music 판은 CPU 에서 120초까지 만든다.
- 쓰지 않는 것: MusicGen 계열·YuE2(가중치 비상업), Udio(다운로드 불가), Suno(공개 API 없음, 소송 진행 중) — 리서치 §B.6.

솔직한 한계:
- 어느 모델도 연주곡 품질을 들어 보지 못했다. 게이트 수치는 "성기고 눌리지 않았다"까지만 보장한다.
- ACE-Step 의 호출 형식(엔드포인트 이름·필드)은 확인하지 않았다(미확인). 파라미터 이름은 저장소의 Tutorial 문서 기준이다.
- AI 생성물은 저작권 보호가 약하다(미국 저작권청 2025-01 보고서: 프롬프트만으로는 보호 대상이 아니다 — https://www.copyright.gov/newsnet/2025/1060.html ). 쓸 수는 있지만 독점할 수는 없다.
- YouTube 의 합성 콘텐츠 공개 의무가 배경음악에도 적용되는지는 확인하지 못했다(미확인) — https://support.google.com/youtube/answer/14328491
