# 01. 업그레이드 로드맵 — 무엇을 어떤 순서로

> 근거: [`00_테스트영상_진단.md`](00_테스트영상_진단.md). 각 항목의 상세 설계·코드 위치·테스트 이름은 해당 문서에 있다.
> 공수는 한 사람(또는 Claude Code 한 세션) 기준 어림값이다.

## 순서의 원칙

1. **버그 먼저, 취향 나중.** 이번 영상의 인상을 망친 것의 절반은 편집 감각이 아니라 결함이다(중복 테이크, 라벨 누수, 구한 자료의 유실, 옛 설치본).
   이것들을 고치고 **같은 원본으로 다시 돌려 본 뒤** 나머지를 판단한다.
2. **멈추는 장치를 두 번째로.** 게이트가 없으면 다음 결함도 20분 렌더가 끝나야 보인다.
3. **재료 → 구성 → 마감.** 실물 자료(03)가 있어야 시퀀스(05)가 서고, 재질이 하나(06)여야 색·질감(07)이 의미가 있다. 음악(04)은 독립이라 언제든 끼울 수 있다.

## 하지 않을 것

- 줌·휩·임팩트 효과음을 늘려서 "프로처럼" 보이게 하기 — 채널 피드백("훅훅 튀어 정신없다")과 충돌한다. 프로다움은 증거·시퀀스·홀드·한 재질·스코어에서 온다.
- AI 생성 이미지로 빈자리 채우기 — "AI틱함"의 직접 원인이 된다. 허용 범위는 질감·배경뿐([`저작권_위험등급_정책.md`](저작권_위험등급_정책.md), 03 리서치).
- 업스케일러·얼굴 복원·항상 켜진 디노이즈·샤픈([07](07_영상_룩_v2.md)).
