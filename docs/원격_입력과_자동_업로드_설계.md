# 폰에서 넣고, 유튜브·인스타그램에 자동으로 올리기 — 조사와 설계

2026-09-30 조사. 아직 구현하지 않은 **다음 단계 설계**다. 지금 프로그램은 Windows PC 에서 세 가지(주제 · 원본 영상 · 대본)를 넣으면
롱폼 1 + 숏폼 2 를 만들어 `output/` 에 저장하고 `업로드정보.txt`(제목 후보 · 설명란 · 태그 · 숏폼 캡션)까지 써 두는 데서 끝난다.
여기서 두 가지를 더하려면:

1. **폰에서 넣기** — 노트북 앞에 앉지 않고 촬영본·대본·주제를 보낸다.
2. **자동 업로드** — 완성되면 유튜브(롱폼 + 쇼츠)와 인스타그램(릴스)에 올린다.

결론부터: 둘 다 공식 API 로 가능하고 비용은 거의 없다. 다만 **유튜브는 API 심사(Compliance Audit)를 통과하기 전까지 API 로 올린 영상이
비공개로 잠기고**, **인스타그램은 영상 파일이 공개 URL 에 있어야** 한다. 이 두 제약이 설계를 정한다.

---

## 1. 전체 흐름

```
폰                          PC(워커)                                    플랫폼
─────────────────────       ───────────────────────────────────────    ──────────────
① 촬영본·대본·주제를    →   ② 접수함 감시 → 기존 파이프라인 실행    
   접수함에 넣는다            (headless: python -m studio run)
                             ③ 결과 + 검토 시트 + 썸네일을 폰으로   →   (텔레그램 알림)
④ 폰에서 훑어보고       →   ⑤ 승인되면 업로드                      →   YouTube(롱폼·쇼츠 2)
   '올려' 라고 답한다                                                  →   Instagram(릴스 2)
                             ⑥ 결과 링크·상태를 폰으로              →   (텔레그램 알림)
```

- **PC 는 계속 켜 두거나 원격으로 깨운다.** 음성 인식(GPU)·렌더(Chrome)·인코딩은 지금처럼 PC 가 한다. 나중에 클라우드 GPU 로 옮길 수도
  있다(아래 6장).
- **사람이 한 번 보는 단계(④)를 남긴다.** 완전 자동도 되지만, 결과 품질은 녹화·AI 판단에 따라 달라지므로 폰에서 검토 시트
  (`부가자료/검토시트_*.jpg`, 2.5초마다 한 장)와 썸네일만 훑고 '올려' 한마디로 승인하는 쪽이 안전하다. 유튜브의 **예약 공개**를
  쓰면 승인 없이 올려도 공개 전까지 YouTube Studio 앱에서 취소·수정할 시간이 생긴다.

## 2. 폰에서 넣기 — 접수함

촬영 원본은 수 GB 다(4K 20분 ≈ 5–10GB). 그래서 **파일은 클라우드 폴더로, 글은 채팅으로**가 현실적이다.

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **클라우드 폴더 감시** (Google Drive · OneDrive · iCloud Drive 의 `ChoiStudio/접수함/`) | 폰 공유 시트에서 바로 저장, 큰 파일 OK, PC 동기화 앱이 알아서 받음 | 동기화 끝날 때까지 기다려야 함(파일 크기 안정될 때 시작) | **기본** |
| 텔레그램 봇 | 채팅으로 주제·대본 보내기 편함, 알림·승인 버튼까지 한곳 | 공식 Bot API 는 **파일 내려받기 20MB 제한**. 직접 Bot API 서버를 돌리면 2000MB — 촬영 원본엔 부족 | **글·알림·승인용** |
| PC 위 작은 웹앱 (FastAPI + Tailscale/Cloudflare Tunnel) | 업로드 화면을 맘대로 | 폰 브라우저로 수 GB 올리기는 불안정, 서버 관리 | 나중 |
| 카카오톡 | 익숙함 | 봇이 파일을 받는 공개 API 가 없음 | 알림만 가능 |

**접수함 규칙(제안)**
```
접수함/
└── 2026-10-05 게슈탈트/        ← 폴더 하나 = 작업 하나
    ├── 원본.mp4  (여러 개면 전부: 다른 각도·나눠 찍은 것)
    ├── 대본.txt  (또는 .docx/.hwpx)
    ├── 주제.txt
    └── 시작       ← 이 빈 파일을 만들면(폰에서 메모 앱으로 저장) 시작. 없으면 파일 크기가 10분간 안 변할 때 시작
```
- 워커: `python -m studio watch --inbox <폴더>` (새 명령). 폴더를 30초마다 훑어 조건이 맞으면 `Pipeline.run()` 을 창 없이 돌리고,
  결과를 `보낸함/<작업>/` 에 복사한다(클라우드가 다시 폰으로 올려 준다). 진행·완료·오류는 텔레그램으로.
- 주제·대본을 텔레그램으로 보내는 것도 받는다: 봇이 마지막 메시지들을 `주제.txt`·`대본.txt` 로 저장.
- PC 가 꺼져 있으면: Wake-on-LAN(같은 집 공유기면 폰 앱으로 깨움) 또는 그냥 켜 둠. 절전만 막으면 된다.

## 3. 검토와 승인(폰)

- 완료 알림에 붙는 것: 썸네일 3장, 검토 시트(롱폼·숏폼), `업로드정보.txt` 의 제목 후보·설명 요약, 편집 리포트의 "자동 후반 작업" 부분
  (색보정 레시피 · 앵글 · 화면 구성).
- 텔레그램 인라인 버튼: **[유튜브+인스타 올리기] [유튜브만] [예약 공개(내일 18:00)] [다시 만들기] [보류]**.
  제목 후보 중 고르기도 버튼으로(1/2/3).
- 승인 없이 자동으로 가고 싶으면: 유튜브는 **예약 공개**(비공개로 올리고 `publishAt`), 인스타는 승인 뒤에만. 릴스는 올리는 순간 공개라
  되돌리기가 삭제뿐이다.

## 4. 유튜브 업로드 — YouTube Data API v3

### 필요한 것
1. Google Cloud 프로젝트 만들고 **YouTube Data API v3** 켜기.
2. OAuth 클라이언트(데스크톱 앱) 만들기 → `client_secret.json` 을 `user/` 에(저장소 밖, gitignore).
3. 처음 한 번 PC 브라우저에서 채널 계정으로 동의 → 리프레시 토큰을 `user/youtube_token.json` 에 저장. 이후는 자동 갱신.
   스코프: `youtube.upload`(올리기) + `youtube.force-ssl`(썸네일·자막·재생목록).
4. 채널에 **전화번호 인증**(썸네일 지정과 15분 넘는 영상에 필요).

### 흐름(영상 1편 = API 호출 4~5번)
| 단계 | 호출 | 내용 |
|---|---|---|
| 올리기 | `videos.insert` (재개 가능 업로드, 1080p 파일 그대로) | `snippet`: 제목 · 설명(챕터 타임코드 포함) · 태그 · `categoryId=27`(교육) · `defaultLanguage=ko` / `status`: `privacyStatus` · `publishAt`(예약) · `selfDeclaredMadeForKids=false` |
| 썸네일 | `thumbnails.set` | `부가자료/썸네일1_signal.jpg` |
| 자막 | `captions.insert` | `롱폼_자막.srt`(한국어) — 자동 자막보다 정확 |
| 재생목록 | `playlistItems.insert` | 시리즈 재생목록에 추가 |
| 쇼츠 | `videos.insert` 같은 방식 | 세로(9:16) · **3분 이하**면 자동으로 쇼츠 분류(따로 설정 없음). 제목·설명에 `#Shorts` |

- 우리 `업로드정보.txt` 가 이미 제목 후보 · 설명란(챕터 타임코드) · 태그 · 숏폼 캡션을 갖고 있으니 그대로 넣으면 된다.
- 할당량: 프로젝트마다 하루 **`videos.insert` 100회**, 그 밖 10,000단위(썸네일 50 · 자막 400). 영상 한 편(롱폼 1 + 쇼츠 2)이면 넉넉하다.

### 가장 중요한 제약 — API 심사 전엔 비공개로 잠긴다
> "All videos uploaded via the videos.insert endpoint from unverified API projects created after 28 July 2020 will be restricted to private viewing mode."

- 2020-07-28 이후 만든 프로젝트는 **Compliance Audit(API 규정 심사)** 를 통과하기 전까지 API 로 올린 영상이 **비공개로 잠긴다**.
  `privacyStatus=public` 으로 보내도 실패하지 않고 조용히 잠기며, 이 잠금은 이의 제기가 안 된다.
- 심사: "YouTube API Services – Audit and Quota Extension Form" 제출. 공개된 **개인정보처리방침·이용약관 페이지**(GitHub Pages 로 충분),
  앱이 무엇을 하는지 설명, 사용자가 접근을 철회할 수 있는 방법. 개인 도구라도 신청할 수 있고 보통 몇 주 걸린다.
- **심사 전 현실적인 운용**: 비공개(또는 예약)로 올리고 → 폰의 **YouTube Studio 앱에서 공개로 바꾸는 한 번의 탭**. 제목·설명·태그·
  썸네일·자막·재생목록은 이미 다 들어가 있으므로 손이 거의 안 간다. 심사가 통과되면 그 탭도 없어진다.

## 5. 인스타그램 릴스 — Instagram Platform API(Instagram Login)

### 필요한 것
1. 인스타그램 계정을 **프로페셔널(비즈니스 또는 크리에이터)** 로 전환. 페이스북 페이지는 **필요 없다**("Instagram API with Instagram Login").
2. Meta for Developers 에서 앱 만들기 → Instagram 제품 추가 → 권한 `instagram_business_basic` + `instagram_business_content_publish`.
3. **내 계정에만 올리면 앱 심사(App Review) 필요 없음** — 앱을 개발 모드로 두고 내 계정을 테스터/관리자로 넣으면 된다. 다른 사람 계정에
   올리는 서비스로 만들 때만 심사(2~4주, 스크린캐스트·사업자 인증).
4. 토큰: 60일짜리 장기 토큰을 `user/instagram_token.json` 에 저장, 만료 전 자동 갱신.

### 흐름(릴스 1개 = 호출 3번 + 상태 확인)
```
POST /<IG_ID>/media           media_type=REELS, video_url=<공개 URL>, caption=..., share_to_feed=true,
                              cover_url=<썸네일 URL> 또는 thumb_offset=<ms>
GET  /<컨테이너 ID>?fields=status_code   → FINISHED 될 때까지 몇 초마다(보통 30초~2분)
POST /<IG_ID>/media_publish   creation_id=<컨테이너 ID>
```

### 제약
- **영상이 공개 URL 에 있어야 한다.** Meta 서버가 그 URL 을 받아 간다("we cURL media … must be hosted on a publicly accessible server").
  PC 파일을 그냥 줄 수 없으므로 두 가지 중 하나:
  - **임시 저장소**: Cloudflare R2(무료 10GB) · Backblaze B2 · S3 에 올리고 서명된 URL 을 준 뒤, 게시가 끝나면 지운다. **추천** — 단순하고
    PC 를 밖에 노출하지 않는다.
  - Cloudflare Tunnel 로 PC 폴더를 잠깐 공개. PC 가 켜져 있어야 하고 보안 신경 쓸 게 많다.
- 릴스 규격: MP4/MOV, H.264 또는 HEVC, AAC, 23–60fps, 세로 9:16 권장, **3초~15분**, **300MB 이하**, `moov` 앞(faststart). 우리 숏폼
  (1080×1920 · 30fps · 55초 안팎)은 그대로 맞고 용량도 수십 MB 다. 롱폼(16:9)은 릴스 대상이 아니다.
- 하루 **100개**까지(24시간 이동 창). 캡션은 `업로드정보.txt` 의 숏폼 캡션을 쓴다.
- 비공식 방법(폰 앱 자동 조작·쿠키 로그인 봇)은 계정 제재 위험이 커서 쓰지 않는다. 위 API 는 Meta 공식이다.

## 6. 대안: 게시 대행 서비스 하나로

Buffer · Publer · Metricool · Upload-Post 같은 서비스는 유튜브·인스타·틱톡을 **API 하나**로 받고, 구글·메타 심사를 자기들이 통과해 둔 상태다.
- 장점: 유튜브 비공개 잠금 문제와 인스타 공개 URL 문제를 둘 다 서비스가 대신 처리. 구현이 가장 짧다(파일 + 제목 + 예약 시간 POST).
- 단점: 월 요금(API 플랜은 대개 유료), 파일이 남의 서버를 거친다, 서비스가 바뀌면 따라가야 한다.
- 판단: 먼저 공식 API 로 만들되, 유튜브 심사가 오래 걸리면 그동안 이런 서비스를 잠깐 쓰는 것도 방법.

## 7. 워커를 클라우드로 옮길 때(선택)

- 파이프라인은 창 없이도 돈다(`python -m studio run`; 이 저장소의 E2E 는 리눅스 컨테이너에서 돌고 있다). Windows 전용인 것은 창·설치
  스크립트뿐이라, 리눅스 GPU 서버에서도 그대로 돌릴 수 있다.
- 비용 감: RTX 4090급 시간제 GPU ≈ 시간당 $0.4~0.7. 15분 영상 한 편이 30~40분 걸리면 **편당 $0.3~0.5**. Claude 기획은 지금처럼
  구독(Claude Code)으로.
- 대신 촬영 원본을 서버로 올려야 하므로(수 GB) 접수함이 클라우드 저장소여야 한다 — 2장의 클라우드 폴더 방식과 같다.

## 8. 구현 순서(제안)와 저장소에 들어갈 것

| 순서 | 일 | 크기 |
|---|---|---|
| 1 | `studio/upload/youtube.py`: OAuth · 재개 가능 업로드 · 썸네일 · 자막 · 재생목록 · 예약. 설정 대화상자에 "유튜브 연결" 버튼(브라우저 동의). 결과 화면에 "유튜브에 올리기(비공개/예약)" 버튼 | 2~3일 |
| 2 | Google Cloud 프로젝트 + 개인정보처리방침·이용약관 페이지(GitHub Pages) + **Compliance Audit 신청** | 반나절 + 대기 수 주 |
| 3 | `studio/upload/instagram.py`: 토큰 갱신 · 임시 저장소 업로드 · 컨테이너 → 상태 → 게시. 결과 화면에 "릴스 올리기" | 2일 |
| 4 | `python -m studio watch`: 접수함 감시 · headless 실행 · 보낸함 · 오류 재시도 | 2일 |
| 5 | `studio/notify/telegram.py`: 완료 알림(썸네일·검토 시트) · 승인 버튼 · 주제/대본 받기 | 1~2일 |
| 6 | (선택) 클라우드 워커용 설치 스크립트(리눅스) | 1~2일 |

지켜야 할 것: 토큰·클라이언트 비밀은 전부 `user/`(gitignore)에, 로그·진단에는 있음/없음만(지금 `net.redact` 규칙 그대로). 업로드는
반드시 마스터링된 최종 파일(`output/*.mp4`)만. 실패하면 파일을 남기고 알림에 이유를 적는다.
