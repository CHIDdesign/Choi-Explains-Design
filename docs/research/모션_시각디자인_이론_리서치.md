해석 [제안]
- linear 는 '시작하자마자 최고 속도, 멈출 때 즉시 정지'라 무게가 없다. CSS `ease`/AE Easy Ease 는 **대칭에 가깝고 감속 꼬리가 짧아** 모든 요소가 같은 성격으로 움직인다. 프로의 차이는 (1) 진입·퇴장·이동에 **서로 다른 곡선**을 쓰고 (2) 감속 꼬리를 길게(quart~expo) 잡고 (3) 요소 크기·역할에 따라 곡선을 바꾸는 데 있다. Carbon 이 productive/expressive 로 두 벌을 둔 것, M3 가 standard/emphasized 를 나눈 것이 같은 생각이다.
- 현재 `motion.ts` 의 `outQuint (0.23,1,0.32,1)`·`outExpo (0.19,1,0.22,1)` 는 easings.net 정본과 소수 둘째 자리만 다르다. 바꿀 필요는 없고, **역할 이름**이 없어서 에이전트가 아무 데나 outQuint 를 쓰는 것이 문제다.

영상으로 옮길 때 [제안]
- UI 수치는 '사용자가 조작을 기다리는' 상황 기준이다. 영상은 조작이 없고 시선 이동 거리가 길어, 기존 리서치가 확인한 영상용 스킬 값(조각당 400~600ms, "Premium" 350~600ms)이 M3 의 medium4~long4(400~600ms) 구간과 겹친다. 그래서 이 채널의 사다리는 **M3 토큰을 30fps 프레임으로 읽은 값**으로 잡는다: 200ms=6f, 300ms=9f, 400ms=12f, 500ms=15f, 600ms=18f, 800ms=24f. 현재 `DUR`(5/8/12/18/24)와 거의 같다. 없는 것은 **고르는 규칙**이다.

|---|---|---|
| 제자리 변화(색·밑줄·불투명도) | 4~6f | 강조색 전환, 칩 |
| < 5% (≈54px) | 8f | 단어 리빌, 배지 |

| 15~35% | 14~16f | 플레이트 쓸어 들어오기, 화자 열 이동 |
| 35~60% 또는 면적 > 프레임의 30% | 18~20f | 보드 판 |

### 1-3. 오버슛과 스프링

| 근거 | 내용 | 표기 |

직접 계산 [제안의 근거]
- 감쇠비 ζ = damping / (2·√(stiffness·mass)).
  - Remotion 기본(100/10): ζ = 0.5 → 오버슛 약 **16%**. 이 기본값을 그대로 쓰면 '통통 튀는 웹 데모' 느낌이 난다.
  - 현재 토큰 `gentle`(100/20): ζ = 1.0(임계 감쇠, 오버슛 0) · `stiff`(400/30): ζ = 0.75 → 약 **2.8%** · `slow`(50/20): ζ = 1.41(과감쇠).
- bezier `(0.34, y1, 0.64, 1)` 의 피크(y(t) = 3(1−t)²t·y1 + 3(1−t)t² + t³ 최대값): y1=1.56 → **≈ +9.8%**, y1=1.35 → **≈ +4.1%**, y1=1.2 → **≈ +1.3%**.

규칙 [제안]
- Material 3 가 위치 스프링에 감쇠비 0.9(오버슛 ≈ 0.15%)를 쓰는 것이 '차분한 제품' 기준선이다. 교육 채널의 롱폼은 **오버슛 0~4%**, 숏폼 훅만 **≤ 10%**.
- 오버슛은 '가벼운 것'에만: 배지·칩·테이프·작은 스티커. 큰 면(보드·전면 카드)과 **글자 줄**은 오버슛 0.
- 종이는 탄성체가 아니다. 종이의 '안착'은 스케일 바운스가 아니라 **회전·그림자**가 정착하는 것으로 표현한다(§4-3).

규칙 [제안] — 수치는 이 채널용 설계값
- **예비동작은 '의지가 있는 것'에만**: 숫자 카운터가 치고 올라가기 전 1~2f 정지, 키워드 슬램 전 사진이 먼저 어두워짐(이미 `KeywordSlam` 의 dim 10f 가 예비동작 구실). 종이 메모·사진 같은 '붙이는 물건'에는 반대 방향 예비동작을 넣지 않는다(School of Motion 의 "의지 없는 물체" 기준).
- 예비동작 크기: 본 동작 거리의 5~8%, 길이는 본 동작의 20~25%(최대 4f). 롱폼에서는 히어로 요소에만.
- **팔로스루 = 부품의 시간차**: 본체 도착 뒤 부속이 늦게 정착한다. 메모 본체 0f → 그림자 정착 +2f → 테이프 +3f → 배지 +4f(현재 `SectionBar` 배지가 +4f) → 밑줄 스윕 +6f → 손글씨 주석 +8f. 한 부품의 지연은 2~4f, 전체 꼬리는 12f 이내.
- **오버랩 = 속성의 시간차**: 한 요소의 위치·불투명도·회전이 같은 프레임에 끝나지 않게. 불투명도는 길이의 40~60%에서 먼저 끝내고(현재 `RiseLine` 이 25% 지점에서 불투명도 1 — 좋은 예), 회전은 위치보다 2~3f 늦게 끝낸다.
- **2차 동작은 하나만**: 주 동작(메모가 붙는다) + 2차 동작(테이프가 눌린다). 세 번째부터는 장식.

| Carbon | 표 내용 진입을 20ms 씩 스태거하면 인지 부하가 준다. "the delay should be adjusted to ensure that total time is still within 500 ms." 순서는 가장 안정된 것(정적 콘텐츠) → 가장 중요한 것(주요 행동·결과)으로 — https://carbondesignsystem.com/elements/motion/choreography/ | [확인] |

규칙 [제안]
- UI 의 20ms 는 30fps 한 프레임(33ms)보다 짧다. 영상은 프레임 단위라 **글자 1f · 단어 2f · 줄 3f · 블록 4~5f** 가 하한(현재 `STAGGER` 그대로).
- **상한이 없다는 것이 문제**: 장식적 스태거(말과 무관한 것)의 총 길이는 **15f(500ms)** 이내. `stagger = min(토큰, floor(15 / (n−1)))`. 8개 이상이면 둘씩 묶는다.
- **말에 맞춘 순차 등장(목록·단계)은 스태거가 아니다.** 단어 시각을 따르고 상한을 적용하지 않는다(시간 근접 원칙, §2-1).
- 방향은 한 화면에 하나(M1 "single direction"). 위계 순: 라벨 → 헤드라인 → 본문 → 주석. Carbon 의 "안정된 것 먼저, 중요한 것 마지막"을 따르면 **강조 밑줄·숫자가 마지막**에 온다.
- 같은 프레임에 '시작'하는 독립 요소는 최대 2개. 카드 DSL 의 "0.15초 이상 간격" 규칙은 유지.

- 한 낱말 키워드(≤ 6자)도 최소 1.2초 정지(Netflix 최소 5/6초 + 도착 후 초점 시간).
- 읽는 중에는 그 글자를 움직이지 않는다. 푸시인·드리프트는 배경과 사진에만.

규칙 [제안]
- **모션 블러는 기본 끔.** 글자에는 절대 금지(읽기 예산을 깎는다). 채널이 휩·줌 전환을 금지하므로 쓸 자리가 거의 없다.
- **스텝은 '손으로 만든 것'에만**: 종이 메모·테이프·찢어진 액자·손글씨·분필 선. 자막, 화자 영상, 카메라 글라이드, 잉크/시그널 표면의 정밀한 타이포에는 쓰지 않는다. 한 화면에서 스텝 요소와 매끈한 요소가 섞이는 것이 오히려 '붙인 물건 vs 화면'의 층을 만든다.
- 30fps 설계 기준: 2프레임 유지(15fps)가 on twos 에 해당, 3프레임 유지(10fps)가 on threes. **이동 모션은 2프레임 유지, 보일(질감·미세 흔들림)은 4프레임 유지(7.5fps)**. PremiumBeat 의 4~12fps 범위 안.
- 스텝은 8~14f 짜리 짧은 안착에만. 20f 넘는 느린 이동을 스텝하면 '버벅임'으로 보인다(스텝하려면 푸시인은 빼고 정지 + 보일).
- 보일 진폭: 회전 ±0.3~0.5°, 위치 ±0.6~1px, 찢긴 가장자리 시드 2~3개 순환. **글자 래스터 자체는 흔들지 않는다**(종이만 흔들고 글자는 종이에 붙어 같이 움직인다).
- 출력이 24/25fps 일 때도 유지 프레임 수는 같게 두면 12~12.5fps 가 되어 고전적 on twos 와 일치한다.

규칙 [제안]
- **한 샷 = 히어로 무브 하나.** 한 그래픽에서 눈에 띄는 움직임(거리 > 5% 또는 스케일 변화 > 5%)은 하나, 나머지는 지원 동작(≤ 2%·페이드·밑줄). 숫자 카운트업이 히어로면 판의 진입은 조용히, 판의 진입이 히어로면 내용은 줄 리빌만.
- **카메라와 오브젝트를 동시에 움직이지 않는다.** 강조 글라이드(카메라)가 도는 0.7초 동안 새 그래픽 진입을 시작하지 않는다(앞뒤 6f 간격).
- **방향 연속성**: 한 챕터 안에서 얼굴 옆 요소는 늘 '바깥 → 안'(현재 규칙), 연속한 두 그래픽이 같은 축이면 같은 방향. 방향을 바꾸는 것은 챕터 전환에서만.
- **아이 트레이스**: 컷 직전 시선 위치(보통 화자의 눈 또는 직전 그래픽의 강조어)에서 새 그래픽의 첫 초점까지의 거리가 프레임 폭의 1/3 을 넘으면, 새 요소가 **그쪽에서 출발해** 시선을 끌고 간다(진입 방향 = 이전 초점 쪽).
- **패럴랙스 3층**: 배경(종이·사진) 0.3× · 중간(메모·액자) 0.6× · 전경(테이프·글자) 1.0×. 사진 푸시인 1.00 → 1.05 를 쓸 때 사진 위 글자는 1.00 고정(§1-7).
- 공동 운명을 묶음에 쓴다: 한 묶음(배지 + 헤드라인 + 본문)은 같은 방향·같은 이징, 다른 묶음은 3f 이상 어긋나게.

Do / Don't
- Do: 진입·이동·퇴장에 서로 다른 곡선. 거리로 길이를 고른다. 부품 2~4f 시간차. 도착 뒤 `글자 수 ÷ 7` 초 정지.

규칙 [제안]
- **그래픽 글자 = 말의 요약·구조(신호)**, 말의 전사 = 자막 레일. 그래픽이 말을 문장째 옮기면 중복 원칙에 걸린다. 현재의 `dedupe_captions`(그래픽과 같은 말이면 자막 숨김)는 이 원칙과 일치하므로 유지·강화한다: 겹침 판정을 '같은 문자열'에서 '같은 핵심어(어간 일치) 2개 이상'으로.
- 그래픽 제목은 12자 안쪽의 **주장**(현재 `motion.md` 규칙), 본문은 역할 라벨. 문장을 넣어야 하면 인용 카드로 분류하고 그동안 자막을 끈다.
- 글과 그림은 붙여 놓는다(공간 근접): 도식 라벨은 범례가 아니라 **도형 옆 직접 표기**, 사진 설명은 사진에서 24px 이내.
- 글자는 그 말을 하는 순간에 도착한다(시간 근접): 현재의 "0.2초 전 도착" 유지. 발화보다 1초 이상 먼저 나온 글자는 스포일러, 0.5초 이상 늦으면 뒷북.

- 그래픽 글자도 자막과 같은 줄바꿈 규칙을 쓴다: **어절 단위**, 조사·어미만 남는 줄 금지, 숫자 + 단위 붙임, 마지막 줄이 2자 이하인 '고아' 금지, 2줄이면 아랫줄이 길게. 줄바꿈은 에이전트가 `\n` 으로 직접 넣고 렌더러는 `word-break: keep-all` 로 방어한다.
- **한글 속 영문·숫자**: 같은 서체를 쓸 때는 그대로, 다른 서체(Playfair·Anton)로 바꿔 끼울 때는 크기 +5~8%(현재 `<Numerals>` 가 1.08em — 범위 안), 베이스라인은 서체 쌍마다 눈으로 맞춰 토큰화한다(`NUMERAL_SHIFT`). Anton 은 x-높이가 커서 오히려 한글보다 커 보일 수 있으니 한글 캡 높이에 맞춘다.
- **명조·고딕 혼용**: 한 화면에서 역할이 다를 때만(문장 = 명조, 라벨·데이터 = 고딕). 같은 위계에서 섞지 않는다. 한글에는 진짜 이탤릭이 없으므로 명조 기울임은 영문·숫자에만 쓰고, 한글 강조는 굵기·크기·색으로(Netflix KR 도 이탤릭 금지).
- **굵기 대비는 두 단계 이상 건너뛴다**: 400 ↔ 700, 500 ↔ 800. 600 ↔ 700 같은 한 단계 차이는 위계로 읽히지 않는다. 한 화면 굵기 3종 이내(KRDS 는 4종 이내).
- 자간: 큰 글자는 음수, 작은 글자는 0~양수(기존 리서치 A3-3 표). 추가 규칙: Black Han Sans·Jua 처럼 굵기가 하나인 디스플레이 서체는 −0.01em 이상 좁히지 않는다(획이 붙는다 — 현재 코드가 −0.01em). 손글씨(Nanum Pen Script)는 자간 0, 크기를 고딕의 1.25배로(획이 가늘어 작아 보인다).
- 줄 길이: 자막 16~18자(Netflix KR 16자), 그래픽 본문 22자 이내(카드 DSL 현행), 헤드라인 12자 이내 × 2줄.

규칙 [제안]
- **12열 그리드**를 토큰으로: 1920 폭, 바깥 여백 96, 거터 24 → 열 폭 122. 16:9 의 모든 그래픽 왼쪽 변은 열선에 붙는다. 현재 무대(화자 36% + 작업대 64%)는 12열에서 4.3 : 7.7 이므로 **4 : 8 또는 5 : 7** 로 스냅하고, 한 영상에서 두 비율을 챕터 단위로 번갈아 쓴다(§6).
- 9:16(1080×1920): 6열, 바깥 여백 64, 거터 20. 세로는 8px 기준선.
- **타입 스케일은 비율로**: 현재 `TYPE`(18·22·34·44·64·96·150·260)은 단계비가 1.22~1.73 으로 들쑥날쑥하다. 1.5(완전 5도) 스케일에 맞추면 20 · 30 · 44 · 66 · 100 · 150 · 225. 한 화면에는 **세 단계만**, 인접 단계가 아니라 **한 칸 건너뛴** 조합(예: 30 / 66 / 150)을 쓴다. 가장 큰 글자 ÷ 둘째 ≥ 1.6, 둘째 ÷ 셋째 ≥ 1.4.
- 위계 신호는 단계마다 **둘 이상**을 바꾼다(크기 + 굵기, 크기 + 서체, 크기 + 색). 크기만 조금 다른 같은 굵기의 스택이 '균일한 무게'의 정체다.
- **정렬**: 기본은 왼쪽 정렬. 가운데 정렬은 (a) 한 낱말 슬램 (b) 챕터 번호 (c) 숏폼 자막에만. 한 화면의 왼쪽 정렬선은 2개 이하.
- **비대칭**: 그래픽의 무게중심을 3분할 교점에 둔다. 화자가 한쪽 1/3 에 있으면 그래픽은 반대쪽 2/3 의 안쪽 교점 근처, 화자의 시선 방향 앞(리드 룸)에. 화자 눈높이는 위 1/3 선(y ≈ 360) 근처, 얼굴 옆 메모의 헤드라인 기준선을 눈높이 ± 60px 에 맞추면 시선 이동이 수평이 된다.
- 근접으로 묶는다: 한 묶음 안 간격 ≤ 0.5em~1em, 묶음 사이 ≥ 2em. 간격이 전부 같으면 묶음이 사라진다.

| 광원 | 요소마다 그림자 방향이 다름, 전부 수직 아래 | 화면 전체가 **광원 하나**(위 왼쪽, Gilliam 식 탑 라이트) | 그림자 벡터 비 dx : dy = 2 : 3 고정 |
| 그림자 색 | 순검정 rgba(0,0,0,…) | 바닥색을 어둡게 한 색(따뜻한 잉크) + multiply | `rgba(38,33,30,α)` |
| 그림자 층 | 큰 블러 하나 | **접촉 그림자**(선명·작음) + **주변 그림자**(부드럽고 큼) 두 겹 | 접촉 1~2px 블러 0~2 / 주변은 높이별 표 |
| 높이 = 그림자 | 모든 요소 같은 그림자 | 높이 3단: 붙음(1) · 살짝 뜸(2) · 들림(3). 높을수록 오프셋·블러 크고 α 낮게 | 아래 토큰 |
| 그림자 움직임 | 요소만 움직임 | 들어올 때 높이 3 → 1(오프셋·블러가 줄며 선명해짐), 스케일 1.03 → 1 과 동기 | 9~11f |
| 가장자리 | 한 변만 찢김, 나머지 완전 직선·직각 | 네 변 모두 미세 불규칙(가위 자국 0.6~1.2px), 찢긴 변만 진폭 큼, 모서리 1~2px 무작위 깎임 | 가위 변 amp 0.8·step 40~70, 찢긴 변 amp 6 |
| 찢긴 단면 | 종이색 그대로 | 단면에 밝은 섬유 띠(종이 속살) 2~4px | 찢긴 변 안쪽에 +8% 밝은 띠 |
| 회전 | 0° 또는 전부 같은 각 | 요소마다 시드로 다른 작은 각, **0° 금지** | 글 있는 메모 ±0.6~1.8°, 사진 ±1~3°, 테이프 ±3~8°, 스티커·배지 ±2~4° |
| 정렬 | 완벽한 중앙·대칭 | 그리드에는 붙되 2~6px 어긋남 | 위치 지터 ±4px |
| 질감 스케일 | 요소를 축소하면 질감도 같이 축소 | 질감은 **화면 픽셀 기준 고정**(같은 종이면 입자 크기가 같다) | 타일 256px 고정, 요소 scale 과 분리 |
| 질감의 일관성 | 종이마다 다른 노이즈, 사진은 깨끗 | 종이·사진·컷아웃이 **같은 입자**를 공유(현 디자인 문서 5-1 의 관찰과 일치) | 전 요소에 같은 하프톤/그레인 한 겹 |
| 하프톤 | 요소 전체에 균일한 점 | 사진·어두운 면에만, 각도 15~45°, 점 크기가 명암을 따라감 | 점 간격 5~6px, 각도 15° |
| 오정합 | 색면과 선이 완벽히 일치 | 시그널 색면이 잉크 선에서 1~3px 어긋남(한 방향) | (+2px, +1px) |
| 테이프 | 불투명 사각형 | 반투명(0.85~0.9), 끝이 톱니 또는 비스듬, 아래 종이가 비침, 길이·각 다양 | 현행 + 끝 톱니, 길이 80~160 |
| 겹침 | 요소가 서로 안 닿음 | 2~3장이 실제로 겹치고 위 장이 아래 장에 그림자를 떨굼 | 겹침 8~20% |
| 시간 | 60fps 로 매끈 | 2프레임 스텝 + 4프레임 보일(§1-9) | — |
| 글자 | 종이 위 글자가 화면에 떠 있음 | 글자가 종이와 **같이** 회전·스텝하고 multiply 로 섬유가 비침 | 잉크 α 0.92 + multiply |
| 사진 | 원색 스톡 사진 | 채도 −20~30%, 따뜻한 톤, 같은 입자, 흰 테두리 폭이 변마다 조금 다름 | 테두리 10~14px |

### 4-3. 종이가 '붙는' 모션 [제안]
- 종이는 가볍고 뻣뻣하다: 스쿼시 없음, 오버슛은 **회전**으로(도착 각 θ 를 1~1.5° 지나쳤다 돌아옴), 그림자는 높이 3 → 1.
- 순서: (0f) 종이가 위·바깥에서 1.03 배·높이 3 으로 나타남 → (9~11f, 2프레임 스텝) 내려앉으며 회전 정착·그림자 수축 → (+2f) 접촉 그림자 → (+3f) 테이프가 2~3f 에 눌림(scaleY 1.15 → 1) → (+5f) 글자 줄 리빌.
- 떼는 모션: 테이프 쪽을 축으로 +2° 돌며 높이 1 → 2, 8f, 불투명도는 마지막 4f 에만.
- 종이끼리는 **미끄러지지 않는다**(미는 모션은 '판·보드' 같은 단단한 표면에만). 메모는 놓고, 붙이고, 떼고, 넘긴다.

| A 강조 장치 | A1 밑줄 스윕 · A2 반전 상자 · A3 손글씨 동그라미/화살표(그리기) · A4 숫자 카운트 · A5 사진 어둡게 + 슬램 | 화면당 1개 |
| M 재질 | M1 크림 메모 · M2 잉크 판 · M3 사진 위 직접 · M4 모눈/괘선 종이 | 챕터의 '키' 재질 1개 + 보조 1개 |
| T 주역 서체 | 역할표(heavy·round·serif·display)에서 내용이 정함 | 변수가 아니라 내용의 함수 |
| R 회전·지터 | 시드(그래픽 id)로 범위 안에서 | 재실행해도 같게 |

제약(변주가 혼돈이 되지 않게)
1. **챕터 키**: 챕터마다 (M 키 재질, E 주 진입) 한 쌍을 정하고 그 챕터 그래픽의 60% 이상이 따른다. 챕터가 바뀌면 키가 바뀐다 → 챕터 안은 일관, 챕터 사이는 변화.
2. **연속 금지**: 직전 그래픽과 (L, E) 가 둘 다 같으면 안 된다. 같은 L 은 최대 2회 연속. 같은 A 는 최대 2회 연속.
3. **예산**: 12분 ≈ 그래픽 50~70개(8~15초에 하나). 한 (L, E, A) 조합은 영상 전체에서 최대 6회. 가장 많이 쓴 조합의 점유율 ≤ 20%.
4. **히어로**: 챕터당 1개만 규칙을 깨도 된다(전면 블리드 + 가장 긴 모션 + 사운드). 영상 전체 '크라운'은 1개.
5. **반복은 의도적으로**: 같은 종류의 정보(챕터 카드, 소제목 바, 정리 보드, 출처)는 **항상 같은 모양**. 변주는 '개념 그래픽'에만 준다. 내비게이션 부품이 변하면 길을 잃는다.
6. **조용한 구간**: 변주 축을 한 번에 둘 이상 바꾸지 않는다(구도가 바뀌면 진입은 유지).
7. 선택은 결정적: `seeded(hash(graphic.id))` 로 후보 중 고르고, 제약 위반이면 다음 후보. 결과를 `plan.long.variety` 에 통계로 남긴다(조합별 횟수, 최대 연속).

  exit: Easing.bezier(0.3, 0, 0.8, 0.15),        // M3 emphasized-accelerate

export const durFor = (distPct: number, areaPct = 0): number => {
  const d = distPct < 5 ? 8 : distPct < 15 ? 11 : distPct < 35 ? 15 : distPct < 60 ? 19 : 23;
  return Math.min(26, d + (areaPct > 50 ? 3 : areaPct > 25 ? 2 : 0));
};

/** 장식적 스태거 상한 15f(말에 맞춘 순차 등장에는 쓰지 않는다) */
export const staggerFor = (n: number, base: number, cap = 15) =>
  n <= 1 ? 0 : Math.max(1, Math.min(base, Math.floor(cap / (n - 1))));

export const HOLD = {cps: 7, minSec: 1.2} as const;

/** 손맛 스텝: hold 프레임마다만 갱신(2 = on twos 상당, 4 = 보일) */
export const stepFrame = (frame: number, hold = 2) => Math.floor(frame / hold) * hold;
export const BOIL = {hold: 4, rotate: 0.4, shift: 0.8, seeds: 3} as const; // ±도, ±px

/** 부품 시간차(팔로스루): 본체 도착 기준 프레임 */
export const FOLLOW = {shadow: 2, tape: 3, badge: 4, underline: 6, note: 8, maxTail: 12} as const;

export const SPRING = {
  ...SPRING_CURRENT,                                   // gentle ζ1.0 / stiff ζ0.75(≈2.8%) / slow ζ1.41
  paper: {stiffness: 260, damping: 22, mass: 1},       // ζ≈0.68, 오버슛 ≈5% — 메모 회전 안착
  snap:  {stiffness: 500, damping: 32, mass: 1},       // ζ≈0.72, ≈4% — 칩·배지·테이프
  heavy: {stiffness: 120, damping: 22, mass: 1},       // ζ≈1.0, 0% — 보드·전면
  float: {stiffness: 40,  damping: 18, mass: 1},       // ζ≈1.42 — 배경·시차
} as const;

export const EXIT_RATIO = 0.75; // 허용 0.6~0.87

### 8-3. 적용 순서 제안
1. P0-1(버그) → P0-2·P0-3(재질, 눈에 가장 먼저 보이는 차이) → 샘플 스틸 12장을 렌더해 운영자에게 전/후 확인.
2. P0-4·P0-5·P0-7(모션 가족 + 변주) → 2분짜리 샘플에서 조합 통계 확인.
3. P0-6·P1-12(루브릭 + 기계 검사) → 기존 결과물에 돌려 불합격률을 본다. 처음에는 med 를 경고로만 두고 임계값을 조정.
4. 나머지 P1 → P2.

모든 [제안] 수치는 **렌더 스틸·시퀀스로 눈 검증 후 확정**한다. 특히 회전 범위, 그림자 α, 스텝 유지 프레임, 7자/초는 운영자(디자이너)의 눈이 최종 기준이다.

## 9. 확인하지 못한 것 · 한계

- **웹 검색 한도 소진**으로 뒤쪽 주제(School of Motion 의 팔로스루·오버랩 글, Jake Bartlett·Ben Marriott 의 구체 수치, 시니어 모션 디자이너의 '템플릿 룩' 비평)는 추가 검색을 못 했다. §1-4 의 시간차 수치와 §5-2 의 영상 쪽 반대 규칙은 조사자 제안이다.
- JS 렌더·차단으로 본문을 못 읽은 것: Material 3 공식 사이트(대신 Material Components GitHub 문서로 토큰 확인), Apple HIG Motion(검색 스니펫 + 구판 미러), BBC 자막 가이드 원문(Clevercast 요약으로 대체), UX in Motion Manifesto(Medium 403), Mayer 2017(Wiley 403), Brame 2016, Lupton *Thinking with Type*, Nature HSSC 키네틱 타이포 리뷰, EBU R95 PDF(텍스트 추출 실패), Adobe 한글 도움말.
- 책은 원문을 보지 못했다: *The Illusion of Life*, *Grid Systems in Graphic Design*, Bringhurst, Tufte, Murch, Gerstner, Wong — 전부 위키·2차 요약을 거쳤다.
- 한국어 **자막** 읽기 속도의 시선 추적 연구는 확인하지 못했다. 7자/초는 일반 묵독 연구 2건에서 조사자가 환산한 값이다(낱말당 2.9자 가정).
- Vox 12fps, Kurzgesagt 제작 수치, NYT Op-Docs 스타일은 검증하지 못했다.
- 유튜브 쇼츠 세이프존 공식 수치, 휴대폰 플레이어의 가림 영역은 확인하지 못했다.
- easeOutBack 의 오버슛·스프링 감쇠비·대비 수치는 조사자가 공식으로 직접 계산했다(검산 권장: `measureSpring`, 대비 계산기).
- `check.mjs` 글꼴 허용 목록 문제(D8)는 저장소(HEAD `ce2f323`)와 설치본 두 곳의 코드를 읽어 확정했다. 실행 재현(해당 글꼴을 쓴 카드를 검사에 넣기)은 하지 않았다.
- WebFetch 는 작은 모델이 페이지를 요약해 돌려주므로, [확인] 표시의 인용문도 프롬프트·문서에 옮기기 전에 원문과 대조하는 것이 안전하다.
