- 조사일: 2026-09-30
- 계기: 릴스 [instagram.com/reel/Dd5_-C5IJvH](https://www.instagram.com/reel/Dd5_-C5IJvH/) (hongik.man) — "이제 영상 편집 직접 하지 마세요. 원본 MP4 하나로 컷 편집·자막·모션 디자인·효과음까지". 구성은 **Claude Opus 5.5(영상 구성·디자인 생성) + HyperFrames(실제 영상으로 완성)**.

## 0. 요약

1. HyperFrames 는 HeyGen 이 공개한 **HTML → MP4 렌더러**(Apache-2.0)다. `data-start`/`data-duration` 을 단 HTML 조각을 헤드리스 Chrome 이 프레임마다 찍고 FFmpeg 로 묶는다. 우리의 Remotion 과 **같은 원리**(브라우저 스크린샷)이고, 다른 점은 "React 대신 순수 HTML + GSAP" 과 **에이전트용 스킬 21종·린트(`check`)·클라우드 렌더**다. [원문]
2. 릴스가 말한 "컷 편집"은 HyperFrames 의 기능이 아니다. 토킹헤드 스킬(`talking-head-recut`)은 **"컷은 자동이 아니다"** 라고 명시하며, 원본을 자르지 않고 그 위에 카드(타이틀·로어서드·인용)를 얹는다. 자르려면 에이전트가 트랜스크립트를 읽고 FFmpeg 를 직접 돌려야 한다. [원문]
3. 그러니 그 조합은 "**AI 가 HTML 을 잘 쓰니까, 영상을 HTML 로 만들자**" 에 강하고, **말을 듣고 자르는 일**(되풀이·추임새·NG·싱크·테이크 선택·검증)에는 우리가 이미 훨씬 앞서 있다. 다시점·색보정·마스터링·숏폼 파생·검토 시트도 그쪽에 없다.
4. 반대로 우리가 뒤지는 것은 넷이다. **(a) 표현의 상한** — 템플릿 17종 + 제한된 모션 DSL 이라 안전하지만 비슷해 보인다. **(b) 결정론적 린트** — 글 넘침·대비(WCAG)·폰트 로드 실패를 렌더 전에 못 잡는다. **(c) 렌더 속도** — 이 컨테이너(4 vCPU·GPU 없음)에서 70초 롱폼 렌더에 22분(1.6 fps). **(d) 사람 매트** — 글자를 사람 뒤로 넣는 `embed` 자막, 배경 제거 같은 기법이 없다. [실측·원문]
5. 그러나 가장 큰 난항은 기능이 아니라 **검증 없이 만들고 있다는 사실**이다. 지금까지 모든 확인은 합성 음성 + 스톡 인물 클립 + 가짜 Claude 로 했다. 첫 업로드본의 문제(싱크·실수·색)는 모두 실전에서 드러났다. 실제 촬영본 2–3편과 운영자가 직접 편집한 결과가 있어야 "얼마나 좋은지"를 숫자로 잴 수 있다.
6. 두 번째는 **취향이 되돌아오지 않는다**는 것이다. 운영자가 결과를 보고 고친 것을 프로그램이 배우는 경로가 없다. 리포트는 나가지만 들어오는 것은 없다.
7. 해법은 "HyperFrames 로 갈아타기"가 아니다. 컷의 프레임 정확도(CFR 프록시 + `OffthreadVideo`)는 우리 쪽이 확실하고, 그쪽은 브라우저 `<video>` 탐색이라 키프레임 재인코딩(`-g 30`)으로 버틴다. 대신 **그쪽의 좋은 것을 우리 안에 들인다**: 자유 HTML 장면 슬롯 + 우리 린트 + 비전 검수, 카드 레지스트리 호환, `check` 급 정적 검사.
8. 렌더는 세 층으로 푼다. 즉시(벤치마크·설정), 다음(검수 후 **바뀐 구간만** 다시 렌더 — Remotion 4.0.502+ 의 다중 frameRange), 구조(**얼굴 층은 Chrome 을 거치지 않는 두 층 렌더**).
9. 취향은 세 경로로 되돌린다. 검토 시트에서 👍/👎, Premiere XML **왕복 diff**(운영자가 고친 컷·지운 그래픽을 읽음), 채널 메모리(`user/channel.md`).
10. 순서: ① 골든 세트와 측정 → ② 린트·폰트 단언·부분 재렌더 → ③ 자유 장면 슬롯 + 사람 매트 → ④ 두 층 렌더 → ⑤ 취향 루프. ①은 운영자 자료가 필요하다(저장소 밖, 사진처럼).

## 1. 그 릴스의 조합은 정확히 무엇인가

### 1-A. HyperFrames 사실 확인 [원문]

| 항목 | 내용 |
|---|---|
| 제작 | HeyGen (`github.com/heygen-com/hyperframes`), Apache-2.0, 렌더당 요금 없음. 2026-09 기준 0.8.27, 6월 이후 152회 릴리스 [글] |
| 원리 | HTML/CSS + **탐색 가능한(seekable) 애니메이션**(GSAP·CSS keyframes·Lottie·Three.js·Anime.js·WAAPI)을 헤드리스 Chrome 이 프레임마다 캡처 → FFmpeg 인코딩. "같은 입력, 같은 프레임, 같은 출력" |
| 작성 모델 | 루트 `<div data-composition-id data-width data-height data-duration>`; 시간은 `class="clip"` + `data-start`/`data-duration`(CSS·JS 시간이 아니라 이 속성만 읽음); 컴포지션마다 `gsap.timeline({paused:true})` 하나를 `window.__timelines[id]` 에 등록 |
| 금지 | `Math.random()`·시계·네트워크, `repeat:-1`, `.clip` 에 display/visibility 트윈, CSS transform 과 GSAP 같은 속성 충돌, 원격 폰트(로컬 `@font-face` 만) |
| CLI | `init` · `preview` · `snapshot --at` · `timeline` · **`check`**(린트 + 런타임 오류 + 레이아웃 넘침 + WCAG 대비를 한 번에) · `render --fps --concurrency`(투명 WebM 가능) · `cloud render`(HeyGen 호스팅) · `lambda deploy/render` · `catalog`/`add`(레지스트리 블록) · `transcribe`(로컬 Whisper; 자막 스킬은 `uvx whisperx`) · `caption` · `remove-background` |
| 스킬 21종 | 라우터 `hyperframes` · 워크플로 `talking-head-recut`·`embedded-captions`·`faceless-explainer`·`product-launch-video`·`pr-to-video`·`motion-graphics`·`music-to-video`·`slideshow`·`general-video`·`remotion-to-hyperframes` · 도메인 `hyperframes-core`·`-animation`·`-keyframes`·`-creative`·`-audio`·`-cli`·`-registry`·`-studio`·`media-use`·`figma` |
| 요구 | Node 22+, FFmpeg. 개발용 테스트 기준선 240 MB(LFS) |

`hyperframe.ai`(비즈니스 영상 플랫폼)는 다른 제품이다.

### 1-B. 토킹헤드 영상에 실제로 하는 일 [원문 `talking-head-recut`, `embedded-captions`]

- **트랜스크립트**: `npx hyperframes transcribe` → 단어별 `{text,start,end}`. 에이전트가 문장 단위로 묶는다.
- **컷**: "Cuts are **not automatic**". 무음·추임새로 자르지 않는다. 카드 개수를 공식(`max(5, 길이 ÷ (기본 속도 × 밀도 배수))`)으로 정하고 카드를 얹는다. 원본은 `-g 30 -keyint_min 30` 으로 재인코딩해 **무음 처리한 `<video>`** 로 깔고, 소리는 별도 `<audio>` 트랙으로 끊김 없이 튼다. 즉 **말을 자르는 편집은 스킬 밖**이다. 릴스의 "컷 편집"은 에이전트가 FFmpeg 로 손수 했거나(`media-use`), 카드 전환을 컷이라 부른 것으로 본다. [해석]
- **자막**(`embedded-captions`): 레일(하단 자막) · **임베드**(핵심어를 **사람 뒤에** 매트로 합성, 생각 단위당 ≤1, 0.6초 간격) · 드롭(추임새는 안 보임). 2–5 단어 절 단위, `group.in ≤ 첫 단어 시작`, ≥0.5초, 시간·화면 겹침 금지, `check-timing --strict`(80 ms), `safe-zones.json`(사람 위치·밝기), 넘침·대비 검사.
- **소리**(`hyperframes-audio`): 보이스 자리 비우기(carving)·EQ·컴프레서·오토메이션.
- **한계**(작성자 글 [글]): CPU 렌더가 60초 영상에 수 분, 빈 프레임·폰트 누락 사례, "시네마틱·실사 푸티지에는 맞지 않음", HTML 미리보기와 최종 검토는 사람이.

## 2. 지금 이 프로그램이 겪는 난항 (근거와 함께)

### 난항 1 — 실전 품질을 잰 적이 없다 (가장 크다)

- 지금까지의 검증: 합성 음성(gTTS) + 스톡 인물 클립(좌우 반전으로 B캠 흉내) + 가짜 Claude CLI. 실제 운영자 촬영본·실제 Claude 기획·실제 Pixabay 소재·Windows 실행은 **모두 미확인**(PR 검증 항목에 적어 둔 그대로).
- 첫 업로드본의 문제(싱크, 남은 실수, 오렌지 얼굴)는 전부 **실전에서** 나왔고, 색보정도 운영자 사진 3장을 받고서야 방향을 잡았다.
- 이 환경의 제약: YouTube·Instagram 영상은 프록시가 막아 **참고 영상을 직접 볼 수 없다**(캡션·썸네일·스토리보드만). Windows 실행도 못 한다.

### 난항 2 — 렌더가 느리다 [실측]

- 이 컨테이너(4 vCPU, GPU 없음, `swangle`): 롱폼 2,106 프레임(70초·1080p)에 **22분 30초 ≈ 1.6 fps**, 숏폼 726 프레임 3분 19초 ≈ 3.6 fps. 전체 E2E 31분 중 렌더가 27분. `eta_history` 의 렌더 계수 4.7(기본 모델의 4.7배).
- 원인 구조: 화면의 80–90% 가 얼굴 영상인데 그 프레임까지 **전부 Chrome 이 찍는다**. 그래픽이 없는 구간도 같은 비용.
- 운영자 PC(Windows, GPU 유무 미확인)에서는 `angle` + NVENC 로 빨라지겠지만, 한 편 만드는 데 30분–1시간이면 "폰에서 보내고 자동 업로드" 흐름에서도 병목이다.

### 난항 3 — 취향이 되돌아오지 않는다

- 나가는 것: 편집 리포트·검토 시트·XML. 들어오는 것: 없음. 운영자가 결과에서 무엇을 지우고 무엇을 바꿨는지 프로그램은 모른다.
- 편집 문법의 수치(`PARAMS`)·프롬프트 톤은 리서치와 채팅 피드백으로 고쳤다. 피드백 → 코드 수정 → 재배포의 주기가 길고, 나(개발자)가 중간에 끼어야 한다.

### 난항 4 — 표현의 상한이 낮다

- 템플릿 17종, 모션 DSL 요소 10종(`text rect circle line arrow path dots counter bar image`) · 36개 상한 · 색 7개 · 진입 10종. 안전하고 깨지지 않지만, **에이전트가 새로운 것을 만들 수 없다**. 그래픽이 비슷해 보이는 이유.
- HyperFrames 는 그 반대(무엇이든 HTML 로) — 대신 깨질 위험을 `check` 와 사람 검토로 막는다. 우리는 그 중간(자유 장면 + 자동 린트 + 비전 검수)이 비어 있다. 이전 리서치(`클로드_영상자동화_사례.md` §6-10)에서 "맞춤 장면 슬롯"으로 제안했지만 아직 안 만들었다.

### 난항 5 — 렌더 전 정적 검사가 없다

- 글이 상자를 넘치면(말줄임을 넣었지만 모든 템플릿을 보장하진 못함) 스틸 검수에서 운 좋게 잡히거나 결과물에 남는다.
- **폰트 로드 단언이 없다**(`fonts.check` 0건): Pretendard 로드가 실패하면 조용히 맑은 고딕으로 렌더된다.
- 대비(WCAG)·자막 겹침·안전 영역 검사가 없다. HyperFrames 의 `check` 가 한 번에 하는 일이다.

### 난항 6 — 한국어 ASR·단어 경계의 정확도 상한

- 실수 정리·자막·컷 전부 faster-whisper large-v3 의 **단어 타임스탬프**에 걸려 있다. Whisper 단어 시각은 50–120 ms 오차가 보고되고(이전 리서치 §0-6), 한국어 조사·어미 붙임은 더 흔들린다. VAD 끝 연장과 편집 오류 검사로 막고 있지만 **정확도를 잰 데이터가 없다**.
- 대안 정렬기(WhisperX 강제 정렬 — HyperFrames 자막 스킬이 쓰는 것)는 시험하지 않았다.

### 난항 7 — 색보정은 규칙이고, 피부 판정이 약한 고리다

- 3단계(교정→레시피→피부 보호)는 방향이 맞지만, 피부 마스크가 **CIELAB 색상 범위**(12–100°)라 노란 벽·나무 가구·주황 조명이 피부로 잡힐 수 있다. 얼굴 박스(YuNet) 안 중심부만 쓰는 보정이 있으나 얼굴 밖 피부(손·목)는 못 지킨다.
- 좋아하는 장면(`user/reference_frames/`)으로 목표를 조금 옮기는 것 외에 학습이 없다.

### 난항 8 — 소재의 빈틈

- 추상 개념(게슈탈트·위계·여백)은 스톡이 없다. 규칙("틀린 B-roll 보다 없는 게 낫다")과 모션 장면으로 대신하지만, 모션 장면은 난항 4 의 상한에 걸린다.
- Pixabay CDN 차단·키 오류 등 네트워크 실패는 견고해졌지만, **소재 자체의 질**(한국어 디자인 교육 맥락에 맞는 그림)은 검색으로 해결이 안 된다.

### 난항 9 — 개발 환경과 실행 환경의 거리

- Linux 에서 만들고 Windows 에서 돈다. 관리자 창 끌어다 놓기(64비트 핸들 수정 포함), CUDA/cuDNN DLL, 콘솔 숨김, 경로, 백신 HTTPS 검사(`truststore`) — 전부 **실행해 본 적 없는 코드**다.
- 의존성 무게: Python + PySide6 + faster-whisper(CTranslate2·CUDA) + Node 22 + Remotion 4.0.530 + Chrome + FFmpeg 7. 처음 설치가 실패할 지점이 많다.

### 난항 10 — AI 단계의 시간·비용·의존

- 기획(감독 + 전문가 병렬) 150초+, 검수 180초(ETA 모델). Claude Code 로그인 상태에 의존하고, 한도에 걸리면 규칙 기반으로 떨어진다(품질 급락).
- 가짜 CLI 로만 검증했으므로 **실제 Opus 5.5 가 우리 스키마에 얼마나 잘 맞는 계획을 내는지** 모른다(스키마 위반·과밀·앵커 오류의 실제 빈도).

### 3-5. 렌더 전 정적 검사 — 우리식 `check` (가져올 것 2)

- **폰트 단언**: 컴포지션 시작 시 쓰는 웨이트마다 `document.fonts.check()`; 실패하면 렌더를 멈추고 로그(조용한 폴백 금지). `measureText` 에 `validateFontIsLoaded`.
- **계획 린트(LLM 없이)**: 앵커 단어가 표시 구간 안에서 발화되는지, 자막 창이 단어를 감싸는지(`in ≤ 첫 단어`, `out ≥ 마지막 단어`), 최소 0.5초, 겹침 없음, CPS ≤ 12–14, 그래픽 밀도·연속 3개 금지, 전환은 챕터 경계만(이전 리서치 §6-4 그대로).
- **DOM 검사**: 스틸 검수 렌더 때 같은 Chrome 세션에서 `scrollWidth > clientWidth`(넘침), 텍스트/배경 대비(WCAG 4.5:1), 자막이 얼굴 박스와 겹치는지(`face.json` 기준 안전 영역 — HyperFrames `safe-zones` 에 해당)를 JSON 으로 뽑는다. 비전 검수보다 싸고 확실하다.
- **결과물 게이트**: `ffprobe` 로 v/a 길이 일치, `ebur128` 라우드니스, 최종 재전사 대 정렬 대본(이미 `verify` 가 편집 목소리에 함 — **최종 파일**에도 한 번).
- **프레임 기준선**: 템플릿마다 대표 프레임 PNG 를 저장하고 PR 마다 SSIM 비교(HyperFrames 의 240 MB 기준선을 작게).

### 3-6. 사람 매트 — 글자를 사람 뒤로 (가져올 것 3)

- 프록시에서 **사람 알파 매트** 생성: Robust Video Matting(RVM, 시간 일관성 좋음, GPU 권장) 또는 MediaPipe Selfie Segmentation(CPU 가능, 경계 거침). 결과는 `media/matte.mp4`(회색 알파) 로 저장.
- 쓰는 곳: 숏폼 첫 2.2초 큰 제목(사람 뒤), 롱폼 챕터 타이틀, 핵심어 강조 1회/생각 단위(HyperFrames `embed` 규칙 0.6초 간격 차용). 렌더러는 `<OffthreadVideo>` 두 개(원본·매트)와 `mask-image` 또는 캔버스 합성.
- 비용이 크니 **선택 기능**(GPU 있을 때 자동, 없으면 끔). 색보정도 매트가 있으면 피부 마스크 대신 **사람 마스크**를 쓸 수 있어 난항 7 이 함께 좋아진다.

### 3-11. AI 단계

- 실제 계획 로그(3-1 C)로 스키마 위반·과밀·앵커 오류 빈도를 재고, 잦은 것은 **린트 자동 보정**(3-5)으로 옮겨 재호출을 줄인다.
- 검수 라운드 1 → 2–3(3-2 부분 재렌더가 전제). 비평가는 계획 근거를 모르는 채 프레임만 본다(블라인드, 이전 리서치 §6-2).
- 규칙 기반 폴백의 품질 바닥을 올린다(템플릿·자막·효과음 규칙만으로도 "볼 만한" 수준) — 한도에 걸린 날의 결과가 곧 채널 신뢰다.

---

## 4. HyperFrames 에서 가져올 것 / 가져오지 않을 것

**가져온다**
1. 자유 HTML 장면 규약(`data-anim-*` 선언, 스크립트 없음, 로컬 폰트만) 과 카드 레지스트리 호환 — 3-4
2. `check` 의 범위(넘침·대비·런타임·폰트) 를 우리 스틸 검수 세션에 — 3-5
3. `embed` 자막(사람 뒤) 과 `safe-zones`(사람 위치 기반 자막 배치) — 3-6, 3-5
4. 자막 타이밍 규칙의 수치(`in ≤ 첫 단어`, ≥0.5초, 80 ms 검사, 절 단위 2–5 단어, 시간·공간 겹침 금지) — 우리 `build_phrase_cues` 검증에
5. 프레임 기준선 회귀 테스트 — 3-5
6. `snapshot --at`/`timeline` 같은 **에이전트용 검사 명령** 발상 — 우리 `python -m studio` 에 `plan lint`, `stills --at`, `timeline` 서브커맨드

**가져오지 않는다**
- 렌더러 교체(컷 정확도·파이프라인 손실), 브라우저 `<video>` 탐색, "컷은 사람이" 모델, 클라우드 필수 흐름.

## 5. 우선순위와 단계

| 단계 | 할 일 | 필요한 것 | 효과 |
|---|---|---|---|
| **① 측정** | 골든 세트 러너 + 지표, 실제 Claude 1회 로그 수집, Windows CI | **운영자: 촬영본 2–3편 + 직접 편집본(저장소 밖)** | 이후 모든 판단의 기준 |
| **② 안전** | 폰트 단언, 계획 린트, DOM 넘침·대비 검사, 최종 파일 게이트, 부분 재렌더 + 검수 2라운드 | — | 깨진 프레임 0, 검수 비용 ↓ |
| **③ 표현** | `HtmlScene` 자유 장면 슬롯 + 게이트, 카드 레지스트리 호환, 아이콘 세트, 사람 매트(선택) | GPU 있으면 매트 자동 | 릴스 조합의 표현력을 우리 파이프라인 안에서 |
| **④ 속도** | 두 층 렌더(얼굴 층 FFmpeg) | ② 의 게이트로 픽셀 일치 검증 | 렌더 3배 |
| **⑤ 학습** | 검토 시트 👍/👎, XML 왕복 diff, 채널 메모리, 계획 잠금 | 운영자가 한 번 고쳐 볼 것 | 회차마다 채널답게 |

①이 먼저다. 지금 상태에서 ③④를 만들면 또 합성 데이터로만 "좋아졌다"고 말하게 된다.

## 6. 구현 상태(2026-09-30, 같은 날)

§3-4 · §3-5 의 첫 단계를 바로 만들었다 — HyperFrames 를 갈아타지 않고 **그 규약을 우리 렌더러 안에 들였다**.
- 자유 HTML 카드(템플릿 `card`): 모션 디자이너가 HyperFrames talking-head 카드 규약(HTML + 스코프 CSS + `data-anim-*`, 스크립트 없음)으로
  핵심 장면을 직접 디자인 → `studio/motion/card.py` 가 정리(화이트리스트·스코프·글꼴·범위) → `renderer/vendor/hyperframes/card-anim.mjs`
  (data-anim → GSAP 일시정지 타임라인) 를 `HtmlCard.tsx` 가 `useCurrentFrame()` 으로 매 프레임 seek. 컷 정확도·파이프라인은 그대로.
- 우리식 `check`(`renderer/scripts/check.mjs`): 렌더와 같은 Chrome 에서 글꼴 로드·넘침·캔버스 이탈·최소 글자 크기·WCAG 대비·런타임 오류를
  검사 → 실패하면 카드 디자이너가 검사 결과를 받아 고치고 → 그래도 실패하면 키워드 카드로 대체.
- 폰트 단언(`useFontGuard`): Pretendard·Anton 이 로드되지 않으면 렌더를 실패시킨다(조용한 폴백 금지).
- 예시 5종(editorial · academic · swiss · board · minimal)이 검사와 렌더를 통과했고 에이전트 프롬프트에 붙는다.
- 아직: 카드 레지스트리 호환(그쪽 카탈로그 가져오기), 사람 매트, 두 층 렌더, 골든 세트.
