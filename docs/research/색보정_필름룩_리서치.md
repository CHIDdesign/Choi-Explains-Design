## 0. 한 장 요약

1. **지금 색 파이프라인은 "교정 + 룩 LUT" 까지만 있다.** 화자 영상은 33³ LUT 하나, 자료 사진·스톡은 크기만 맞추고 색은 손대지 않는다(`studio/stock/process.py`). "붙여 넣은 것 같다"의 가장 큰 원인은 이것이다 — 출처가 다른 그림이 저마다의 블랙·화이트·채도로 크림 종이 위에 올라온다.
2. **가장 값싼 큰 개선은 '하우스 트리트먼트'** 다: 모든 외부 그림의 블랙을 잉크(#26211E) 쪽, 화이트를 종이(#F5F2EA) 쪽으로 눌러 담고, 채도 중앙값을 맞추고, 같은 입자를 얹고, 가장자리를 인쇄물처럼 처리한다(8장). 전부 numpy/PIL + 기존 LUT 굽기로 된다.
3. **"AI 같다"의 색 쪽 원인 후보 셋**: ① 항상 켜진 디노이즈 + 샤픈(`cleanup_filters` — 깨끗한 영상에도 `hqdn3d` 와 `unsharp 0.35`)이 만드는 매끈하고 날 선 피부, ② L 을 고정한 채 채도만 올리는 '전자적' 채도(`enrich`), ③ 질감이 전혀 없는 평평한 디지털 면(그레인 기본 끔). 각각 적응형 정리(6장), 감산식 채도·하이라이트 탈색(4.5·4.6), 저강도 입자(4.3)로 대응한다.
4. **색 과학 구멍 둘**: `render.mjs` 가 Remotion `colorSpace` 를 지정하지 않는다(v4 기본값은 `"default"`, BT.709 는 v5 부터 기본) — 2차에서 `ffprobe` 로 확인했다: 테스트 완성본은 **풀레인지 BT.601**(`yuvj420p` · `pc` · `bt470bg`)로 나갔다. `bt709` 를 명시해야 한다. 그리고 LUT 를 8비트 `gbrp` 에서 적용한다 — 16비트/float 로 올리고 오차 확산 디더로 내려야 벽·그라데이션 밴딩이 준다(10장).
5. **시작점으로 받은 GitHub 토픽 3개는 거의 비어 있다.** `cinematic-color-grading` 2개, `film-restoration` 6개, `cinematography`(Python) 는 대부분 AI 영상 프롬프트 스킬이다. 쓸 만한 것은 연관 토픽(`film-emulation`, `color-transfer`, `lut`, `video-matting`, `shot-detection`)과 잘 알려진 저장소에서 나왔다(3장).
6. **라이선스로 걸러지는 것이 많다.** GPL-3.0: RobustVideoMatting · color-matcher · spektrafilm · OpenDRT · hald-clut. 비상업: NeuralPreset(CC BY-NC-SA) · pyiqa(PolyForm NC) · shot-type-classifier(CC BY-NC) · Depth Anything V2 Base/Large(CC BY-NC) · MatAnyone/CodeFormer(NTU S-Lab). 권리 유보: deep-analog. **안전한 축**: MediaPipe · BiRefNet · MODNet · Depth Anything V2 Small · PySceneDetect · TransNetV2 · colortrans · utility-dctls · filmlook · spectral_film_lut · OpenColorIO(모두 Apache/MIT/BSD). 알고리즘(Reinhard, MKL, 할레이션, 감산식 채도)은 직접 짧게 구현하는 편이 의존성·라이선스 모두 낫다.
7. **하지 말 것**: 초해상(Real-ESRGAN)·얼굴 복원(GFPGAN/CodeFormer) — 1080p 출력에 이득이 없고 '만들어 낸 질감'이 불만을 키운다. 화자에 색수차, 글자·그래픽에 게이트 위브, 구운 레터박스, 압축 전 `gradfun`.

## 4. Q1 — LUT 너머의 필름 에뮬레이션

LUT 는 **픽셀마다 독립**인 변환만 담는다. 할레이션·확산·입자·위브는 이웃 픽셀이나 시간이 필요해서 LUT 로 못 굽는다. 그래서 구현 위치가 갈린다.

| 효과 | 픽셀 독립? | 권장 위치 | 이유 |
|---|---|---|---|
| 하이라이트 롤오프·탈색, 감산식 채도, 스플릿 토닝, 프린트 곡선 | 예 | `auto.py` → 기존 33³ LUT | 비용 0, 롱폼·숏폼·썸네일이 같은 색 |
| 확산(Pro-Mist), 할레이션 | 아니오(블러) | FFmpeg, **프록시 만들 때** LUT 뒤 | 화자 영상에만 걸려야 한다(종이·글자에 걸리면 번진다). 한 번 굽고 캐시 |
| 입자 | 아니오(무작위) | Remotion 최상단 오버레이(기존 `Grain`) | 화자·사진·종이를 **같은 입자**로 묶는 것이 목적. 프록시에 구우면 재인코딩에서 뭉개진다 |
| 게이트 위브·플리커 | 아니오(시간) | Remotion `FilmLook` 안, 사진·스톡 레이어에만 | 글자에 걸리면 떨린다 |
| 비네트·얼굴 조명 | 위치 의존 | Remotion(얼굴 트랙이 props 에 있다) | 얼굴을 따라가야 한다 |

### 4.1 할레이션

**원리**: 강한 빛이 유제를 지나 필름 베이스 뒤에서 반사돼 다시 유제를 노광시킨다. 가장 깊은 층이 적감층이라 붉은-주황 테두리가 된다. utility-dctls 는 "반사광이 R → G → B 순으로 재노광하고 층을 지날수록 빛을 잃고 더 흐려진다"로 모델링하고(반사 손실·G 손실·B 손실을 스톱으로, 블러 폭은 화면 폭의 천분율로 조절), 붉은 편향을 행렬로 되돌리는 옵션을 둔다. ComfyUI-Darkroom 은 한 걸음 더 가서 전반사 고리 + 확산 꼬리 커널을 쓰고 채널 가중치 프리셋을 둔다: CineStill 800T `(1.00, 0.32, 0.10)`, Vision3 subtle `(1.00, 0.45, 0.18)`. grainlight 의 값싼 버전은 반경 `0.004 × 화면 높이` 8탭 블러 → `max(blur − 0.70, 0)` → `(1.0, 0.30, 0.12)` 색 → 세기 0.12 가산이다.
출처: [utility-dctls README](https://github.com/thatcherfreeman/utility-dctls) · [ComfyUI-Darkroom `nodes/halation.py`](https://github.com/jeremieLouvaert/ComfyUI-Darkroom) · [grainlight 셰이더](https://github.com/claudiofabian-sudo/grainlight)

**FFmpeg 체인 〔2차 — 실행 검증함〕**(프록시, LUT 뒤, `gbrp16le` 상태. 1080p 기준: 1/4 로 줄여 σ 1.7 ≈ 원 해상도 σ 6.5 ≈ 0.6% × 높이):
```
split[m][h];
[h]scale=iw/4:ih/4:flags=bilinear,
   colorlevels=rimin=0.72:gimin=0.72:bimin=0.72:romax=0.10:gomax=0.032:bomax=0.010,
   gblur=sigma=1.7:steps=2,scale=iw*4:ih*4:flags=bilinear[halo];
[m][halo]blend=all_mode=screen
```
- 세기와 색(1.0 : 0.32 : 0.10 × 0.10)은 `colorlevels` 의 **출력 최댓값**에 넣는다. 1차 스케치의 `blend=…:all_opacity=0.08` 은 16비트 RGB 에서 암부를 띄우고 색을 깨뜨렸다(실측: 화면 평균 휘도 +8%, 0.5% 지점 2 → 23, 보라·초록 얼룩). 불투명도 1 의 `screen` 은 정상이다.
- 실측(전등이 화면에 있는 2번 카메라, 4초): 화면 평균 휘도 +0.08%, 전등갓 가장자리에만 옅은 온기. 3배 세기에서도 +0.22%. 1/4 해상도 블러는 2.3초, 원 해상도 블러는 7.0초(체인 없이 1.7초).
- `gbrpf32le` 는 쓰지 않는다 — 같은 LUT 인데 결과가 달라졌다(평균 R 134.7 → 128.1).

`colorlevels` 의 입력 블랙을 0.72 로 올리면 그 아래는 0 이 되고 위는 0~1 로 다시 펴진다(문턱 + 정규화). 옵션 이름·범위는 [colorlevels](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/colorlevels.html) · [gblur](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/gblur.html) · [blend](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/blend.html) 문서로 확인했다. 감마 공간 근사다(정확히 하려면 선형광에서).

**numpy 스케치**(정지 사진용):
```python
def halation(rgb, thr=0.72, sigma_frac=0.006, tint=(1.0, 0.32, 0.10), amount=0.08):
    lin = np.power(np.clip(rgb, 0, 1), 2.2)
    t = thr ** 2.2
    src = np.clip((lin - t) / (1 - t), 0, 1)                      # 밝은 곳만
    halo = cv2.GaussianBlur(src, (0, 0), sigma_frac * rgb.shape[0]) * np.array(tint, np.float32)
    return np.power(np.clip(lin + amount * halo, 0, 1), 1 / 2.2)  # 선형광 가산
```

**쓰지 말아야 할 때**
- 화면에 광원·창·강한 반사가 없을 때. 자동 조건: 교정 후 휘도 0.75 이상 화소가 0.2%~8% 일 때만 켠다. 그보다 적으면 효과가 없고, 많으면(흰 벽 하이키) 벽 전체가 주황으로 뜬다.
- 얼굴 하이라이트가 문턱을 넘을 때 — 이마·콧등이 붉게 번져 화상처럼 보인다. 얼굴 상자 안에서는 문턱을 0.85 로 올리거나 끈다.
- 종이 메모·자막·그래픽. 크림 종이(휘도 약 0.95)가 통째로 문턱을 넘는다. 그래서 **프록시 단계에서만** 건다.

### 4.2 블룸 · 확산(Pro-Mist 룩)

shitsukan-diffusion-kit 의 구조: 하이라이트 소프트 문턱 → 블러 4단(상대 반경 1×·2×·4×·8×, 게인 0.50·0.35·0.20·0.10) → 선형광 가산 → 베일(저주파 부드러움 + 하이라이트 탈색). Black Pro-Mist 느낌은 Black Suppress 0.80~0.90, Veil 0.03~0.05, Highlight Desaturation 0.10~0.25. HD 에서 실제 블러 반경은 약 0.6~0.8 / 1.3~1.6 / 2.6~3.2 / 5.0~6.5.
출처: [shitsukan-diffusion-kit](https://github.com/50asa/shitsukan-diffusion-kit)

토킹헤드에서 확산이 주는 것: 디지털 샤픈의 날을 죽이고, 피부 하이라이트의 경계를 풀고, 미세 대비를 낮춘다. 폰·웹캠 영상의 "과하게 선명하고 평평한" 인상을 가장 값싸게 바꾸는 손잡이다.

**FFmpeg 체인 〔2차 — 실행 검증함〕**(2탭 근사, 하이라이트 가중, `gbrp16le`, 1080p):
```
split=3[m][a][b];
[a]scale=iw/4:ih/4:flags=bilinear,colorlevels=rimin=0.45:gimin=0.45:bimin=0.45:romax=0.07:gomax=0.07:bomax=0.07,
   gblur=sigma=1.0:steps=2,scale=iw*4:ih*4:flags=bilinear[g1];
[b]scale=iw/8:ih/8:flags=bilinear,colorlevels=rimin=0.45:gimin=0.45:bimin=0.45:romax=0.05:gomax=0.05:bomax=0.05,
   gblur=sigma=2.0:steps=2,scale=iw*8:ih*8:flags=bilinear[g2];
[m][g1]blend=all_mode=screen[t];[t][g2]blend=all_mode=screen
```
실측(2번 카메라 4초): 화면 평균 휘도 +1.57%, 암부 0.5% 지점 2.0 → 2.1(뜨지 않는다), 2.8초. 3배 세기는 +4.7% — 과하다. 할레이션과 합치면 +1.65%, 3.6초.
세기 기준: 화면 평균 휘도를 2% 넘게 올리지 않을 것. 할레이션과 같은 이유로 `all_opacity` 는 쓰지 않는다.

**쓰지 말아야 할 때**: 이미 부드러운 영상(얼굴 라플라시안 분산이 낮음 — `face.py frame_quality` 의 `sh` 로 판정), 역광으로 이미 뿌연 영상, 저비트레이트 웹캠(블록 노이즈가 번져 더 지저분해진다).

### 4.3 휘도 의존 입자

**근거 값**
- Darkroom: 마스크 `4·L·(1−L)`(중간톤 최대, 암부·하이라이트 0), 세기 1.0 = 중간톤에서 약 0.08 가산, 청색 채널에 20% 더.
- grainlight: 응답 `smoothstep(0.02, 0.20, L) · (1 − 0.65·smoothstep(0.45, 1.0, L)) + 0.06`, 세기 0.030(은은) ~ 0.078(강), 입자 크기 4K 기준 1.6~2.9px, 색 비상관 0.18~0.32. 3옥타브(1×, 0.53×, 1.91× 크기, 가중 1.0·0.55·0.60) + 화소 단위 반짝임 0.22.
- 물리 모델: Newson 외(2017)의 불리언 모델 + 몬테카를로(입자 반지름, 반지름 분산, 필터 σ, 반복 수). 해상도 독립이지만 영상에는 무겁다.
출처: [ComfyUI-Darkroom `utils/grain.py`](https://github.com/jeremieLouvaert/ComfyUI-Darkroom) · [grainlight](https://github.com/claudiofabian-sudo/grainlight) · [Newson et al., IPOL 2017](https://doi.org/10.5201/ipol.2017.192)

**지금 구현이 이미 휘도 의존인 이유**: `Grain.tsx` 는 `mix-blend-mode: overlay` 다. overlay 에 회색 0.5 + n 을 얹으면 변화량이 바닥이 a<0.5 일 때 `2·a·n`, a>0.5 일 때 `2·(1−a)·n` — 곧 `2·min(a, 1−a)` 삼각 마스크다. 검정과 흰색에서 0, 중간에서 최대. 따로 마스크를 만들 필요가 없다. `soft-light` 로 바꾸면 종 모양에 더 가깝고 색 변화가 덜하다.

**고칠 것**
1. 타일 4장 × 2프레임 유지 = 8프레임 주기 반복. `FilmLook` 처럼 타일 하나를 프레임마다 다른 위치로 옮기되, 위치 수를 6 → 프레임 해시 기반(사실상 무한)으로 늘린다.
2. 960×540 타일을 1920 으로 늘려 쓰는 것은 유지해도 된다(입자 약 2px — 이전 연구의 "굵으면 뭉개진다"와 "너무 고우면 사라진다" 사이). 대신 백색 잡음에 약한 뭉침만 준 지금 타일을 **대역 통과**로 바꾼다.
3. 기본 켬, 세기는 낮게(overlay 불투명도 0.035~0.05). 종이·그래픽 위에도 같은 입자가 지나가야 "한 장의 필름"이 된다.

```python
def grain_tile(n=1024, seed=7, size_px=1.6):
    rng = np.random.default_rng(seed)
    g = rng.normal(0, 1, (n, n)).astype(np.float32)
    def blur(a, s):                       # 타일 이음새를 없애려고 직접 감싼 뒤 흐린다(GaussianBlur 의 BORDER_WRAP 지원 여부는 미확인)
        p = int(4 * s) + 1
        return cv2.GaussianBlur(np.pad(a, p, mode="wrap"), (0, 0), s)[p:-p, p:-p]
    x = blur(g, size_px * 0.5) - 0.6 * blur(g, size_px * 1.9) + 0.22 * g   # 뭉침 − 저주파 + 반짝임
    x /= x.std()
    return np.clip(128 + 26 * x, 0, 255).astype(np.uint8)                   # 이어 붙여도 이음새 없음
```

**쓰지 말아야 할 때**: 최종 비트레이트가 낮을 때(입자는 비트를 먹는다 — 10.4), 화면 녹화·UI 캡처 구간, 숏폼의 작은 글자 위(가독성).

FFmpeg 로 굽는다면 `noise=c0s=6:c0f=t+u`(루마만, 시간 변화, 균일) — 다만 FFmpeg `noise` 는 휘도 의존이 아니다([noise 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/noise.html)).

### 4.4 게이트 위브 · 플리커

grainlight 값(화면 높이 대비): 느린 표류 X 0.00022~0.00075, Y 0.00030~0.00100(1080p 에서 0.24~1.1px), 프레임 떨림 0.00008~0.00032(0.09~0.35px), 밝기 플리커 0.25~0.45%. 표류는 주기가 다른 사인 둘의 합(프레임당 위상 0.113·0.041 rad 등).
출처: [grainlight `35mm-1-sutil.glsl` · `35mm-4-equilibrado.glsl`](https://github.com/claudiofabian-sudo/grainlight)

**쓸 곳은 하나**: 전면 **정지 사진**(`Photo.tsx`, `Broll.tsx` 의 사진). 멈춘 JPEG 에 표류 0.3px + 떨림 0.1px + 플리커 0.3% + 입자를 주면 "붙인 이미지"가 "찍은 필름"으로 읽힌다. 켄번즈 배율에 1.004 여유를 더하면 가장자리가 드러나지 않는다.
```tsx
// FilmLook 을 감싼 미디어 div 에만. frame 으로 결정적(렌더 재현 가능)
const weave = (f: number, H: number) => {
  const dx = (Math.sin(f * 0.113) * 0.55 + Math.sin(f * 0.041 + 1.3) * 0.45) * 0.00030 * H;
  const dy = (Math.sin(f * 0.097 + 0.7) * 0.5 + Math.sin(f * 0.033 + 2.1) * 0.5) * 0.00040 * H;
  return {translate: `${dx.toFixed(2)}px ${dy.toFixed(2)}px`};
};
```
**쓰지 말 것**: 화자 영상(자막·메모가 고정돼 있어 화자만 떨리면 손떨림으로 읽힌다), 글자가 있는 모든 레이어, 스톡 영상(이미 움직인다).

### 4.5 감산식 채도 · 밀도

utility-dctls 의 정의: 화소를 `Value`(큰 값이 나오는 평균 — 산술·기하·L2)로 나눠 `Color` 를 얻고, `Color` 를 거듭제곱해 채도를 올린 뒤, **작게 나오는 평균**(조화 평균 권장)으로 구한 `Density` 를 곱한다. 흰색은 보존된다. 결과: 진한 색일수록 어두워진다 — 염료가 빛을 **빼는** 필름의 성질.
출처: [utility-dctls README, Subtractive Saturation DCTL](https://github.com/thatcherfreeman/utility-dctls)

지금 `enrich()` 는 Lab 에서 a·b 만 키운다(L 고정). 밝은 채 진해지는 색은 발광하는 화면의 색이고, 이것이 "디지털·AI 같다"의 한 축이다. 고치는 방법 둘:

```python
# (가) enrich() 안, 최소 변경: 늘어난 채도만큼 밝기를 깎는다(피부 제외, 암부는 덜)
dC = np.maximum(np.hypot(a2, b2) - C, 0.0)
L2 = L - density * dC * (1 - skin) * np.clip(L / 60.0, 0, 1)     # density 0.15~0.30 (L/C 단위)

# (나) 선형 RGB 에서 DCTL 방식 그대로
def subtractive_sat(lin, gamma=1.2, density=0.6, eps=1e-6):
    v = lin.mean(-1, keepdims=True) + eps                 # Value: 산술 평균(크게 나옴)
    c = np.power(np.clip(lin / v, eps, None), gamma)      # Color^gamma → 채도 ↑
    c /= c.mean(-1, keepdims=True)
    d = 3.0 / (1.0 / np.clip(lin, eps, None)).sum(-1, keepdims=True)   # Density: 조화 평균(작게 나옴)
    return c * (v + density * (d - v))                    # 무채색은 d == v 라 그대로
```
(가)는 픽셀 독립이라 LUT 에 그대로 들어간다. 테스트: 채도 높은 파랑·빨강 패치의 L 이 내려가고 회색 계단은 변하지 않을 것.

## 5. Q2 — 자동 룩 매칭

### 5.1 고전 색 전이 셋

| 방법 | 수식 | LUT 로 굽기 | 약점 |
|---|---|---|---|
| Reinhard(2001) | Lab 채널별 `(x − μs)·σr/σs + μr` | 예(전역 아핀) | 채널 상관을 무시. 평균을 통째로 옮긴다 — 이 저장소가 이미 겪은 "파란 방이 통째로 주황" |
| MKL(Pitié & Kokaram 2007) | `T = Σs^(−½)·(Σs^(½)·Σr·Σs^(½))^(½)·Σs^(−½)`, `y = T(x − μs) + μr` | 예(3×3 + 오프셋) | 가우시안 가정. 분포가 여러 봉우리면 타협한 색 |
| 히스토그램(CDF) 매칭 | 채널별 1D LUT | 예(1D ×3) | 계단·포스터화, 채널 독립이라 색 틀어짐. 루마 톤 매칭에만 |

출처: [colortrans(LHM·PCCM·Reinhard, 논문 서지 포함)](https://github.com/dstein64/colortrans) · [colour_transfer_MKL(Pitié & Kokaram 서지)](https://github.com/mahmoudnafifi/colour_transfer_MKL) · [color-matcher(복합 HM-MVGD-HM 이 가장 낫다는 저자 실험)](https://github.com/hahnec/color-matcher)

```python
def mkl(src, ref, k=0.5, lim=(0.8, 1.25)):          # src, ref: (N,3) — 같은 색 공간, 마스크된 화소만
    mu_s, mu_r = src.mean(0), ref.mean(0)
    Cs = np.cov(src.T) + 1e-6 * np.eye(3); Cr = np.cov(ref.T) + 1e-6 * np.eye(3)
    def sqrtm(M):
        w, v = np.linalg.eigh(M); return (v * np.sqrt(np.clip(w, 0, None))) @ v.T
    Cs_h = sqrtm(Cs); Cs_ih = np.linalg.inv(Cs_h)
    T = Cs_ih @ sqrtm(Cs_h @ Cr @ Cs_h) @ Cs_ih
    w, v = np.linalg.eigh(T); T = (v * np.clip(w, *lim)) @ v.T      # 과한 늘림·줄임 막기
    T = np.eye(3) + k * (T - np.eye(3))                             # 세기
    return lambda x: (x - mu_s) @ T.T + mu_s + k * (mu_r - mu_s)
```

### 5.2 어디에 쓰나 — 안전한 순서

1. **다시점 카메라 매칭(가장 안전, 추천)**: 두 카메라는 같은 장면을 본다. `sources.py` 가 구한 오프셋으로 **같은 순간** 프레임 쌍을 뽑아, B 카메라를 A 카메라의 **보정 결과**에 MKL 로 맞춘다(k 0.7~1.0). 지금은 "같은 룩, 레시피는 카메라마다 다시"라 앵글 교차 때 피부·벽 색이 어긋날 수 있다. 얼굴 상자 화소와 배경 화소를 따로 맞춰 비교하고, 맞춘 뒤 얼굴 ΔE 를 로그에 남긴다.
2. **스톡·사진을 채널 룩 쪽으로**: 8장. 마스크된 통계(피부 아닌 중간톤) 기준, k ≤ 0.5.
3. **`user/reference_frames/` v2**: 지금은 평균으로 목표를 ±30% 옮길 뿐. 영역별 통계(암부·중간·하이라이트 각 a*, b*, C 중앙값)로 넓히되 **화면 평균을 옮기지 않는다는 원칙은 지킨다** — 전역 MKL 을 화자 영상에 그대로 걸면 같은 사고가 난다.

## 6. Q3 — 토킹헤드 화질(웹캠·폰·미러리스)

### 6.1 디노이즈: 항상 켜지 말고 등급을 나눈다

지금: 잡음이 가장 적어도 `hqdn3d=1:1:3:3`. `hqdn3d` 는 시간축 강도가 있어(기본 `4:3:6:4.5`) 움직이는 얼굴·손에 잔상이 남고 피부 결을 민다([hqdn3d 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/hqdn3d.html)).

| 등급 | 조건(제안) | 필터 | 근거 |
|---|---|---|---|
| 0 깨끗함 | 시간 잡음 σ < 0.004 | **없음** | 손대지 않는 것이 가장 덜 'AI 같다' |
| 1 약함 | 0.004~0.010 | `hqdn3d=0.8:2.5:2:5`(색 잡음 위주) | 루마 결은 남기고 색 얼룩만 |
| 2 중간(고정 카메라) | 0.010~0.020 | `atadenoise=0a=0.02:0b=0.04:1a=0.03:1b=0.06:2a=0.03:2b=0.06:s=9` | 적응형 시간 평균 — 고정된 배경에 이상적. 문턱 A 는 급변, B 는 연속 변화에 반응해 움직임을 보호한다([atadenoise 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/atadenoise.html)) |
| 3 심함(저조도) | > 0.020 | `atadenoise` 를 `s=15` 로 + 색 위주 `hqdn3d`, 뒤에 입자 | 〔2차〕 `nlmeans=s=2.5:p=7:r=9` 는 1080p 4초에 58초(실시간의 약 15배, i5-13500HX 20스레드) — 기본 경로에서 뺀다. 기본값은 `s=1.0, p=7, r=15`([nlmeans 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/nlmeans.html)). 빌드에 `nlmeans_opencl`·`nlmeans_vulkan` 이 있으나 실행 검증 안 함 |

`bm3d` 는 품질은 가장 좋지만 2패스 구성이 권장되고 매우 느리다([bm3d 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/bm3d.html)) — 쓰지 않는다. 신경망(FastDVDnet, MIT)은 PyTorch 가 필요해 등급 3 전용 선택 기능으로만.

**잡음 측정을 바꾼다**: 지금 `noise` 는 한 프레임의 라플라시안 중앙값이라 벽지 무늬도 잡음으로 센다. 연속 두 프레임 차이의 중앙값(움직이지 않는 영역만)으로:
```python
def temporal_noise(f0, f1):                 # 연속 프레임, 0~1 루마
    d = np.abs(f1 - f0)
    still = d < np.percentile(d, 60)        # 움직임 제외
    return 1.4826 * np.median(d[still]) / np.sqrt(2)
```

### 6.2 밴딩과 디밴드

- 원인: 8비트 소스의 매끈한 벽에 S-커브·감마를 걸면 계단이 벌어진다. 지금은 LUT 자체를 8비트 RGB 에서 건다.
- 처방 순서: ① **16비트에서 LUT**(10.2) → ② 필요하면 `deband=1thr=0.012:2thr=0.012:3thr=0.012:range=16:blur=1`(기본 문턱 0.02, 범위 16 — [deband 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/deband.html)) → ③ 오차 확산 디더로 8비트 → ④ 약한 입자(디더 역할을 겸한다).

### 6.4 자동 화이트밸런스의 함정

- **카메라가 렌더한 sRGB 는 대각 게인으로 완전히 교정되지 않는다** — 렌더링의 비선형 때문(Afifi 외, CVPR 2019 의 핵심 주장). 지금 구현은 감마 2.2 근사로 선형화한 뒤 게인을 건다. 게인이 커질수록(0.7~1.4 허용) 오차가 색 틀어짐으로 나타나니, 큰 교정은 신뢰도를 낮추고 세기를 줄이는 지금의 보수적 설계가 맞다.
- 회색 세계 가정은 나무·크림 벽 같은 **지배색**이 있으면 틀린다. 이미 무채색 후보 → 피부색 선 순으로 보완했다.
- **혼합 조명**(한쪽 스탠드, 한쪽 모니터)은 전역 WB 로 못 푼다. 피부 우선(지금 방식)이 정답이고, 배경의 색 차이는 "장면의 빛"으로 남긴다.
- 자동 WB·자동 노출이 켜진 웹캠은 **시간에 따라 변한다** → 6.5.
출처: [WB_sRGB (CVPR 2019)](https://github.com/mahmoudnafifi/WB_sRGB)

### 6.5 노출 플리커와 드리프트

- **프레임 단위 깜빡임**(형광등·LED 와 셔터의 맥놀이): `deflicker=s=5:m=am`(이동 평균 프레임 수 기본 5, 범위 2~129 — [deflicker 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/deflicker.html)).
- **느린 드리프트**(자동 노출·자동 WB 가 몇 초에 걸쳐 변함): 먼저 **잰다** — 얼굴 휘도·피부 색상을 2초마다 재서 표준편차가 문턱(휘도 0.03, 색상 4°)을 넘는지. 넘으면:
  - 값싼 방법: Remotion 에서 화자 영상에 CSS `filter: brightness(k)` 를 시간 곡선으로(±8% 안). `TalkingHead` 에 이미 `filter` prop 이 있다. 밝기만 고칠 수 있다.
  - 제대로: FFmpeg `haldclut` 는 CLUT 입력이 **영상**일 수 있다(`clut=all` 이 기본 — 프레임마다 다른 CLUT). 2초마다 구운 Hald 이미지를 `framerate` 로 선형 보간해 넣으면 시간에 따라 변하는 그레이드가 된다(LUT 의 선형 보간은 유효한 LUT). 체인 자체는 실행해 보지 못했다(미확인).
  출처: [haldclut 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/haldclut.html)

### 6.6 암부의 구르는 잡음, 그리고 초해상

- 감마로 얼굴을 올리면(`gamma` 0.72 까지) 암부 잡음이 같이 올라온다. 잡음 등급 2 이상이면 감마 하한을 0.85 로 묶고 나머지는 얼굴 쪽 조명(7.2)으로 채운다. 색 잡음은 루마보다 강하게 지운다(등급 1 의 `hqdn3d` 색 강도).
- **초해상·복원은 넣지 않는다.** 1080p(프록시 1440p) 출력에서 1080p·4K 소스는 이득이 0 이다. 720p 웹캠에서는 Real-ESRGAN 이 디테일을 '지어내는데', 그 질감이 정확히 운영자가 싫어하는 "AI 같은" 느낌이다. GFPGAN·CodeFormer 는 얼굴을 다시 그려 본인과 달라진다. 속도 수치는 README 에 없다(미확인). 대안: lanczos 업스케일 + `cas` + 입자.
  출처: [Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN)

### 6.7 피부 보정의 선

기본은 **하지 않는다.** 교육 채널에서 화자의 얼굴을 바꾸는 것은 신뢰 문제이고, 과한 평활은 "AI 같다"의 대표 신호다. 옵션으로 둔다면: 운영자가 직접 켜야 하고, 피부 마스크 안에서 중간 주파수만(양방향 필터 결과를 30% 이하로 섞기), 모공·잔주름 대역은 그대로, 편집 리포트에 적용 사실 기록. 형태를 바꾸는 것(턱·눈)은 하지 않는다. (이 항은 판단이며 외부 출처가 없다.)

## 7. Q4 — 고정 토킹헤드를 "싸 보임 → 시네마틱"으로

비용 순으로 네 단계. 앞의 둘은 의존성 없이 지금 코드에 붙는다.

### 7.1 프레이밍 점검(의존성 0)

- 프록시는 **원본이 1440p 이상일 때만** 출력의 1.33배다(`assemble.proxy_height_for` 는 `min(원본 높이, 1440)`). 〔2차〕 테스트 원본은 iPhone 14 Pro **1080p**(H.264 8비트 BT.709, 약 15Mbps)라 프록시도 1080p — 재프레이밍 여유가 0 이고 106% 푸시인은 업스케일이다. 4K 로 찍으면 33% 여유가 생긴다([`12_촬영_체크리스트.md`](../upgrade/12_촬영_체크리스트.md)).
- 눈높이를 위 1/3 선(y 0.33~0.38)에 — YuNet 은 눈 좌표를 준다(`face.py detect_full` 이 이미 읽는다). 머리 위 여백이 과하면 기본 프레이밍을 100% 대신 104~108% 로 잡아 눈을 선에 올린다.
- **느린 크리프**: 20초 넘게 같은 프레이밍이면 100% → 102.5% 를 그 구간 전체에 걸쳐 선형으로(초당 0.1% 안쪽). 인터뷰 다큐의 기본기이고, "젠틀하게" 원칙(`CameraShot.glide`)과 충돌하지 않는다. 컷에서 원위치.

### 7.2 얼굴 중심 비네트 + 키 라이트(의존성 0, 추천)

지금 `Vignette` 는 화면 중심 고정이고 검정 알파라 대비를 같이 낮춘다. 얼굴 트랙(`props.face`)이 이미 있으니:
```tsx
export const FaceLight: React.FC<{x: number; y: number; s: number; k?: number}> = ({x, y, s, k = 1}) => {
  const edge = Math.round(255 * (1 - 0.22 * k));           // 가장자리 −0.35 스톱쯤
  return (
    <AbsoluteFill style={{pointerEvents: 'none'}}>
      <AbsoluteFill style={{mixBlendMode: 'multiply', background:
        `radial-gradient(${95 + s * 60}% ${115 + s * 60}% at ${x * 100}% ${y * 100}%, #fff 0%, #fff 36%, rgb(${edge},${edge},${edge}) 100%)`}} />
      <AbsoluteFill style={{mixBlendMode: 'soft-light', opacity: 0.10 * k, background:
        `radial-gradient(${s * 150}% ${s * 180}% at ${x * 100}% ${(y - 0.02) * 100}%, #fff 0%, transparent 70%)`}} />
    </AbsoluteFill>
  );
};
```
- 곱하기 블렌드는 '노출을 내리는' 것이라 색이 탁해지지 않는다. 얼굴 쪽 `soft-light` 는 +0.1 스톱쯤의 부드러운 키.
- 중심은 얼굴 트랙을 따라가되 강하게 평활(이미 τ 0.9초). 화자 판(둥근 판)·종이 액자 안에서는 세기를 절반.
- 8비트 그라데이션 밴딩을 막으려면 이 위로 입자가 지나가야 한다(4.3).

## 8. Q5 — 자료 사진·스톡을 한 세계로: 하우스 트리트먼트

채널 룩: 크림 종이 `#F5F2EA`(245,242,234) · 웜 잉크 `#26211E`(38,33,30) · 시그널(테마 accent 주황) 하나(`renderer/src/design/tokens.ts NOTE`).

**핵심 생각**: 인쇄물에는 종이보다 밝은 색도, 잉크보다 어두운 색도 없다. 외부 그림의 톤 범위를 **[잉크, 종이] 안으로** 담으면 그래픽과 같은 톤 공간에 놓인다. 순수한 검정(0,0,0)과 순수한 흰색(255,255,255)이 종이 위에 올라오는 것이 "붙여 넣은 것"의 정체다.

### 8.1 공통 전처리(모든 등급)

1. **레벨 정규화**: 휘도 0.5%·99.5% 지점을 0·1 로. 늘림은 1.4배까지(바랜 아카이브 사진을 억지로 펴지 않는다).
2. **채도 정규화**: 피부 아닌 중간톤의 Lab 채도 중앙값을 목표 16(화자 영상의 `target_chroma` 15~21 과 같은 대역)으로 — 이득 0.6~1.25, 채도 40 초과는 무릎(초과분 ×0.3). 네온 같은 스톡이 가라앉는다.
3. **색 방향**: 중간톤 a*·b* 중앙값을 채널 기준(`REFERENCE_LAB` 의 a 4.7, b 14.5 방향)으로 **절반만**. 통째로 옮기지 않는다(5장의 교훈).
4. **잉크·종이 리맵**: `out = lo + x·(hi − lo)`, `lo = k·INK`, `hi = 1 − k·(1 − PAPER)`. 전면 사진·영상은 k 0.5(블랙 약 (19,17,15), 화이트 약 (250,249,245)), 종이 위에 붙는 사진은 k 0.85.
5. **출력**: 영상은 클립마다 구운 33³ `.cube` 를 `lut3d` 로(1~4 는 전부 픽셀 독립이라 LUT 하나에 들어간다), 사진은 PIL 로 바로.

```python
INK = np.array([38, 33, 30], np.float32) / 255
PAPER = np.array([245, 242, 234], np.float32) / 255

def house_stats(frames):                                  # 클립에서 3~5 프레임 표본
    pix = np.concatenate([f.reshape(-1, 3) for f in frames])
    lum = _luma(pix); lo, hi = np.percentile(lum, [0.5, 99.5])
    L, a, b = srgb_to_lab(pix); C = np.hypot(a, b); mid = (L > 25) & (L < 80)
    return dict(lo=lo, hi=max(hi, lo + 1 / 1.4), c_med=float(np.median(C[mid])),
                a_med=float(np.median(a[mid])), b_med=float(np.median(b[mid])))

def house_grade(x, st, k=0.5, c_target=16.0, pull=0.5, ref_ab=(4.7, 14.5)):
    x = np.clip((x - st["lo"]) / (st["hi"] - st["lo"]), 0, 1)
    L, a, b = srgb_to_lab(x)
    w = 4 * (L / 100) * (1 - L / 100)                                  # 중간톤에서만 방향을 옮긴다
    a = a + pull * (ref_ab[0] - st["a_med"]) * w * 0.5
    b = b + pull * (ref_ab[1] - st["b_med"]) * w * 0.5
    C = np.hypot(a, b) + 1e-6
    g = np.clip(c_target / max(st["c_med"], 4.0), 0.6, 1.25)
    C2 = np.where(C * g > 40, 40 + (C * g - 40) * 0.3, C * g)
    x = lab_to_srgb(L, a * C2 / C, b * C2 / C)
    lo, hi = k * INK, 1 - k * (1 - PAPER)
    return lo + x * (hi - lo)
```
`srgb_to_lab`·`lab_to_srgb`·`_luma` 는 `auto.py` 에 있는 것을 그대로 쓴다. 영상용 LUT 는 `write_cube` 와 같은 격자에 `house_grade` 를 태우면 된다.

FFmpeg 만으로 4번을 하려면 `colorlevels=romin=0.075:gomin=0.065:bomin=0.059:romax=0.980:gomax=0.975:bomax=0.959`(k 0.5) — 출력 블랙·화이트를 채널별로 정할 수 있다([colorlevels 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/colorlevels.html)).

### 8.2 세 등급

| 등급 | 언제 | 처리 | 가장자리·질감 |
|---|---|---|---|
| **T1 그레이드 사진**(기본) | 화질 좋은 사진·스톡 영상, 색이 정보인 그림(작품·제품) | 8.1 전부 | 전면: `FilmLook`(비네트 + 입자) + 게이트 위브(사진만). 패널·pip: 크림 인화 테두리 14~18px, 0.4~1.2° 기울임, 그림자 두 겹(`0 2px 3px rgba(38,33,30,.25)` + `0 14px 30px rgba(38,33,30,.18)`), 안쪽 1px 잉크 12% 선 |
| **T2 듀오톤 잉크** | 색이 제각각인 연속 사진, 낮은 화질, 색이 정보가 아닌 인물·건물·풍경 아카이브 | 휘도 → 잉크→종이 그라데이션 맵(중간에 따뜻한 회색 한 점). 대비는 S-커브 0.15 | 종이에 직접 '인쇄된' 것처럼 — 테두리 없이 찢긴 가장자리(`tornRectPath`) + `Halftone` 오버레이 |
| **T3 하프톤 클리핑** | 작거나(긴 변 < 1200px) 압축이 심한 그림, 신문·잡지 느낌이 맞는 자료 | AM 하프톤(45°, 셀 6~8px @1080p), 잉크 한 색. 선택: 시그널 판을 밝은 영역에 평면으로 깔고 1~2px 어긋나게 | 신문 조각처럼 찢긴 사각 + 테이프(`Tape`) |

```python
def duotone(rgb, ink=INK, paper=PAPER, mid=(0.55, 0.50, 0.45)):
    t = _scurve(_luma(rgb), 0.15)[..., None]
    lo = ink + (np.array(mid) - ink) * np.clip(t * 2, 0, 1)             # 잉크 → 따뜻한 회색
    hi = np.array(mid) + (paper - np.array(mid)) * np.clip(t * 2 - 1, 0, 1)
    return np.where(t < 0.5, lo, hi)

def halftone(gray, cell=7.0, angle=45.0, ink=INK, paper=PAPER):          # gray: 0~1, 먼저 σ≈cell/2 로 흐린다
    h, w = gray.shape; yy, xx = np.mgrid[0:h, 0:w].astype(np.float32)
    th = np.deg2rad(angle)
    u = (xx * np.cos(th) + yy * np.sin(th)) / cell; v = (-xx * np.sin(th) + yy * np.cos(th)) / cell
    d = np.hypot(u - np.round(u), v - np.round(v))                       # 셀 중심까지(셀 단위)
    r = np.sqrt(np.clip(1 - gray, 0, 1) / np.pi)                         # 점 면적 = 어두운 정도
    alpha = np.clip((r - d) * cell + 0.5, 0, 1)[..., None]               # 1px 안티에일리어싱
    return paper + (ink - paper) * alpha
```
셀이 5px 보다 작으면 유튜브 압축에서 모아레·뭉개짐이 난다(판단 — 실측 필요). utility-dctls 의 Halftone Dot Printing DCTL 과 Darkroom 의 Halftone 노드(AM 15/75/0/45 로제트, FM 베이어)가 같은 구조다.
출처: [utility-dctls README, Halftone Dot Printing](https://github.com/thatcherfreeman/utility-dctls) · [ComfyUI-Darkroom README](https://github.com/jeremieLouvaert/ComfyUI-Darkroom)

**시그널 색 규칙**: 사진 안에 주황을 '물들이는' 트리톤은 기본으로 쓰지 않는다 — 시그널은 화면에서 한 가지 일(강조)만 해야 한다. 쓴다면 T3 에서 한 장면에 하나, 평면 판으로만.

```python
def picture_flags(rgb, face_box=None):
    y = _luma(rgb); p10, p90 = np.percentile(y, [10, 90])
    out = {"flat": p90 - p10 < 0.40,
           "clipped": float((rgb.max(-1) >= 0.985).mean()) > 0.02,
           "crushed": float((y <= 0.02).mean()) > 0.08}
    if face_box:
        x0, y0, x1, y1 = face_box; f = rgb[y0:y1, x0:x1].reshape(-1, 3)
        L, a, b = srgb_to_lab(f); hue = np.degrees(np.arctan2(np.median(b), np.median(a))) % 360
        out |= {"face_clip": float((f.max(-1) >= 0.985).mean()) > 0.005,
                "skin_hue_off": not (32 <= hue <= 60), "skin_chroma_hi": float(np.median(np.hypot(a, b))) > 30,
                "face_lab": (float(np.median(L)), float(np.median(a)), float(np.median(b)))}
    return out
# 컷마다: ΔE = sqrt(ΔL² + Δa² + Δb²) (앞 클립 마지막 0.5초 vs 뒤 클립 첫 0.5초의 face_lab)
```

## 10. Q7 — 유튜브 납품 색 과학

### 10.1 태그

유튜브 권장(SDR): BT.709 — 전달 함수·원색·행렬 모두 H.273 값 1. 컨테이너 MP4, moov 앞(Fast Start), H.264 High, 프로그레시브, B 프레임 2 연속, **폐쇄 GOP = 프레임레이트의 절반**, CABAC, 4:2:0, 가변 비트레이트. SDR 업로드 권장 비트레이트(24~30fps): 1080p 8Mbps · 1440p 16Mbps · 2160p 35~45Mbps. 오디오 AAC-LC 48kHz 스테레오 384kbps.
출처: [YouTube 고객센터: 권장 업로드 인코딩 설정](https://support.google.com/youtube/answer/1722171?hl=en)

- 프록시: `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv` ✔.
- **최종 렌더: `renderMedia` 에 `colorSpace` 가 없다.** Remotion 소스의 옵션 설명: 허용값 `bt601`·`bt709`·`bt2020-ncl`·`bt2020-cl`(v4 는 `default` 도), **기본은 v4 에서 `"default"`, v5 부터 `bt709`**, v4.0.83 부터는 태그만이 아니라 실제 변환을 하고, 색 정확도를 위해서는 `imageFormat: "png"` 를 권한다. → `colorSpace: 'bt709'` 를 명시하고, 완성 파일을 `ffprobe` 로 읽어 세 태그가 `bt709` 인지 **단언**한다.
  〔2차 — 실행 검증함〕 테스트 완성본은 `yuvj420p` · `color_range=pc` · `color_space=bt470bg` · 전달 함수·원색 `unknown` 이다. 설치된 4.0.530 의 `ffmpeg-args.js` 는 `default` 일 때 색 인자를 붙이지 않으므로 Chrome 이 찍은 JPEG 프레임의 풀레인지 BT.601 이 그대로 H.264 에 담긴다. 태그를 읽는 재생기는 맞게 보여 주지만, HD 를 BT.709 리미티드로 가정하는 경로에서는 대비·색이 틀어진다. `bt709` 를 주면 같은 파일이 태그 4개와 `zscale=matrix=709:range=limited:primariesin=709:primaries=709:transferin=709:transfer=709` 를 붙인다.
  출처: [remotion `options/color-space.tsx`](https://github.com/remotion-dev/remotion/blob/main/packages/renderer/src/options/color-space.tsx) · [renderMedia 문서](https://www.remotion.dev/docs/renderer/render-media)
- 스톡 영상(`prepare_video`)은 색 태그도, 입력 행렬 지정도 없다. 프록시와 같은 `-colorspace…` 인자를 붙인다.
- 썸네일 경로(`pipeline.py:1986`)는 `format=gbrp,lut3d` 만 있어 태그 없는 HD 소스를 swscale 기본 행렬로 읽는다. `build_proxy` 의 `scale=in_color_matrix=…` 부분을 함수로 빼서 같이 쓴다.

### 10.2 비트 심도와 밴딩

- FFmpeg `lut3d` 는 `gbrp16`·`gbrpf32` 까지 받는다(소스의 `pix_fmts[]`: RGB24/48, GBRP 9~16, GBRPF32 등, 보간 기본값은 사면체).
- 제안 체인(`assemble.build_proxy`) 〔2차 — 실행 검증함: 원본 4초 구간, 8비트 경로와 속도 차이 없음(1.9초 vs 2.0초). `zscale=min=gbr:m=709:rin=full:r=limited:d=error_diffusion` 로 써도 출력이 완전히 같았다〕:
```
scale=in_color_matrix=<matrix>,format=gbrp16le,
lut3d=file='grade_N.cube':interp=tetrahedral,
[확산·할레이션은 여기 — 16비트 RGB]
zscale=m=bt709:r=tv:d=error_diffusion,format=yuv420p
```
`zscale` 의 디더 값은 `none`·`ordered`·`random`·`error_diffusion`([zscale 문서](https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/zscale.html)). 이 저장소는 HDR 경로에서 이미 `zscale` 을 쓰므로(`hdr_to_sdr_filter`) 빌드 의존성은 새로 생기지 않는다.
  출처: [FFmpeg `vf_lut3d.c`](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_lut3d.c)
- 10비트 **중간 파일** 자체는 이득이 작다. Remotion 은 Chrome 이 찍은 8비트 프레임(JPEG q92)을 인코딩하므로 프록시가 10비트여도 거기서 8비트가 된다. 의미 있는 것은 "색 연산은 16비트에서, 8비트로는 디더와 함께 **한 번만**"이다.
- 10비트 원본(아이폰 HLG 등)은 톤 매핑을 `gbrpf32le` 에서 하고 있어 ✔. 그 뒤 `format=yuv420p` 로 내리는 자리에 디더만 더한다.
- JPEG 프레임(q92, 4:2:0)은 입자와 고운 그라데이션을 한 번 더 깎는다. 입자를 켜면 q95 이상으로 올리거나, 시간이 허락하면 PNG(느림).

### 10.3 인코더 설정

지금: GPU 면 Remotion 하드웨어 가속 + 비트레이트만(1080p 16M), CPU 면 CRF 18 medium. Remotion 은 하드웨어 가속일 때 CRF 를 못 쓰고, 튠·AQ·GOP 를 직접 노출하지 않는다.
출처: [Remotion 인코딩 가이드](https://www.remotion.dev/docs/encoding)

**제안: 2단 인코딩.** Remotion 은 메자닌(가속 40M 또는 CRF 12)으로 뽑고, `mux_final` 이 `-c:v copy` 대신 최종 인코딩을 한다(어차피 음향을 합치려고 한 번 읽는다).

- x264: `-c:v libx264 -preset slow -crf 16 -tune film -profile:v high -pix_fmt yuv420p -bf 2 -g <fps/2> -flags +cgop -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv -movflags +faststart`
  - `-tune film` = 디블록 −1:−1, psy-trellis 0.15. `-tune grain` = 디블록 −2:−2, psy-trellis 0.25, dct-decimate 끔, ip/pb 비 1.1, AQ 0.5, 데드존 6/6, qcomp 0.8 — 입자를 강하게 지키지만 파일이 커진다. 우리 입자는 약하므로 `film` 이 맞다.
  출처: [x264 `common/base.c` (GitHub 미러)](https://github.com/mirror/x264/blob/master/common/base.c)
- NVENC: `-c:v h264_nvenc -preset p6 -tune hq -rc vbr -cq 18 -b:v 0 -bf 2 -b_ref_mode middle -spatial-aq 1 -aq-strength 8 -temporal-aq 1 -rc-lookahead 20 -g <fps/2>` — NVIDIA 문서의 고화질 예(`-preset p6 -tune hq … -bf 3 -b_ref_mode middle -temporal-aq 1 -rc-lookahead 20`, AQ 강도 1~15, 룩어헤드 10~20 권장)를 유튜브의 "B 프레임 2, GOP 절반"에 맞춘 것. 공간 AQ 는 평탄한 벽의 밴딩에, 시간 AQ 는 고정 배경에 비트를 아끼는 데 듣는다.
  출처: [NVIDIA: FFmpeg with NVIDIA GPU](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html)
- H.264 NVENC 의 10비트 지원 여부는 확인하지 못했다(미확인). 최종은 어차피 8비트 4:2:0.
- 〔2차 — 실행 검증함〕 번들 FFmpeg n9.0.2 의 `h264_nvenc` 는 NVENC API 13.1(드라이버 610.00 이상)을 요구한다. 테스트 PC 의 드라이버(32.0.15.9282)로는 열리지 않아 `FFmpeg._nvenc_variant()` 가 조용히 실패하고 x264 로 떨어졌다. 위 NVENC 인자는 이 PC 에서 실행 검증 안 함. 진단(`진단.md`)에 "NVENC: 드라이버가 낮음"을 적어야 한다.

### 10.4 입자와 유튜브 재인코딩

- 유튜브는 올린 파일을 다시 인코딩한다. 고운 입자는 그 과정에서 가장 먼저 사라지고 블록으로 바뀐다 — 이전 연구가 "기본 끔"으로 결론 낸 이유. 그래서 4.3 의 입자는 **약 2px, 낮은 세기**다.
- "1440p 이상으로 올리면 더 좋은 코덱·비트레이트 사다리를 받는다"는 널리 알려진 경험칙이지만 공식 문서로 확인하지 못했다(미확인). 프록시가 이미 1440p 이고 그래픽은 벡터라, Remotion `scale: 1.333` 으로 **1440p 출력 옵션**을 만드는 비용은 렌더 시간(화소 1.78배)뿐이다. A/B 로 확인할 가치가 있다.

## 13. 확인하지 못한 것

1. 〔2차에서 해소〕 16비트 LUT + 디더, 할레이션, 확산, 정리 필터, `maskedmerge`, 측정 필터는 번들 FFmpeg 로 실행했다(맨 위 "검증 상태"). **아직 실행하지 않은 것**: `haldclut` + CLUT 영상(6.5), CAMBI, 2단 인코딩 인자(10.3), 스톡 영상용 `lut3d` 체인, 얼굴 중심 비네트의 Remotion 구현, 입자 타일 코드, MKL 코드, 1440p 출력.
2. 〔2차에서 해소〕 Remotion 4.0.530 의 기본 출력은 풀레인지 BT.601(`yuvj420p`, `bt470bg`)이다. `colorSpace: 'bt709'` 를 준 뒤의 출력은 아직 렌더해 보지 않았다(소스로만 확인).
3. 유튜브가 1440p 이상 업로드에 더 좋은 코덱 사다리를 준다는 경험칙.
4. NVENC H.264 10비트 지원. (libvmaf 는 번들 빌드에 있다 — 2차 확인.)
5. MediaPipe·MODNet·Depth Anything Small 의 **데스크톱 CPU** 속도, RVM 의 CPU 속도, `nlmeans` CPU 속도, Real-ESRGAN 속도.
6. RawTherapee 필름 시뮬 HaldCLUT 모음의 라이선스, spektrafilm LUT 의 상업 조건, `spectral_film_lut` 이 내는 LUT 의 입력 로그 규격, 무료 프린트 필름 LUT 팩 일반.
7. CineScale 의 클래스 구성·라이선스·논문, CodeFormer·GFPGAN·VMAF 의 정확한 라이선스 문구(API 가 NOASSERTION 으로만 답함).
8. darktable AgX/filmic 문서, FFmpeg 위키 H.264 가이드(접속 차단), x264 원 저장소(미러로 대체).
9. 웹 검색을 쓰지 못해 **토픽·지명 조회 밖의 저장소는 찾지 못했다.** 예컨대 오픈소스 Dehancer 대체품이 더 있을 수 있다.
10. ComfyUI-Darkroom README 는 MIT 라고 쓰지만 복제본에 LICENSE 파일이 없다. shitsukan-diffusion-kit·grainlight 도 API 가 라이선스를 검출하지 못했다(README·LICENSE 표기는 MIT).
11. 문턱값(잡음 등급, QA 경고, 하프톤 셀 크기, 입자 세기)은 출처의 수치와 기존 코드 상수에서 유추한 **제안**이다. 운영자의 실제 촬영본(골든 세트)으로 맞춰야 한다.
