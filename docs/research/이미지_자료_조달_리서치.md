## 0. 한 장 요약

- 이번 테스트 영상의 실물 이미지는 **26.5초 / 764초 = 3.5%**, 전면 0회였다. 요청 11건(사진 2 + 스톡 9)이 화면 5건이 됐다.
- 직접 원인은 "찾다가 실패"가 아니었다. 이 대본은 고유명사가 거의 없는 개인 경험담이고, 지금 엔진에는 **화자 자신의 자료·논문 같은 1차 자료·서비스 화면**을 요청할 길이 없다.
  길이 있는 두 건 중 하나는 틀린 대상(핀터레스트 → CEO 무대 사진), 하나는 타이밍 충돌로 사라졌다. 남은 것은 전부 얼굴 옆 작은 액자였고 라벨은 검색어였다.
- 고유명사가 많은 대본(디자이너·작품)에서는 다른 문제가 기다린다: 엔티티당 대표 이미지 1장만 받는다.
  **[실측]** "디터 람스"는 Wikidata(Q76427) → Commons 분류에 자유 라이선스 파일이 50장 이상, 영어 위키백과 문서에만 22장이 있다.
- 소스는 충분하다. Commons·Wikidata 와 오픈 액세스 미술관 6곳은 키 없이(또는 무료 키로) 쓸 수 있고, 서지는 Crossref 로 풀린다.
  부족한 것은 **무엇을 봐야 하는지 정하는 단계**(need), **대체 사다리**, **화면 처리**다.

### A-4. 처음 추정과 달랐던 점

- 처음 메모는 `name_en` 결함·자유 라이선스 필터·"못 찾으면 버림"을 맨 위에 두었다. 이번 실행에서는 **셋 다 발동하지 않았다.**

- 라벨 누수(16)·검수 수정 미반영(17)·NC/ND 선택(19)은 코드만 읽어서는 우선순위를 낮게 봤거나 놓친 것이다.
- 결론: 엔진 설계의 중심은 "더 많은 소스"가 아니라 **need 유형 → 대체 사다리 → 전면 표시**여야 하고, 소스 확장은 그다음이다.

### A-5. 기타 준수 사항

- **Unsplash API 가이드라인은 핫링크를 요구**한다("We require the image URLs returned by the API to be directly used or embedded" — https://unsplash.com/documentation). 영상에 구워 넣는 용도와의 관계는 운영자가 확인해야 한다(미확인).

#### B-1.1 Wikimedia Commons · Wikipedia · Wikidata — 엔티티 조달의 기본

**엔드포인트(모두 키 없음, 연락처 든 User-Agent 필수)**

| 용도 | 호출 | 출처 |
|---|---|---|
| 한글 이름 → QID | `https://www.wikidata.org/w/api.php?action=wbsearchentities&search=디터 람스&language=ko&type=item` | https://www.wikidata.org/wiki/Wikidata:Data_access |
| QID → 속성·사이트링크 | `action=wbgetentities&ids=Q…&props=claims|sitelinks|labels` (요청당 50개까지) | 위와 같음 |
| 관계 질의(작품 목록·연도) | SPARQL `https://query.wikidata.org/sparql` | 위와 같음 |
| 문서 안 **모든** 이미지 | `https://{lang}.wikipedia.org/api/rest_v1/page/media-list/{title}` 또는 Action API `generator=images&titles=…&prop=imageinfo` | https://www.mediawiki.org/wiki/API:Images |
| Commons 분류의 파일 | `https://commons.wikimedia.org/w/api.php?action=query&generator=categorymembers&gcmtitle=Category:…&gcmtype=file|subcat&prop=imageinfo` | https://www.mediawiki.org/wiki/API:Imageinfo |
| 구조화 데이터 "묘사 대상" 검색 | `generator=search&gsrnamespace=6&gsrsearch=haswbstatement:P180=Q… filetype:bitmap` | https://www.mediawiki.org/wiki/Help:CirrusSearch |
| 라이선스·작가·썸네일 | `prop=imageinfo&iiprop=url|size|mime|extmetadata&iiurlwidth=1920` (`LicenseShortName`, `LicenseUrl`, `Artist`, `Credit`, `Attribution`, `UsageTerms` …) | https://www.mediawiki.org/wiki/API:Imageinfo |
| 대표 이미지(자유/비자유) | `prop=pageimages&piprop=original&pilicense=free|any` — 기본값은 `free` | https://www.mediawiki.org/wiki/Extension:PageImages |

검색 키워드: `haswbstatement:P180=Q146`, `incategory:`, `deepcat:`(하위 5단계·256개 분류까지), `filetype:`, `filemime:`, `fileres:`, `filew:`, `fileh:` (https://www.mediawiki.org/wiki/Help:CirrusSearch).

**한도·예절**: 연락처가 든 UA 는 분당 200회, 식별 불가는 분당 10회, 초과 시 429 + `Retry-After`(https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits). 직렬 호출·`maxlag` 권장(https://www.mediawiki.org/wiki/API:Etiquette). 브라우저 UA 흉내 금지(https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy).

**쓸 만한 Wikidata 속성** [실측: 속성 라벨을 API 로 확인]: P18 image · P154 logo image · P8972 small logo or icon · P571 inception · P577 publication date · P287 designed by · P84 architect · P170 creator · P176 manufacturer · P800 notable work · P135 movement · P373 Commons category · P935 Commons gallery · P5775 image of interior · P109 signature · P180 depicts. P569/P570(출생·사망)·P571·P577 을 모으면 **타임라인을 자동 생성**할 수 있다.

**[실측] "디터 람스" 예시 (2026-10-01)**

권장 표기: 화면 `Braun SK 4 · 사진: {작가} · CC BY-SA 2.0 · Wikimedia Commons`, 설명란에 파일 페이지 URL + 라이선스 URL.

#### B-1.3 로고

- 1순위: Wikidata **P154(logo image)** → Commons SVG. 단순 글자·도형 로고는 Commons 에서 `PD-textlogo`(저작물성 없음) + `Trademarked` 틀이 붙는 경우가 많다(틀 운용은 이번 조사에서 개별 확인 안 함 — (미확인)). 저작권이 없어도 **상표권은 별개**다.
- Simple Icons: 프로젝트는 CC0 이지만 "브랜드가 제기하는 법적 문제에 책임지지 않으며, 사용자는 올바른 허락을 구하라"는 면책이 있고 아이콘별 라이선스·가이드가 다를 수 있다(https://github.com/simple-icons/simple-icons/blob/develop/DISCLAIMER.md). 단색 글리프라 **원래 색·비례의 로고를 비평할 때는 부적합**하다.
- 사용 원칙(B-3 참조): 지칭 목적(nominative)·필요한 만큼·후원 오인 금지. 로고를 **변형·재색칠하지 않는다**(비평 대상이 로고 디자인 자체일 때는 주석 레이어를 따로 얹는다).

### B-3. 저작권·공정이용 (일반 정보, 법률 자문 아님)

**한국 저작권법**
- 제28조(공표된 저작물의 인용): "공표된 저작물은 보도·비평·교육·연구 등을 위하여는 정당한 범위 안에서 공정한 관행에 합치되게 이를 인용할 수 있다." (https://casenote.kr/법령/저작권법/제28조)
- 판단 기준(대법원 2006.2.9. 선고 2005도7793): "인용의 목적, 저작물의 성질, 인용된 내용과 분량, 피인용저작물을 수록한 방법과 형태, 독자의 일반적 관념, 원저작물에 대한 수요를 대체하는지 여부 등을 종합적으로 고려". 같은 판결은 작은 썸네일 이미지 제공을 정당한 인용으로 본 원심을 수긍했다(https://casenote.kr/대법원/2005도7793). 실무에서는 인용하는 쪽이 주(主), 인용되는 쪽이 종(從)인 **주종관계**가 자주 거론된다(검색 요약, https://www.lawtimes.co.kr/news/105101).
- 제35조의5(저작물의 공정한 이용): 일반적 이용 방법과 충돌하지 않고 저작자의 정당한 이익을 부당하게 해치지 않으면 이용 가능. 고려 사항 ① 이용의 목적 및 성격 ② 저작물의 종류 및 용도 ③ 이용된 부분의 비중과 중요성 ④ 현재·잠재 시장 또는 가치에 미치는 영향(https://casenote.kr/법령/저작권법/제35조의5).
- 제37조(출처의 명시): 이용자는 출처를 명시해야 하고, "이용 상황에 따라 합리적이라고 인정되는 방법"으로, 실명·이명이 표시된 저작물이면 그것을 명시(https://casenote.kr/법령/저작권법/제37조).

**미국**
- 17 U.S.C. §107 네 요소: 목적과 성격(상업성·교육성), 저작물의 성질, 이용된 양과 실질, 시장에 미치는 영향. 변형적 이용은 "add something new, with a further purpose or different character"이며 판단은 사안별(https://www.copyright.gov/fair-use/).

### B-4. AI 생성 이미지

**써도 되는 곳**: 추상 개념의 은유(질감·배경·패턴), 종이·잉크 텍스처, 장면 사이의 분위기 판, 실물이 필요 없는 "가상의 예시"(가짜 앱 화면으로 나쁜 UX 를 보여 주기 등 — 화면에 "예시"라고 표시).
**쓰면 안 되는 곳**: 실존 디자이너의 초상, 실존 작품·제품·포스터의 "재현", 역사적 장면. 역사가들은 AI 가 만든 가짜 역사 사진이 "tsunami of fake history" 를 만든다고 경고한다(AFP, https://www.taipeitimes.com/News/world/archives/2024/10/17/2003825454). 디자인사 채널에서 가짜 SK4 사진 한 장은 채널 신뢰 전체를 깎는다.

**YouTube 공개 의무**: 사실적으로 보이는 변경·합성 콘텐츠(실존 인물이 하지 않은 말·행동, 실제 사건·장소 변경, 일어나지 않은 사실적 장면)는 공개해야 한다. 명백히 비현실적이거나 애니메이션, 색 보정 같은 미적 편집, 대본·아이디어 등 제작 보조는 공개 대상이 아니다. 공개해도 수익·도달에 불이익은 없고, 반복 미공개는 콘텐츠 삭제·파트너 프로그램 정지 사유가 될 수 있다(https://support.google.com/youtube/answer/14328491). → 추상 일러스트·질감에 한정하면 공개 대상에서 벗어나지만, 자산 메타에 `synthetic: true` 를 남기고 업로드 정보에 "AI 생성 이미지 N장(추상 일러스트)" 를 자동 기재하는 편이 안전하다.

**왜 "AI 같다"는 느낌이 나는가**
- 표면이 지나치게 매끈·광택, 조명이 균일, 구도가 평균적(검색 요약: https://news.ycombinator.com/item?id=41262547 등 다수의 관찰 글).
- **특정성이 없다**: "브라운 라디오 같은 것"은 SK4 가 아니다. 디자인 영상의 시청자는 실물을 안다.
- 장면마다 화풍이 미세하게 달라 **시리즈 일관성**이 깨진다.
- 출처·크레딧이 없다(실제 자료는 "출처: …" 가 붙어 증거처럼 읽힌다).
- 연구들은 AI 표시·AI 인상이 신뢰·호감을 낮추는 경향을 보고한다(예: 웹사이트 맥락 https://dl.acm.org/doi/10.1145/3772363.3798849 , 서비스 이미지 https://www.sciencedirect.com/science/article/pii/S0268401225000866 — 초록 수준 확인, 본문 (미확인)).
- 그리고 이 프로그램의 경우 **AI 이미지를 쓰지 않아도** "AI 같다"는 말이 나왔다. 원인은 이미지가 아니라 **실물 증거의 부재 + 템플릿 그래픽의 반복 + 칠판 위 컬러 클립아트**(모션 장면의 Pixabay 벡터)다. 처방은 생성이 아니라 조달이다.

**일관성 기법(쓴다면)**: ① 고정 스타일 프롬프트(매체·팔레트·질감·금지 요소)를 코드 상수로 ② 채널 기준 이미지 3~5장을 **참조 이미지**로 매 호출에 첨부(다중 참조 지원 모델) ③ LoRA(로컬) ④ 생성 후 **채널 공통 후처리**(듀오톤·하프톤·종이 입자)로 실사 자료와 같은 재질로 통일 ⑤ 시드·프롬프트·모델을 자산 메타에 기록.

### B-5. 대본에 이미지 맞추기

1. **문장별 "시각 필요" 분류**(에이전트): `identify`(고유명사 첫 등장) · `show_work`(작품·제품 자체) · `show_detail`(특정 부분) · `compare`(A 대 B, 전/후) · `context`(시대·장소·사람들) · `process`(만드는 과정) · `quote_doc`(문서·책 구절) · `screen`(웹·앱 화면) · `principle_demo`(원리 도식) · `data` · `mood` · `none`.
2. **엔티티 해석**: `name_ko` → `wbsearchentities(language=ko)` → QID → 영어 라벨·별칭·Commons 분류·P18·제작자·연도. 동명이인은 설명(description)과 대본 문맥을 LLM 이 대조해 고른다. QID 를 못 찾으면 `name_en` 으로 재시도, 그래도 없으면 자유 검색.
3. **검색어 생성**: `{영어 라벨} + {연도} + {매체}`("Braun SK 4 1956 radio phonograph"), 제작자 조합("Dieter Rams Braun"), 미술관용 필드 검색(AIC `classification_title=poster`, Rijks `type=poster&creator=`). 기존 `query_variants()` 축약 로직은 재사용.
4. **다중 후보**: 소스별 상위 N(예 8)장씩 모아 엔티티당 20~40장 후보.
5. **게이트**(기계적): 최소 긴 변(풀스크린 1600px·pip 900px) · 종횡비(레이아웃별 허용 범위, 세로 이미지는 버리지 않고 **세로용 트리트먼트**로) · 흐림(라플라시안 분산 — 일반 기법) · 워터마크(LAION 워터마크 검출기, MIT — https://github.com/LAION-AI/LAION-5B-WatermarkDetection) · 라이선스 등급 · 중복(pHash, `imagehash` BSD — https://github.com/JohannesBuchner/imagehash).
6. **관련도 점수**: SigLIP 2(다국어, 코드·가중치 Apache-2.0 로 소개됨 — https://huggingface.co/blog/siglip2 , arXiv 2502.14786)로 `must_show`·문장과 이미지의 유사도. 한국어 문장을 그대로 넣을 수 있다. GPU 가 없으면 건너뛰고 7 로.
7. **비전 LLM 선택**: 기존 `contact_sheet()` + `pick_stock` 을 사진에도 확장. 요청마다 상위 6~9장을 한 장의 시트로, "이 문장의 증거로 맞는가 / 틀린 대상은 아닌가 / 어느 부분을 비출까(초점 상자)"까지 받는다.
8. **다양성**: 같은 엔티티에서 인물 1 + 작품 2~3 + 맥락 1 처럼 **역할이 다른** 장을 고른다(임베딩 MMR 또는 LLM 지시).
9. **채널 자산 라이브러리**: `user/asset_library/{qid}/…` + SQLite 색인(자산 메타는 설계 문서 03 의 8절). 한 번 받은 디터 람스 12장은 다음 영상에서 검색 없이 재사용. 운영자가 직접 넣은 파일(책 촬영본 등)도 같은 색인에 들어간다.
10. **증거 밀도 목표**: "에세이 채널은 분당 몇 장" 같은 공신력 있는 외부 기준은 **찾지 못했다.** 근거로 쓸 수 있는 것은 ① 이 저장소의 레퍼런스 실측(`docs/research/레퍼런스_영상_분석.md`): 참고 채널 평균 **사진·B-roll 29.6%**, 얼굴 단독 30%, 플레이북 목표 B-roll·사진 30% ② 실무 블로그의 경험칙 "3~5초마다 시각 변화", B-roll 3~7초(2차 출처, https://air.io/en/youtube-hacks/advanced-retention-editing-cutting-patterns-that-keep-viewers-past-minute-8 · https://socialrails.com/blog/b-roll-footage-complete-guide). 10분 영상에서 30% = 180초, 한 장 4~5초면 **36~45장(분당 약 4장)** 이 나온다 → 게이트 B1 의 목표(25~30%)와 같은 크기다. 이번 테스트의 실측은 3.5% 였다.

### B-7. 스톡 영상이 뻔해 보이지 않게

- **특정성 규칙**: "Stock is not automatically generic — the problem is usually an imprecise visual choice … search for observable actions and settings rather than abstract themes"(https://www.scenepull.com/blog/stock-footage-vs-b-roll). 검색어는 **관찰 가능한 행동 + 장소 + 화각**("letterpress printer inking metal type close up").
- **금지 목록(편집 판단)**: 악수·전구·화이트보드 앞 회의·노트북 타이핑 손·지구본·톱니바퀴 같은 추상 은유 컷. 디자인 주제에서 쓸 만한 스톡은 **공정·재료·도구·공간**(인쇄기, 활자, 목공, 도면, 공장 라인, 거리의 간판).
- **채널 룩으로 그레이딩**: 스톡끼리, 그리고 본편과 색을 맞춘다(https://artlist.io/blog/how-to-use-stock-footage-when-editing-videos/). 이미 `grade_N.cube` 룩이 있으므로 스톡에도 같은 LUT + 약한 듀오톤을 `prepare_video()` 에서 굽는다.
- **프레임 안에 넣기**: 풀스크린 대신 종이 위 액자·창(마스크) 안에서 재생하면 "채널의 물건"이 된다. 풀스크린은 장면 전환·분위기에만(현행 프롬프트와 일치).
- **짧게**: 1.5~3초 인서트 2~3개가 7초 한 컷보다 낫다. 현재 `NEED_SEC = 8.0`, 템플릿 최대 7초 → 스톡 영상의 기본 길이를 2.5~4초로.
- **속도·크롭**: 90~110% 속도 조정, 1.1~1.3배 크롭으로 구도를 다시 잡는다(초점 상자 재사용).
- **스틸이 나은 경우**: 대상이 **특정 작품·인물·제품**이면 스톡 영상보다 실물 사진이 항상 낫다. 스톡 영상은 "이렇게 만들어진다·이렇게 쓰인다" 같은 **과정·맥락**에만.

- **Rijksmuseum·Getty·NGA 이미지의 권리 조건**과 Rijks·CMA·Wellcome·Crossref·OpenAlex 의 한도 수치.
- **Unsplash**: API 가이드라인의 핫링크 요구와 영상 제작용 다운로드의 관계.
- **AI 모델**: OpenAI 현행 모델명은 공식 가이드 페이지를 요약 모델로 읽은 결과(`gpt-image-2.5-sunburst/flare`)이고 가격·계보는 2차 출처다. FLUX.2 다중 참조 수·klein 라이선스·VRAM 도 2차 출처. 구현 직전에 다시 확인한다.
- **증거 밀도의 외부 기준**: 공신력 있는 수치를 찾지 못해 저장소 내부 실측과 실무 경험칙으로 대신했다. 게이트 수치(15% 하한·25~30% 목표)는 [`08_품질_게이트.md`](../upgrade/08_품질_게이트.md)의 정의를 따른다.
- **CC BY-SA 와 영상**: 개작 여부는 사안별이라 단정하지 않았다. CC FAQ 의 해당 문단은 직접 인용하지 못했다.
- **프레스 이미지 약관**(Apple 등): 포럼 인용(2차). 허용 목록에 넣을 때 원문을 확인한다.
- **로그인 벽이 있는 사이트의 캡처**: 핀터레스트 비로그인 화면을 실제로 캡처해 보지 않았다.
- **타이밍 손실의 초 단위 재현**: 홍익대 사진·노트 스케치 스톡이 최종 props 에 없다는 것과 코드 경로까지 확인했고, 정확한 시작 시각을 다시 계산하지는 않았다.
- 웹 검색 한도에 걸려 일부 항목(패럴랙스·주석 기법의 실무자 해설, 한국저작권위원회의 1인 미디어 안내서)은 추가 확인을 못 했다.
