## 0. 핵심 요약 (10줄)

1. 2026년 사례의 주류는 **Claude Code + 에이전트 스킬** 조합입니다. 스킬은 Remotion 공식 스킬(2026-01-20 공개), HeyGen HyperFrames 스킬, 커뮤니티 스킬(video-use, ai-video-editor 등)로 나뉩니다.
2. 공통 설계는 **"LLM은 영상을 보지 않고 읽는다"** 입니다. 단어 단위 트랜스크립트가 1차 입력이고, 이미지는 필요한 순간에만 봅니다(필름스트립, 파형, 컨택트 시트).
3. 모션그래픽은 세 방식으로 만듭니다. (a) Claude가 TSX/HTML을 매번 직접 작성, (b) 컴포넌트 라이브러리와 JSON 계획, (c) **둘을 섞는 방식**입니다. (c)는 대부분 컴포넌트로 채우고 핵심 장면만 맞춤 제작합니다. 품질이 가장 좋다고 보고된 것은 (c)입니다.
4. 거의 모든 성숙한 스킬이 **"렌더 → 프레임 추출 → Claude가 이미지를 직접 봄 → 수정 → 재렌더(최대 2~3회)"** 루프를 필수로 둡니다.
5. 가장 정교한 검증 설계는 **remotion-director**에서 나왔습니다. 계획 문서를 모르는 비평가(blind critic)가 렌더된 프레임만 봅니다. 모션 인식 샘플링으로 정지된 프레임을 판정하고, 움직이는 중간 프레임은 결함으로 치지 않습니다. 마지막에 별도의 템포 패스로 읽기 시간을 따로 검증합니다.
6. 보고된 함정은 다섯 가지입니다. API 환각과 버전 드리프트, 폰트 조용한 폴백과 CJK 폰트 타임아웃, 누적 A/V 싱크 드리프트, 트랜스크립트 타임스탬프 오차(약 50–120ms), 느린 렌더와 토큰 비용입니다.
7. 디자인 원칙은 **절제**로 수렴합니다. 그래픽은 말이 보여줄 거리를 담을 때만 넣습니다. 한 청크에 강조는 하나, 트랜지션은 주제 전환에서만 씁니다. 입장은 ease-out, 퇴장은 ease-in으로 하고 퇴장을 더 빠르게 합니다. linear는 금지입니다.
8. 한국어 자막 기준(Netflix 한국어 가이드)은 **줄당 16자, 최대 2줄, 성인 12자/초(SDH 14자/초)** 입니다. 앱의 현재 기본값(줄당 18자)보다 엄격합니다.
9. B-roll은 "키워드 매칭 스톡"이 실패 사례로 꼽힙니다. 문장이 **무엇에 관한 것인지** 먼저 해석하고 소스 종류로 라우팅하는 방식이 권장됩니다. Pexels는 구체 명사에만 씁니다.
10. Choi Studio는 이미 구조화 출력 기반 디렉터, 템플릿 17종, 단어 앵커, 로컬 폰트, CFR 프록시를 갖췄습니다. 가장 큰 공백은 **렌더 후 시각 QA 루프와 결정론적 린트**입니다(6장 참고).

## 1. 전제 바로잡기

- **"video-use"** 는 일반 용어가 아니라 **browser-use 팀의 오픈소스 스킬**(`browser-use/video-use`)입니다. 포크가 많아 검색 결과가 어지럽습니다. [원문]
- **HyperFrames** 는 HeyGen의 아바타 기능이 아닙니다. HeyGen이 공개한 **HTML/CSS/GSAP → MP4 오픈소스 렌더러**(Apache 2.0)이고, 에이전트 스킬 21종을 함께 제공합니다. [원문] 최초 공개일은 자료끼리 어긋납니다. 한 검색 스니펫은 2026-05-08을 말하지만, Nate Herk의 X 게시물(ID로 역산하면 2026-04-23)과 Geeky Gadgets 기사(2026-04-21)가 이미 HyperFrames를 다룹니다. **늦어도 2026년 4월 하순에는 공개**된 것으로 봅니다. [미확인]
- "director 에이전트 → 서브에이전트" 구조는 YouTube 영상보다 **GitHub 스킬 문서에서 구체적으로 확인**됩니다. 영상 내용은 볼 수 없어서, 아키텍처 설명은 모두 저장소 원문 기준입니다.
- 스킬마다 권장 API가 다릅니다. 예를 들어 `claude-remotion-skill`은 "`<OffthreadVideo>`만 쓰라"고 합니다. 반면 현재 Remotion 공식 문서와 스킬(4.0.530)은 `@remotion/media`의 `<Video>`를 권장하고 `OffthreadVideo`는 피하라고 합니다. **커뮤니티 스킬을 그대로 믿으면 안 되는 이유**입니다. [원문]

## 3. 워크플로우 아키텍처

### 3.1 공통 뼈대: "읽고, 계획하고, 승인받고, 렌더하고, 스스로 검사"

```
전사(단어 단위, verbatim) → 정리된 읽기용 뷰 → [사람 승인: 전략/스토리보드]
 → 컷(EDL) → 그래픽·B-roll 배치(단어 앵커) → 초안 렌더 → 자체 검사(이미지·수치) → 수정(≤3회)
 → 최종 렌더 → 결과물 검증(ffprobe·라우드니스·재전사) → 보고서(사람만 판단할 항목 명시)
```

- **video-use**: LLM은 영상을 보지 않고 "읽습니다". 모든 테이크를 약 12KB짜리 `takes_packed.md`에 담고, 문구는 0.5초 이상 무음이나 화자 전환에서 끊습니다. 이미지(`timeline_view`: 필름스트립 + 파형 + 단어 라벨)는 판단 지점에서만 봅니다. README는 "30,000프레임 × 1,500토큰 = 4,500만 토큰"을 텍스트 12KB와 PNG 몇 장으로 대체했다고 설명합니다. [원문]
- **승인 게이트**: video-use는 전략 4–8문장을 제안하고 확인을 기다립니다. ai-video-editor는 질문을 1~3라운드에 몰아 하고 4단계부터는 절대 묻지 않습니다. Nate의 make-a-video는 `BRIEF.md` 승인과 미리보기 게이트 2개를 둡니다. clixie는 "스토리보드 먼저는 선택이 아니다, 승인 안 된 렌더는 토큰·CPU 낭비"라고 씁니다. [원문/글]
- **세션 메모리**: video-use는 `project.md`에 세션마다 전략·결정·이유·미해결을 추가합니다. ai-video-editor는 `edit-settings.json`에 사용자의 답을 저장해 재실행 때 재사용합니다. [원문]

**교훈(remotion-director README 요지):**
- 모델은 자기 렌더를 평가할 때 **이미지를 보지 않고 자기 설계 문서를 풀어 말하는** 경향이 있습니다. 같은 모델에게 같은 프레임만 단독으로 보여주면 결함을 잘 찾습니다. 이 때문에 비평가를 구조적으로 격리합니다.
- 비평가는 VLM이라 균일 샘플링을 쓰면 0.5초짜리 깔끔한 텍스트 이동이 "겹친 텍스트" 스틸 여러 장으로 보여 결함으로 오판됩니다. 그래서 렌더된 mp4에서 움직임을 측정해 **정지 구간마다 대표 프레임 1장**과 결함으로 치지 않을 **중간 모션 프레임**을 구분해 보여줍니다.
- 정지 프레임만 보면 0.5초 정지와 3초 정지가 똑같아 보입니다. 즉 **읽을 수 있는지(시간축)는 프레임 루프로 검증할 수 없습니다.** 그래서 템포 패스를 따로 둡니다.
- 금지 규칙만 나열한 엔진("Dogma")은 모든 모델을 **똑같은 추함**으로 수렴시켰습니다. 대신 좋은 디자이너가 가진 지식(서사, 미학, 색, 구성, 템포, 설득, 질감 7축)을 긍정형으로 제공합니다. 순서는 서사를 먼저 고정하고 질감을 마지막에 둡니다. [원문]

### 3.4 품질 검증 방식

**시각 검증(Claude가 이미지를 직접 봄)**
- claude-remotion-skill: 핵심 프레임을 `npx remotion still … --frame N`로 뽑거나 `ffmpeg -ss`로 mp4에서 추출합니다. 가장 흔한 버그 순서대로 봅니다: em 단위 간격, 가장자리 닿음, 진입 전 노출(clamp 누락), 대비, 레이어 순서. [원문]
- claude-youtube-editor(`vidtsx-2d-generator`, `make-tsx`): 60% 지점 스틸 한 장으로는 부족합니다. 타이밍 기반 리빌은 **각 큐 시점마다** 프레임을 뽑고, 원본 위에 합성된 최종본에서도 샘플을 확인합니다. [원문]
- ai-video-editor `review.md`: 행 하나가 비트 하나이고, **진입·정점·퇴장** 3프레임을 봅니다. 체크리스트 8개는 ①Fit ②Readable ③Mouth clear ④Face in frame ⑤Arrived(정점에서 요소 도착) ⑥Sync ⑦Transitions ⑧Taste이고, 시트 전체에는 리듬(그래픽 3개 연속 금지)과 훅을 봅니다. 문제별 수정 방법 표가 있고 3라운드에서 멈춥니다. [원문]
- video-use: **렌더 결과물**(소스가 아님)의 모든 컷 경계 ±1.5초를 `timeline_view`로 봅니다. 시각 점프, 파형 스파이크(팝), 오버레이에 가린 자막, 잘못된 오버레이 프레임을 찾고, 처음·끝 2초와 중간 2–3곳을 추가로 봅니다. 최대 3회이고, 남은 문제는 사용자에게 보고합니다. [원문]
- b-roll-finder: 각 비트 중간점과 이음새 프레임을 그리드 한 장으로 타일링해 봅니다. B-roll 매니페스트를 두어 승인된 비트가 버전 사이에 사라지지 않게 합니다. [원문]
- Remotion 공식 스킬: `npx remotion render <id> out/frames --frames=0,30,90 --image-format=png`로 **여러 프레임을 한 번에** 뽑을 수 있습니다. [원문]

**결정론적 검증(LLM 없이)**
- ai-video-editor `edit-plan.mjs check`: `word`가 없는 항목, 그래픽이 보이는 동안 말해지지 않는 단어, 가장 긴 정지 구간, 맞춤 장면 수를 검사합니다. `verify.mjs`: 결과물을 **다시 전사해 기대 텍스트와 단어 단위로 비교**하고(필러 잔존·단어 잘림), 크기와 프레임 시트를 확인합니다. 음악 대비 음성 여유를 측정하고, 하위 10%가 12dB 미만이면 재렌더합니다. [원문]
- claude-youtube-editor `verify_cut`: 고스트 발화(전사되지 않은 에너지)를 찾고, **`v:0` 길이와 `a:0` 길이가 같아야 통과**합니다. [원문]
- video-use: `ffprobe`로 EDL 기대 길이와 비교하고, `ebur128`로 통합 라우드니스·트루피크와 구간별 RMS를 측정합니다. "들을 수 없으니 수치를 보고하라"는 규칙입니다. [원문]
- HyperFrames: `lint`(구조와 결정론 규칙), `check`(WCAG AA 대비), 캡션 `check-timing --strict`(전사 대비 80ms 이내), 그룹 창이 단어를 감싸는지 검사합니다. [원문]
- 타입체크: `tsc --noEmit`을 세션마다 돌리라는 일반 권고가 있습니다(Remotion 특화 출처는 아님). [스니펫]

### 3.6 자막

- **Remotion 공식**: 자막은 `Caption` JSON(`text`, `startMs`, `endMs`, `timestampMs`, `confidence`, `pageBreakAfter?`)으로 다루고, 단어 앞 공백까지 `text`에 넣습니다. `createTikTokStyleCaptions`의 `combineTokensWithinMilliseconds`가 크면 한 페이지에 여러 단어가 들어가고, 작으면 단어 단위가 됩니다. 페이지의 token별 `fromMs`/`toMs`로 현재 단어를 강조합니다. 기본 전사는 `@remotion/whisper-webgpu`이고 **다국어는 `language`를 명시해야** 합니다(자동 감지 불가). [원문]
- **video-use 스타일 두 가지**: `bold-overlay`(숏폼: 2단어, 대문자, 0.3초 이상 쉼에서 끊고 0.35초 미만 큐는 3단어로 늘림)와 `natural-sentence`(**교육·다큐: 4–7단어, 문장체, 자연스러운 쉼에서 끊고, 글자 크게, 하단 여백 60–80**)입니다. 자막은 **모든 오버레이 뒤에 마지막으로** 입힙니다(하드룰 1). [원문]
- **HyperFrames `rail`(기본 자막 트랙)**: ≤2줄(영문 기준 줄당 32–42자), 단어 중간이나 한 단어만 남는 줄에서는 끊지 않음, 그룹당 0.5초 이상, 전사 대비 80ms 이내, 글자 크기 약 `0.045 × 화면 높이`(1080p에서 약 48px), 산세리프 500–600, 150–250ms 페이드, **글리치·스케일 팝·단어별 안무 금지**. 강조 단어는 색·굵기 또는 ≤1.1배 팝만 허용합니다. 가독성 처리는 **글자 박스 크기의** 스크림·그림자로 하고, 영상 전체 그레이딩은 금지합니다. [원문]
- **HyperFrames 그룹핑**: 500ms 이상 쉼, 문장 끝, 250ms 이상 쉼이 붙은 쉼표, 담화 전환어, 6단어 또는 2.5초에서 끊습니다. `in = 첫 단어 시작 − 0.08초`, `out = min(다음 in − 0.05, 마지막 단어 끝 + 0.6)`. 최소 2단어·0.5초, 겹침 금지입니다. **여러 단어를 한 엔트리에 묶지 말 것**(두 번째 단어가 일찍 뜸). **그룹 창이 단어를 감싸지 않으면 800ms 지연 버그**가 실제로 났다고 합니다. [원문]
- **"embed"(피사체 뒤 자막)는 희소해야** 합니다. 비트당 1개 이하, 동시 노출 금지, 0.6초 이상 간격이고, 설명형 영상은 레일 위주로 합니다. "모든 단어를 임베드하는 것이 가장 흔한 실수"라고 합니다. [원문]
- **ai-video-editor**: 청크당 강조 단어는 **하나까지**이고 숫자·이름·강한 단어만 강조합니다("things", "really" 같은 단어는 금지). 이모지는 그 단어를 그림으로 보여줄 때만, Dynamic 스타일에서 8초에 1개까지 쓰고 Clean/Cinematic에서는 쓰지 않습니다. 자막은 **입이 가장 낮게 내려가는 지점보다 아래**, 플랫폼 UI 영역 밖에 둡니다. 청크 최대 단어 수는 Dynamic 3(대문자), Clean 5, Cinematic 6입니다. [원문]
- **한국어 기준(Netflix Korean Timed Text Style Guide)**: 줄당 **16자**(라틴 문자·공백·문장부호는 0.5자로 계산), **최대 2줄**, 읽기 속도 성인 **12자/초**(SDH·동일언어 자막은 14자/초), 줄바꿈은 아래가 넓은 피라미드 모양을 선호합니다. [원문]
- 한국어 단어 타임스탬프(WhisperX 등)의 정확도를 따로 측정한 자료는 **찾지 못했습니다.** [미확인]

## 5. 권장 모션·자막 디자인 원칙 (출처별 합의점)

### 5.1 Easing
- **linear 금지**(video-use, claude-remotion-skill). 단 진행바·타자 같은 "rate 기반" sweep만 linear(robotostudio).
- 방향 규칙: 입장은 `.out`, 퇴장은 `.in`, 위치 이동은 `.inOut`입니다. 입장에 ease-in을 쓰면 굼뜨고, 퇴장에 ease-out을 쓰면 미적거리는 느낌이 납니다. (HyperFrames motion-principles)
- Remotion 공식 기본값: `Easing.bezier(0.16, 1, 0.3, 1)`, 튕김 없는 밀기에는 `Easing.spring({damping: 200})`, **scale 애니메이션에는 `output: 'perceptual-scale'`**(선형 스케일은 크게 갈수록 덜 커 보임). 의도적 저프레임에는 `posterize`. [원문]
- "모든 트윈에 같은 ease를 쓰지 말라". 한 장면에서 같은 ease를 쓰는 독립 트윈은 2개 이하로 둡니다. ease는 감정을 결정합니다(`expo.out`=자신감, `sine.inOut`=몽환, `elastic`=장난). (HyperFrames)
- robotostudio 토큰 예: enter는 out-quint 0.5초, exit는 in-cubic 0.3초, move는 in-out-cubic 0.6초, sweep은 linear.

### 5.2 타이밍
- **퇴장은 입장보다 빠르게**(예: 0.4초 대 0.25초, 약 20프레임 대 약 10프레임).
- 스태거는 3–6프레임(claude-remotion-skill)입니다. 전체 스태거 시퀀스는 항목 수와 상관없이 500ms 이하로 하고, 중요도 순서로 먼저 움직입니다(HyperFrames).
- t=0에서 시작하지 말고 0.1–0.3초 오프셋을 둡니다(HyperFrames).
- 장면 구조는 **Build 0–30% / Breathe 30–70%(주변 모션 하나) / Resolve 70–100%** 입니다(HyperFrames).
- 가독 시간: 내레이션 동기 카드는 **최소 3초, 단순 카드 5–7초, 복잡한 도식 8–14초**입니다. 마지막 프레임은 1초 이상 유지하고, 보이스오버 위라면 `내레이션 길이 + 1초` 이상 둡니다(video-use). "화면에 3초 있다면 2초 안에 읽혀야 한다"(HyperFrames typography).
- **독립 요소 두 개를 동시에 드러내지 말 것**: 하나 보여주고, 쉬고, 다음(video-use).
- 단어 착지: 애니메이션 그래픽은 **단어에 맞추되 최대 2프레임 일찍**(ai-video-editor)입니다. 결과(payoff) 단어 타임스탬프에서 `reveal_duration`만큼 앞당겨 시작해 착지 프레임이 그 단어와 일치하게 합니다(video-use). 반면 **컷어웨이 B-roll은 +0.2–0.5초 늦게**(b-roll-finder)입니다. → [해석] 움직이며 도착하는 그래픽은 약간 이르게, 하드컷 B-roll은 약간 늦게.
- 토킹헤드 카드 페이스(HyperFrames talking-head-recut): 영상 길이별 기본 카드 간격은 3–10분 12–20초, **10–30분 20–35초**입니다. 정보 밀도가 높으면 ×0.7, 낮으면 ×1.5를 곱하고 최소 5장입니다. 15초 넘게 떠 있는 카드는 여러 단계 리빌로 풍부하게, 8초 넘는 정적 한 줄은 지루합니다.

### 5.3 절제(Restraint)
- **그래픽은 말이 보여줄 거리를 담을 때만** 넣습니다. 목록→카드/리스트, 숫자→카운트업, 대비→비교, 과정→단계, 핵심 개념→아이콘 하나, 기억할 주장→인용, 인물→로어서드처럼 매핑합니다. 인사·여담·연결 문장은 화자만 보여줍니다. (ai-video-editor craft)
- 프리셋별 예산(ai-video-editor): **Clean premium은 5–7초마다 변화, 그래픽 비율 15–35%**, 트랜지션은 slide/dip/zoom, 효과음 적게. Cinematic은 7–9초, 8–25%. [해석] 교양 강의 톤에는 Clean premium이 가장 가깝습니다.
- **트랜지션은 주제가 바뀔 때만**, 최대 8–14초에 1회입니다. 효과는 순간을 표시할 때 하나만 쓰고 겹치지 않습니다. (ai-video-editor)
- 리듬: 화자가 가려지지 않는 구간 없이 **그래픽 3개 연속 금지**(review.md).
- 색: 베이스, **히어로 색 하나**, 액센트 하나로 60/30/10 비율입니다. 히어로 색은 한 프레임에 한 요소만 씁니다. 글로우는 히어로 요소에만 씁니다(claude-remotion-skill). 액센트는 2색 이하, 빈 공간은 약 40%입니다(video-use 예시).
- 정적 상태에서의 차이: "계속 움직이면 아마추어, 대비가 있어야 비싸 보인다". **정지(hold)는 디자인 도구**입니다(claude-remotion-skill). "움직임 뒤의 정지는 강력하다", 모든 장면에 주변 줌을 쓰지 말라(HyperFrames).
- "AI 티" 목록(ai-video-editor): 모든 게 같은 방식·같은 속도로 움직임, 말과 안 맞는 일반 B-roll, 줄마다 이모지, 컷마다 효과, 음성 위 음악, 이름 오타, 앱 버튼 아래 텍스트, 입을 가린 자막, 늦게 도착한 그래픽, 죽은 첫 프레임.
- 게으른 기본값(HyperFrames house-style): 그라디언트 텍스트, 카드 왼쪽 액센트 줄무늬, 시안-온-다크·보라→파랑 그라디언트, 순수 #000/#fff, 같은 크기 카드 그리드, 모두 가운데 정렬.
- 주의: Nate Herk의 `MOTION_PHILOSOPHY`(장면 평균 1.5초, 화면 90% 검정, 크롬 그라디언트 헤드라인, 매 장면 모션블러 휩)는 **30초 광고 스팟** 기준입니다. **교육용 롱폼에 그대로 쓰면 과합니다.** [해석]

### 5.4 타이포그래피
- 영상 크기는 웹 크기가 아닙니다. 풀스크린 기준 본문 20px 이상, 헤드라인 60px 이상, 피드(모바일) 기준 본문 32px 이상, 헤드라인 90px 이상입니다(HyperFrames). 1080×1920 히어로 80–140px, 1920 가로 100–160px, 웨이트 600–800, 자간 −0.03em, 행간 1.05(claude-remotion-skill). 헤드라인 72–120px, 본문 28–36px, 텍스트에 `margin:0`(vidtsx).
- **웨이트 대비는 극단적으로**(300 대 900). 두 산세리프를 짝짓지 말고, 장면당 표현적인 폰트는 하나만 씁니다. 디스플레이 크기는 자간을 −0.03~−0.05em으로 줍니다(인코딩이 디테일을 뭉갬). (HyperFrames typography)
- **헤드라인당 강조는 한 단어**: 히어로 색, 밑줄, 또는 단어 착지 5프레임 뒤 뒤편에 알약 모양 배경(claude-remotion-skill). 숫자는 `tabular-nums` 카운터로.
- 타자 효과는 부분 문자열 폭이 아니라 **전체 문자열 폭 기준으로 중앙 정렬**합니다(그렇지 않으면 글자가 옆으로 미끄러짐). 입장 시 `letter-spacing`이나 `filter:blur` 애니메이션은 줄 튐을 일으킵니다. (video-use, embedded-captions)

### 5.5 오디오(참고)
- 효과음은 **보이는 사건에만** 붙입니다. 18초에 약 20개면 싸구려로 들리고 약 8개면 설계된 느낌입니다. 효과음 attack만큼 먼저 시작합니다. 음악은 음성 아래 −12~−15dB 더킹하고, 최종 믹스는 2-pass loudnorm으로 −14 LUFS·TP ≤ −1dBTP에 맞춥니다(video-use). 음성은 음악보다 12dB 이상 크게(ai-video-editor).

## 6. 적용 제안 (Choi Studio 기준, 우선순위순)

현재 저장소(`CLAUDE.md`, `README.md`, `studio/`, `renderer/`)를 훑어본 결과, 이미 갖춘 것은 다음과 같습니다. 구조화 출력 디렉터(`studio/director/schema.py`), 단어 앵커(`start_seg`/`start_word`), 템플릿 17종, 모션 토큰(`renderer/src/design/motion.ts`), 로컬 Pretendard(`@remotion/fonts`), CFR 프록시(GOP 15, B프레임 0), 샘플 단위 오디오 컷, 계획 캐시와 "편집 계획만" 워크플로우입니다. 아래 제안은 이것을 전제로 **빠진 부분**에 집중합니다.

### P0: 먼저 할 것 (품질·안정성에 직결)

1. **렌더 후 시각 QA 단계(`review`) 추가**
   - 그래픽 비트마다 **진입 끝·정점·퇴장 직전** 프레임을 `npx remotion render <id> out/f --frames=a,b,c --image-format=jpeg`로 한 번에 뽑습니다.
   - 비트당 한 행씩 컨택트 시트(긴 변 ≤ 2576px)로 묶어 Claude 비전에 보냅니다. 체크리스트는 ai-video-editor의 8개(Fit·Readable·Mouth·Face·Arrived·Sync·Transitions·Taste)입니다.
   - 결과는 **plan.json 패치(JSON 스키마)** 로만 받습니다. TSX를 고치게 하지 않습니다.
   - 바뀐 비트만 다시 렌더하고, 최대 2–3라운드 후 남은 문제는 편집 리포트에 기록합니다.
   - [해석] 참고로, Claude API 스킬 번들 문서에 따르면 Opus 5 계열 고해상도 비전은 긴 변 2576px, 이미지당 최대 약 4,784 토큰입니다. 또 Opus 5.5는 low effort에서도 차트·도식을 정확히 읽는다고 합니다.
2. **블라인드 비평가 원칙 적용**
   - QA 호출에는 **프레임, 해당 구간 전사, 한 줄 채널 브리프만** 넣습니다. 디렉터의 계획 근거(`reason`)나 스타일 가이드 전문은 넣지 않습니다.
   - 같은 비평 대화(persistent)를 라운드 사이에 유지하고, 수정 요청은 디렉터에게 글자 그대로 전달합니다(remotion-director).
3. **모션 인식 프레임 선택**
   - 이미 계획(`plan.json`)에서 각 그래픽의 진입 끝 시점을 알 수 있습니다. 그러니 "정지 프레임"은 진입 애니메이션이 끝난 뒤로 고릅니다.
   - 전환 중 프레임을 보낼 때는 "모션 중, 결함 아님"이라고 라벨을 붙입니다.
4. **렌더 전 결정론적 린트(`plan lint`)**: LLM 호출 없이 싸게 막을 수 있는 것부터 막습니다.
   - (a) 모든 그래픽 항목의 앵커 단어가 표시 구간 안에서 실제로 발화되는지
   - (b) 자막 그룹 창이 단어를 감싸는지(`in ≤ 첫 단어 시작`, `out ≥ 마지막 단어 끝`)
   - (c) 자막 최소 표시 0.5초 이상, 겹침 없음
   - (d) 한국어 CPS ≤ 12(엄격) 또는 14(동일언어 자막 기준)
   - (e) 그래픽 커버리지 비율, 가장 긴 무변화 구간, 연속 그래픽 3개 금지
   - (f) 트랜지션은 챕터 경계에서만
   - (g) 텍스트 박스 오버플로(`fitText`/`fillTextBox`)
   - 위반하면 디렉터에게 자동으로 재요청하거나 규칙 기반으로 보정합니다.
5. **폰트 로드 단언**
   - 현재 `tokens.ts` 폴백 체인에 "Malgun Gothic"이 있어서, Pretendard 로드가 실패하면 **조용히** 맑은 고딕으로 렌더됩니다.
   - 컴포지션 시작 시 사용하는 웨이트마다 `document.fonts.check('<weight> 48px "Pretendard"')`를 확인하고, 실패하면 throw합니다.
   - `measureText`에는 `validateFontIsLoaded: true`를 씁니다(현재 `lib/fit.ts`는 근사 폭 계산).
   - Google Fonts CJK로 바꾸지 말고 지금처럼 로컬 woff2를 유지합니다(CJK 타임아웃 이슈).
6. **결과물 게이트**
   - `ffprobe`로 `v:0` 길이와 `a:0` 길이가 같은지 확인합니다(누적 허용치를 쓰지 말 것).
   - `ebur128`로 통합 라우드니스와 트루피크를 측정하고, 섹션별(대사·엔드카드) RMS 차이를 리포트에 기록합니다.
   - 롱폼 결과물을 **다시 전사해 정렬 대본과 비교**합니다. 잘린 단어, 남은 NG, 고스트 발화를 찾는 용도입니다(ai-video-editor verify, clean-cut).
7. **컷 경계 안전장치 재점검**
   - 컷 가장자리에 30–200ms 패딩을 둡니다(차분하게 프리셋은 약 50ms 앞, 80ms 뒤부터).
   - 마지막 단어 `end`를 미디어 길이로 clamp하고, 400ms 이상 무음을 우선 컷 지점으로 씁니다.
   - 전문용어 사전을 Whisper `initial_prompt`나 hotwords로 쓰고 있는지 확인합니다(clean-cut의 keyterms).

### P1: 다음 단계 (디자인 품질)

8. **착지 규칙 분리**
   - 도식·키워드 슬램 같은 **애니메이션 그래픽은 앵커 단어보다 0–2프레임 이르게 착지**하도록 시작 시각을 `단어 시작 − reveal_duration`으로 역산합니다.
   - 자료 사진 **컷어웨이는 단어보다 0.2–0.5초 늦게** 들어가게 합니다.
9. **"교양 톤" 절제 예산을 프롬프트와 린트에 수치로 넣기**
   - 그래픽 커버리지 15–35%, 5–7초마다 화면 변화(카메라 레벨·그래픽·자막 강조 중 하나), 트랜지션은 챕터 경계에서만, 자막 청크당 강조 1단어, 이모지 금지.
   - 금지 목록은 "AI 티 나지 않게" 같은 일반 지시 대신 **구체 패턴 이름으로** 적습니다(예: 그라디언트 텍스트, 카드 좌측 액센트 바, 모든 요소 y+페이드 동일 진입). [해석] Claude API 문서도 Opus 5.5가 "구체 패턴을 명시한 금지"에 잘 반응한다고 합니다. 반면 금지만으로 스타일을 정의하면 한 가지 추함으로 수렴한다는 remotion-director의 경고도 있습니다. 그러니 **긍정형 원칙과 구체 금지를 함께** 씁니다.
10. **맞춤 장면(bespoke) 슬롯 도입(하이브리드)**
    - 챕터마다 핵심 개념 비트 1–2개(전체 그래픽 비트의 약 3분의 1까지)는 템플릿 대신 Claude가 **kit·토큰만 쓰는 TSX 장면**을 작성하게 합니다.
    - 게이트: 허용 import 화이트리스트 → `tsc --noEmit` → 금지 패턴 정적 검사(`useState`, `Math.random`, CSS transition, 비단조 `interpolate`) → 스틸 렌더 → 시각 QA. 하나라도 실패하면 템플릿으로 폴백합니다.
    - 장면들은 병렬 서브호출로 만들고, 브리프는 video-use의 10개 항목 형식을 씁니다.
11. **kit/토큰 강제와 오래된 컴포넌트 삭제**
    - `design/motion.ts`의 EASE·STAGGER·SPRING을 역할 토큰(enter/exit/move/sweep)으로 이름 붙입니다.
    - 템플릿이 임의의 숫자를 쓰지 못하게 하고, 안 쓰는 변형은 삭제합니다(robotostudio: "import할 수 있으면 쓰인다").
12. **템포 패스(읽기 시간 검증)**
    - 계획을 확정한 뒤, 그래픽마다 `한국어 글자 수 ÷ 12자/초`와 도식 복잡도로 필요 표시 시간을 계산합니다(단순 카드 5–7초, 복잡한 도식 8–14초, 마지막 프레임 1초 이상 유지).
    - 부족하면 늘리거나 단계형 리빌로 나눕니다. 시각 QA와 **별도로**(시간축은 프레임으로 못 봄) 돌립니다.
13. **한국어 자막 파라미터 조정**
    - 롱폼: `max_chars` 18 → **16 검토**(Netflix 기준, 라틴·공백·문장부호 0.5자 계산), 2줄 아래가 넓은 피라미드, CPS 상한 추가, 150–250ms 페이드, 강조는 색이나 ≤1.1배만(HyperFrames rail).
    - 숏폼: 2–3 어절 청크(현재 14자, 3단어)는 유지하되, 0.35초 미만 큐는 다음 단어와 합칩니다(video-use).
    - 자막은 항상 **최상위 레이어**이고 입 아래에 둡니다.
14. **Remotion 렌더 성능 점검**
    - `npx remotion benchmark`로 concurrency를 정합니다.
    - 현재 `OffthreadVideo trimBefore` 기반인데, 공식 문서가 권장하는 `@remotion/media` `<Video>`와 **같은 프록시로 A/B 벤치마크**합니다(싱크 규칙이 있으니 바꾸기 전에 프레임 정확도를 검증).
    - 그레인·블러·box-shadow는 미리 렌더한 텍스처로 바꿀 수 있는지 봅니다.
15. **B-roll 소스 확장(선택)**
    - 현재 로컬 폴더 → 위키미디어 순서에 **Pexels 영상**을 3순위로 추가하되, 조건은 "구체 명사, 분위기 컷"뿐입니다. 추상 디자인 개념(게슈탈트, 위계, 대비)은 템플릿 도식으로 라우팅합니다.
    - Claude가 비트마다 "이 문장은 실제로 무엇에 관한가" 1문장과 영어 검색어 2–3개를 만들고, 후보 썸네일을 비전으로 순위를 매깁니다(워터마크·AI 생성 여부 점검).
    - 출처는 리포트와 설명란에 표기하고, 검색 결과를 캐시합니다(시간당 200회 한도).
    - "틀린 B-roll보다 없는 게 낫다"를 기본값으로 둡니다.
16. **정지 이미지 모션 품질**
    - 자료 사진 켄 번스는 Remotion 안에서 float 스케일(1.00→1.04)로 처리합니다. ffmpeg `zoompan`(정수 스텝 떨림)은 쓰지 않습니다.
    - 같은 요소에 진입 트윈과 켄 번스를 동시에 걸지 말고 부모·자식으로 분리합니다.

### P2: 운영·비용

17. **스토리보드 스틸 미리보기**
    - "편집 계획만" 단계 뒤에, 그래픽 비트별 정점 스틸 **1장씩만** 렌더해 GUI에 그리드로 보여줍니다.

    - 다음 회차 디렉터 호출에 요약으로 넣어 **채널 취향을 학습**시킵니다(video-use, Louise 사례: "편집 스타일은 글쓰기처럼 개인적").
20. **사람이 판단할 항목을 리포트에 명시**
    - 페이싱의 느낌, 그래픽의 느낌, 음악 취향은 측정할 수 없다고 명시하고, 사용자가 볼 타임코드 목록을 줍니다(ai-video-editor 보고 방식).

    - 디렉터가 만드는 숫자·연도·인명(예: "1956년 디터 람스")은 대본이나 메모에 있는 것만 허용하고, 없으면 스켈레톤 표기나 삭제로 처리합니다(motion-broll의 "숫자를 지어내지 않는다").

## 7. 반대 증거와 리스크

- **편향된 출처**: cutback.video는 경쟁 제품(Selects) 판매사이고, MindStudio·nemovideo·dplooy류는 SEO 콘텐츠 성격이 강합니다. Tella 사례는 Tella 직원(Louise)의 채널입니다.
- **자동 비평의 한계**: 프레임 기반 비평은 **소리와 페이싱을 판단하지 못합니다**(remotion-director가 명시). robotostudio는 에이전트가 두 미학 방향을 모두 완벽히 실행했지만 **어느 쪽이 맞는지 의견이 없었다**고 보고합니다. 취향 결정은 결국 사람의 몫입니다.
- **완전 자동의 한계**: clixie는 숏폼 페이싱이 불안정해 "올리지 않겠다" 수준의 반복이 필요했다고 하고, sabrina.dev는 자동 블루퍼 제거가 거칠었다고 합니다. 한국 사례(Threads)도 불필요 발화 제거는 "보고 후 사람이 결정"합니다.
- **스킬 간 모순**: `OffthreadVideo` 대 `<Video>`, 착지 타이밍(이르게 대 늦게), 광고용 고에너지 규칙 대 교육용 절제처럼 규칙이 서로 부딪칩니다. 출처의 맥락(광고, 쇼츠, 롱폼)을 확인하지 않고 합치면 안 됩니다.
- **비용 변동성**: 에이전트형 반복(장면당 컨텍스트 거의 전부, 작업당 26만 토큰 이상)은 API 과금으로 옮기면 비쌀 수 있습니다. Choi Studio의 "구조화 출력 1–2회 + 템플릿" 방식이 비용 면에서는 유리하므로, 코드 생성형 맞춤 장면은 **소수의 핵심 비트로 제한**하는 편이 안전합니다. [해석]

## 8. 조사의 한계

- **YouTube 영상 내용은 확인하지 못했습니다**(프록시 차단). 제목과 채널은 oEmbed로 확인했고, 날짜는 검색 스니펫뿐이며 일부는 [미확인]입니다. Nate Herk의 28분 튜토리얼 YouTube URL은 찾지 못했습니다.
- Medium(Joe Njenga, Chris McKenzie), wikidocs, aisolutions.kr, dplooy는 403·429·로딩 화면 때문에 본문을 읽지 못했습니다.
- 한국어 전용 근거가 부족합니다. **WhisperX/faster-whisper의 한국어 단어 타임스탬프 정확도** 측정 자료, 한국어 교육 채널이 Claude로 모션그래픽을 만든 구체적 사례 문서(GitHub 수준)는 찾지 못했습니다. 한국 사례는 입문 영상, 강의 광고, GPTers·브런치 글 정도입니다.
- HyperFrames 최초 공개일, Remotion 스킬 설치 수(12.6만~15만), "48시간 600만 뷰"는 [2차 인용]이거나 자료끼리 어긋납니다.
- GitHub 별 수는 조사 시점 페이지 기준이며 변동됩니다.
- 직접 확인하려면: 각 YouTube 영상의 설명란과 고정 댓글(연결 저장소), remotion.dev/prompts 갤러리, HyperFrames Discord, GitHub 이슈 탭(`remotion-dev/remotion` "font", "CJK")을 보면 됩니다.
