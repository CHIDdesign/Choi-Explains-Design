## 0. 요약

1. **세 저장소 모두 존재하고 비어 있지 않다.** animate-skill 은 웹 UI 용(라이선스 없음 → 원칙만), claude-remotion-skill 은 30초 프로모용 Remotion 스킬(MIT), ClaudeAnimationBase 는 손그림 캐릭터 단편용 킷(MIT)이다. 그대로 옮길 것은 수치가 아니라 **이유**다.
2. 가장 큰 수확은 ClaudeAnimationBase 의 진단이다: 모델이 만든 움직임은 **모든 부품이 동시에, 같은 곡선으로, 같은 양만큼, 너무 빨리** 움직이고, 시청자가 이해하기 전에 끝난다. 해법은 장면마다 시청자가 이해할 것을 순서대로 적은 **reads 타이밍 표**(한 번에 하나, 각각 찾는 시간 + 읽는 시간 + 여유)와, 렌더한 **모든 프레임을 나란히 보는 스트립 검수**다.
3. Choi Studio 는 지금 **움직임을 아무도 보지 않는다**: 검수는 그래픽당 안착 스틸 1장이고(`pipeline.py stage_qa`), 타이밍 린트가 없고, 모션 예시는 3개뿐이다. 렌더러에 기법을 더하기 전에 이 셋(예시·린트·스트립 검수)을 먼저 고쳐야 한다(§9 P0 1~4).
4. "템플릿 티"의 원인은 2차 대조에서 고쳤다(§4). 맞은 것: 전체화면 그래픽이 전부 같은 와이프로 들어오고, 그래픽끼리 이어지지 않고, 예시 3개의 구조가 그대로 되풀이된다. **틀린 것: "진입이 한 속성뿐이라 기계적이다", "앞에 몰리고 얼어 있다".** 실제 스펙의 진입은 섞여 있었고 말에 맞춰 나눠 왔다. 실제 원인은 요소가 작고(잉크 9~16%), 글자가 24~27px 이고, 0.5초에 제목 하나뿐이고, 컬러 클립아트와 `pop` 을 쓴 것이다.
5. "이미지가 적다"는 느낌에는 **있는 이미지가 죽어 있는 것**도 한몫한다: 사진은 전부 얼굴 옆 작은 액자이고 선형 줌 1→1.05 하나뿐이다. 사진 한 장을 두 층(미리 흐린 배경 + 프린트)으로 나누고 방향을 교대하는 것, 여러 장이 말에 맞춰 쌓이는 것, 문서 한 줄에 표시하고 다가가는 것이 레시피다(06d A1~A3).
6. 곡선은 네 출처가 비슷한 값으로 수렴한다: 등장 `bezier(0.16,1,0.3,1)`, 이동 `(0.83,0,0.17,1)`, 퇴장 `(0.7,0,0.84,0)`. **채택값은 06 6-1 이다**(등장 `0.22,1,0.36,1` · 글 리빌 `0.16,1,0.3,1` · 이동 `0.2,0,0,1` · 퇴장 `0.3,0,0.8,0.15`). Choi 는 토큰 파일이 둘(`motion.ts`, `lib/anim.ts`)이다. 설치본 Remotion 4.0.530 에 `Easing.spring`, `output:'perceptual-scale'`, `posterize` 가 있는 것을 형 정의로 확인했다.
7. `@remotion/paths` 와 `@remotion/layout-utils` 는 **설치만 돼 있고 import 가 0건**이다. 펜 끝이 따라가는 선 그리기, 경로 따라 이동, 도형 모프, 글자 폭 실측이 의존성 추가 없이 된다. GSAP 3.15.0 패키지에도 SplitText·MorphSVG·DrawSVG 가 들어 있다(무료).
8. HyperFrames 의 모션 교리(기존 조사가 다루지 않은 부분)는 차분한 채널과 잘 맞는다: 튀는 이징 금지, 묶음 스태거 총합 0.5초, **그래픽 사이에는 퇴장 없이 전환이 퇴장**, 주 전환 하나를 60~70%로 반복, 읽는 시간 = 0.6~1.5초 + 글자당 0.03~0.06초, 카메라는 판 하나·작성자 하나, 나쁜 움직임보다 정지.
9. 출처끼리 충돌하는 곳(숨쉬기, 퇴장, 스프링, 켄 번스 크기)은 §10-1 에 선택과 이유를 적었다. 프로모용 규칙(90프레임마다 새 요소, 모든 것에 스태거)은 펀치 구간·숏폼·오프닝 하이라이트에만 쓴다.
10. 산출물: 이 노트(근거) → `docs/upgrade/06c_모션_검수_파이프라인.md`(reads 표 · 린트 26규칙 · 스트립 검수, 실제 스펙 5개에 돌린 결과) · `06d_애니메이션_레시피.md`(형 검사를 통과한 레시피와 DSL 추가 요청) · `prompts/examples/모션_예제_후보.md`(오늘의 DSL 로 쓴 예제 10개) · `claude-skills/choi-motion-scene`·`choi-motion-review`. 이 노트의 §5·§7·§9 는 1차 제안으로 남긴다.

### 2-2. JohnHeibel/ClaudeAnimationBase — "시청자를 모델링하라"

#### (2) "코드로 쓴 움직임이 기계적인 이유" [C `ANIMATION_GUIDE.md` Animation principles]

가이드의 진단 한 줄: 코드는 **모든 부품을 동시에, 같은 곡선으로, 같은 양만큼** 움직인다. 고전 원칙을 이 문제의 해법으로 다시 쓴다.

- **예비 동작**: 큰 움직임 전에 반대 방향으로 작게. 어디를 볼지 알려 준다.
- **느리게 출발·느리게 도착**: 맨 `lerp` 는 금지, 진행도를 이징에 통과시킨다.
- **무게**: 무거운 것은 늦게 출발·늦게 멈추고 거의 안 튄다. 가벼운 것은 휙 움직이고 튀고 파르르 멈춘다 → 요소 크기에 따라 스프링 질량을 다르게.
- **호(arc)**: 직선 이동 금지. `arcPt(p0,p1,h,k)` = 직선 보간 − `h·4k(1−k)`.
- **겹치는 동작·따라가기**: 눈이 먼저, 몸이 뒤, 팔·모자·꼬리는 끌려가다 지나쳐 멈춘다 — 부품마다 시작을 조금씩 어긋나게.
- **쌍둥이 금지(twinning)**: 코드가 값을 복사해 두 팔이 같은 각도, 군중이 같은 박자로 튄다 → 한쪽에 주동작, 다른 쪽은 작게, 위상·시드를 어긋나게.
- **과장**, **강한 키 포즈**(정지 화면으로 먼저 읽혀야 함), **생각을 보여 줌**(알아차림 → 생각 → 행동), **보조 동작**(주동작과 경쟁하지 않게).

#### (3) 시간의 순수 함수로 쓴 모션 헬퍼 [C `src/core.js`]

프레임이 병렬·순서 없이 렌더되므로 모든 헬퍼가 `t` 의 닫힌 식이다 — Remotion 과 같은 제약이라 그대로 옮길 수 있다.

| 헬퍼 | 식(요지) | 쓰임 |
|---|---|---|
| `spring(t, t0, k=6, w=18)` | `t<t0 ? 0 : exp(−k·Δ)·sin(w·Δ)` | 사건 뒤의 **감쇠 흔들림**(더해 쓰는 값). 착지 뒤 몸, 모자, 쌓인 것, 끌려오는 꼬리 |
| `ring(t, [t0,t1,…])` | 사건마다 `spring` 을 더함 | 여러 번 치는 충격 |
| `pulse(t, k=6)` | `exp(−frac(beat)·k)` | 박자마다 1 에서 시작해 감쇠 |
| `jump(t, t0, t1, h)` | 0.12초 웅크림(sq +.18) → 포물선 + 늘어남 → 착지 `0.22·exp(−8a)·cos(20a)` | 예비 → 동작 → 안착이 한 함수에 |
| `take(t, t0, amt)` | 0.1초 눌림(.12) → `−0.26·exp(−6a)·cos(16a)` 늘어남 | 놀람 반응 |
| `kf(t, [[t,v],…], ease)` | 구간별 이징 키프레임, 값은 배열도 가능 | 카메라 `cx, cy, zoom` |
| `onTwos(t)` | `floor(t·12)/12` | 2프레임씩 잡아 손그림 느낌 |
| `shakeXY(t, amt)` | 24fps 해시 기반 [dx,dy], 데모에서는 `7·exp(−7Δ)` px | 충격 때 카메라 흔들림 |
| `camBegin(cx,cy,zoom,rot)`/`toScreen` | 세계 좌표 (cx,cy) 를 화면 중앙에 | 카메라 리그. 데모 주석: 느린 드리프트와 푸시로 카메라가 죽어 있지 않게 (`960 + 20·sin(lt·0.6)`, `zoom 1 + 0.02·lt`) |
| `brushWipe(p)` | 띠 5개가 지연 `[0,.14,.06,.18,.1]` 로 덮고(p 0→.5) 끌려 나감(.5→1). **완전히 덮인 순간에 컷**. 앞 장면 마지막 0.3초 + 뒤 장면 첫 0.3초 | 재질이 있는 전환 |

#### (4) 스토리보드 형식과 3단 검수 [C `ANIMATION_GUIDE.md` Workflow, `render.mjs`]

- **`STORYBOARD.md` 를 먼저** 쓴다: 로그라인(무엇을 원하지만 무엇 때문에 그래서) / 세계(배경·작은 팔레트·빛·색의 변화) / 모티프 / 감정 호 / 샷마다 `시작–끝 [들어오는 전환] 보이는 것 · 사건 · 반응 · 카메라` + **reads 표**(read 마다 시작–끝, 그때 시청자의 눈이 어디 있는지). 점검 5문항: 샷마다 사건이 있나 / read 가 다음 것 전에 안착하나 / 이음매마다 전환이 있나 / 글자가 있나 / 끝이 처음과 운이 맞나.
- **한 샷씩** 만들고, 샷 안에서는 **키 포즈를 정지 화면으로 먼저** 확인한 뒤 사이 움직임을 넣는다.
- **"코드를 읽어서는 움직임이 보이지 않는다"** — 렌더해서 세 배율로 본다:
  1. **sheet**: 지정 시각들의 컨택트 시트(전체의 모양) — `--sheet=0.1,0.8,1.6 --cols=6 --w=320`
  2. **strip**: 한 구간의 **모든 프레임**(돌기·놀람·점프·던지기·전환) — `--strip=2.1:2.6`
  3. **crop / crop-at**: 원본 해상도 부분 확대(얼굴·손·접점), `crop-at` 은 **움직이는 카메라를 따라** 세계 좌표의 한 점을 프레임마다 잘라 줌
- 볼 것: 읽힘 / **타이밍**(0.1~0.15초 간격 시트를 순서대로 읽으며 "지금 시청자는 어디를 보고, 이해했는가", read 마다 프레임 수를 센다) / 움직임(예비·따라가기가 있나, 툭 튀는 프레임, 부품이 동시에 움직이나, 등속인가, 좌우 대칭인가) / 접점 / 전환(샷마다 첫·끝 0.5초) / 규칙 / 색.
- **예산**: 샷마다 시트 1장 이상, 핵심 동작·전환마다 스트립, 이야기를 지는 얼굴마다 크롭. 컨택트 시트는 프레임당 0.1~1초라 싸니 건너뛰지 말라고 적는다.
- `render.mjs` 의 프레임 렌더는 **병렬·재개 가능**(없는 프레임만, 임시 파일 → rename 으로 원자적 기록).

#### (6) "생성물처럼 보이게 하는 것" 목록 [C `ANIMATION_GUIDE.md` Common failures] — 모션그래픽에 해당하는 것만

모든 것이 같은 빠른 속도로 움직이고 사건이 겹치며 정지가 없음 / 시청자가 이해하기 전에 끝남 / 주인공이 큰 빈 화면에 작게 / 상태가 툭 바뀜 / 직선·동시·대칭의 기계적 움직임 / 소심한 포즈 / 가만히 있어야 할 것이 매 프레임 떨림 / 어디나 하드 컷이거나 그냥 시작하고 그냥 끝남 / 소품이 닿지 않고 근처에 떠 있음 / 샷마다 다른 세계.

### 2-3. haidrrrry/claude-remotion-skill — 수치와 코드까지

"10 규칙"의 한 줄 요약은 기존 조사에 있다. 여기서는 **규칙에 붙은 숫자와, 예제 코드에만 있는 기법**을 적는다.

#### (1) 테마 토큰 [C `remotion-motion-graphics/assets/theme.ts`]

| 토큰 | 값 | 역할 |
|---|---|---|
| `ease.out` | `bezier(0.16, 1, 0.3, 1)` (expo-out) | 등장 |
| `ease.inOut` | `bezier(0.83, 0, 0.17, 1)` (quint in-out) | 이동, 켄 번스 |
| `ease.in` | `bezier(0.7, 0, 0.84, 0)` | 퇴장 전용 |
| `spring.snappy` | damping 14 · stiffness 160 · mass 0.6 | UI 팝, 낱말 |
| `spring.smooth` | damping 20 · stiffness 90 · mass 1 | 큰 요소 |
| `spring.bouncy` | damping 11 · stiffness 170 · mass 0.7 | 장난스러운 강조, 로고 |

감쇠비 ζ = c / (2√(k·m)) 로 계산하면 [I]: snappy ≈ 0.71, smooth ≈ 1.05, bouncy ≈ 0.50. 즉 "smooth" 는 임계 감쇠(안 튐), "snappy" 는 약 5% 오버슛, "bouncy" 는 약 16% 오버슛이다. Choi 의 `SPRING` 은 stiff(400/30) ζ=0.75, gentle(100/20) ζ=1.0, slow(50/20) ζ=1.41 — 값 자체는 건전한데 **거의 쓰지 않는 것**이 문제다.

#### (2) 규칙별 숫자 [C `SKILL.md`, `references/motion-patterns.md`, `references/design-rules.md`]

| 규칙 | 숫자 |
|---|---|
| 등장은 속성 2~3개를 함께 | 기본 진입 = opacity 0→1 + `translateY 40→0px` + `scale 0.94→1`, `spring.smooth`. 페이드 하나만은 금지 |
| 스태거 | 낱말 3f, 카드·목록 4~5f, 큰 블록 6f. 방사형 12개 선은 1.2f |
| 낱말 리빌 | 낱말마다 `spring.snappy`, `translateY 30→0`, 3f 간격 |
| 퇴장 | 끝 12f 전 ~ 2f 전(10f), `y 0→−42px` + opacity, `ease.in`. 등장 약 20f 대 퇴장 약 10f |
| 대기(2초 넘게 떠 있는 것) | scale `1 + sin(f/22)·0.015`, 위아래 `sin(f/30)·3px`, 느린 흐름 `0→−20px / 300f` |
| 정지 사진 | 켄 번스 `scale 1→1.08~1.10` + `translateX 0→−25px`, 연속 샷은 줌 인·아웃 교대. 둥근 카드에 넣을 때 반경 32, 그림자 `0 40px 80px −20px rgba(0,0,0,.6)` |

| 카운터 | 스프링 `damping 30 / stiffness 60`(ζ≈1.94, 과감쇠 — 길게 끌며 멈춤) + `tabular-nums` |
| 전환(직접 만든 것) | 8~14f. 휩 팬: 6f 에 1500px + `blur 8px`, 중간에 컷. 스케일 스루: A 가 1.3 으로 커지며 사라지고 B 가 0.8→1. 마스크 와이프: 브랜드색 도형이 쓸고 지나가는 뒤에서 컷 |

#### (3) 예제 코드에만 있는 기법 [C `examples/src/codeedit/CodeEdit.tsx`, `selffix/SelfFix.tsx`]

- **세계 좌표 카메라 `cam(px, py, s)`**: 큰 "세계"(1900px 폭 코드 페이지) 하나를 두고 `translate(W/2 − px·s, H/2 − py·s) scale(s)` 로 세계의 한 점을 화면 중앙에 놓는다. 장면은 요소를 움직이지 않고 **카메라만** 움직인다: 3.1배 극접사에서 `sin(f/40)·14px` 드리프트 + `0.004/f` 푸시 → 18f 휩 줌아웃(3.1→0.9, quart-out, 블러 0→9→0px) → 낱말마다 **30f 간격 줌 펀치**(스프링 `16/220/0.5`, 1.7→2.2배, 블러 10→0px 4f). → Choi 의 도식·보드에 그대로 쓸 수 있는 "한 장의 큰 판 위를 카메라가 다닌다" 구조(§7-8).
- **결과를 고정하고 한 가지씩 바꿔 보여 주기**(SelfFix): 같은 장면을 선형·동시·평면 배경 → 스프링 → 배경 → 스태거 → 주인공 색 순으로 75~90f 마다 "고쳐" 보인다. 디자인 교육 채널의 "전/후" 설명 형식으로 바로 쓸 수 있다.
- 강조 낱말 펄스 `1 + p(1−p)·4·0.05`(스프링 진행도 p 의 종 모양, 최대 +5%), 결과 정지 구간의 푸시인 `1→1.05 / 60f`.
- 효과음을 Node 스크립트로 **합성**(노이즈 버스트 훠시 0.4초, 피치가 떨어지는 사인 팝 0.14초, 사인 저음 0.45초, 디튠 패드) [C `examples/scripts/gen-sfx.mjs`] — Choi 의 `studio/sound/synth.py` 와 같은 발상.

#### (4) 검증 루프 [C `SKILL.md` Step 5]

`npx remotion still … --frame N --overwrite` 로 주요 프레임을 뽑아 본다. 흔한 결함 순: em 단위 간격이 부모 글자 크기 기준이라 큰 글자 옆에서 0 이 됨 → **px 로** / 글자가 가장자리에 닿음 / 등장 전·퇴장 후에 보임(clamp 누락) / 주인공 색이 두 군데 / 층 순서(그레인·비네트가 맨 위). 추가 실패: **이모지를 아이콘으로**(플랫폼 색이 팔레트를 깸), `--overwrite` 없이 다시 렌더하고 옛 파일을 검사함, 결과를 렌더하지 않고 말로 설명함.

#### (5) Choi 와 충돌하는 부분 [I]

- 그레인을 `feTurbulence` data-URI 로 매 프레임 이동 → Choi 는 성능 때문에 노이즈 타일(`lib/noise.ts`)을 쓴다. 그대로 둔다.
- 30초 프로모용 리듬(90f 마다 새 요소, 모든 정지 사진에 켄 번스, 모든 요소 스태거)은 롱폼 교육 영상에는 과하다. **펀치 구간·오프닝 하이라이트·숏폼**에만 그대로 적용하고, 본편에는 "정지를 디자인한다"·"프레임당 주인공 색 하나"·"속성 2~3개 등장"·"퇴장이 있다" 만 가져온다.
- `TransitionSeries` 의 Transition 은 길이를 줄이므로 Choi 규칙(영상 길이를 바꾸는 전환 금지)에 어긋난다. 직접 만든 전환과 Overlay 만 해당(§3-1).

### 3-2. HyperFrames — 모션 교리(자막·카드 규약 말고)

**(1) "튀는 것보다 매끄러운 것"** [C `rules/spring-pop-entrance.md`, `adapters/gsap-easing-and-stagger.md`]
- 등장 기본은 `power3.out`(빠른 도착은 `expo.out`) 긴 꼬리 안착, 오버슛 없음. `back.out` 은 에이전트가 만든 영상에서 가장 먼저 거슬리는 것으로 꼽는다. 집 기본값 `duration 0.6s(18f)`.
- 이징 역할: `power1/2.out` 부드러운 보조 · `power3/4.out` 등장·주인공 · `sine.inOut` 느린 움직임·크로스페이드·드리프트 · `expo.inOut` 장면 전환 · `none` 빛 스윕·기계적 움직임 · `steps(N)` 타자. 이징 성격은 **3가지쯤**(하나만 쓰면 밋밋, 다 튀면 싸구려) [A].
- 스프링은 **닫힌 식**으로 쓴다: 임계 감쇠 `pos(t) = 1 − e^(−wt)(1 + wt)`, `w = 2π/response`. response 0.25~0.35 → 0.37~0.51초(칩), 0.35~0.50 → 0.51~0.74초(표준), 0.50~0.70 → 0.74~1.03초(주인공). 감쇠 1.0 기본, 0.80~0.85 는 1~1.5% 오버슛, 0.6~0.7 은 장난스러울 때만. 오버슛은 transform 에만, 불투명도는 따로 `power2.out` [C 식, A 범위].
- 묶음 스태거는 한 박으로 읽혀야 한다: `개수 × 간격 ≤ 약 0.5초`. 등장 간격 `min(0.06, 0.5/N)` 초 [A `rules-index.md`, `spring-pop-entrance.md`].

**(2) 정지와 퇴장** [C `transitions/overview.md`, `faceless-explainer/references/motion-language.md`]
- **장면 중간 퇴장 금지**: 마지막 장면만 퇴장 애니메이션. 다음 장면으로 넘어갈 때는 내용이 다 보이는 채로 전환이 시작돼야 한다 — 전환이 곧 퇴장. 내용을 먼저 페이드아웃하고 다음 장면이 등장하면 "딥이 낀 점프 컷"이 된다.
- 전환은 **주 전환 하나(컷의 60~70%) + 보조 1~2개**. 반복이 프로처럼 보이게 한다 [A].
- 나쁜 움직임보다 움직임 없는 편이 낫다: 순서는 ① 말에 맞춘 순차 리빌 ② 아주 작은 지터 ③ 숨쉬기는 마지막 수단. 숨쉬는 카드·후반부의 느린 팬/푸시는 금지 목록 [C·A]. (같은 저장소의 `hyperframes-creative` 는 반대로 "더 움직이라"고 한다 — 프로모용. 차분한 채널은 faceless 쪽 교리가 맞다 [I])
- **슬라이드쇼 병**: 모든 요소가 앞 25%에 다 들어오고 나머지는 얼어 있음 → 뒤 50%에 걸쳐 **말한 순간에** 하나씩. **화면보호기 병**: 모든 것이 제각각 떠다님 → 정지 + 지터 [A].

**(3) 읽는 시간** [C `rules/dynamic-content-sequencing.md`]
- 항목 길이 = `BASE 0.6~1.5초 + 글자 수 × 0.03~0.06초 + hold`. 폭 넓은 문자 언어는 높은 쪽으로(한국어 0.06초/자 [I]). 중간 hold 0.5~1.0초, 마지막 1.0~2.0초.
- 0.5초 미만의 상태는 "읽히지 않고 스친다". 줌·교체·최종 키워드 뒤에는 1초 이상 머문다. 주인공은 0.5초 안에 보인다. 카메라는 내용이 안착한 뒤 0.5초 기다렸다 움직인다 [A].

**(4) 카메라** [A `rules/viewport-change.md`, `multi-phase-camera.md`, `3d-camera-flight.md`]
- 모든 내용을 `.world` 하나에 넣고 카메라 상태 `{scale, x, y}` 하나를 **한 곳에서만** 쓴다. 배경은 world 밖.
- 줌 크기: 미묘 1.02~1.05 · 강조 1.05~1.15 · 초점 1.15~1.30 · 극적 1.5~2.5. "자연스러운" 푸시는 1.05~1.15배를 2~3초에. 의도적 줌은 1.0~2.0초(0.8초 미만은 순간이동, 2.5초 초과는 늘어짐), `power3.inOut`. 카메라에는 스프링·back 금지.
- 3단: 물러남 0.88~0.96 → 초점 0.98~1.02 → 밀기 1.04~1.15. 정지 중 드리프트 X 2~8px·Y 1~4px, 주파수 비 약 1.3.
- 3D: `perspective` 800~1200px, 다이브 0.6~1.0초 `power4.out`, 평평해지기 1.2~2.0초. **읽기는 착지에서만** — 움직이거나 기울거나 흐린 글자는 질감일 뿐.
- 피사계 심도: 깊이 한 단계당 3~6px, 최대 8~24px, 어둡게 0.4~0.7(0.35 미만 금지), 0.5~1.2초 `power2.inOut`. 넘기기 전에 0 으로 되돌린다.

**(6) 이미지는 "날것으로 평평하게" 두지 않는다** [A `hyperframes-creative/references/motion-principles.md`, `motion-graphics/categories/asset-fusion/module.md`, `news/module.md`]
- 켄 번스 scale 1→1.04, 원근 기울임 `rotateY −8° @ perspective 1200` + 그림자, 기기 프레임, **한 요소를 떼어 다른 깊이에**(패럴랙스), 잘린 창 안 스크롤, **등장은 래퍼에·줌은 자식에**.
- 고정 오버레이 아래에서 카메라를 밀지 않는다. 사각 사진 상자 대신 배경을 지운 컷아웃. 사진 위 글자색은 사진에서 스포이트로.
- 기사 하이라이트: 읽을 수 있는 크기의 글이 `y 52→0` 0.8초로 올라오고, **안착한 뒤** 마커 띠가 왼→오로 0.5~1.5초. 키워드를 화면 가득 확대하는 것은 금지(제자리 강조).

**(7) 기획·검수 형식** [A `hyperframes/references/storyboard-format.md`, `hyperframes-creative/references/storyboard-recipe.md`·`beat-direction.md`, `motion-graphics/agents/*.md`, `scripts/animation-map.mjs`]
- 비트마다: 화면의 글(그대로) / 주인공 소품과 그것이 다시 나오는 비트 / **이름 붙은 동작 + 이징 + 길이** / 나가는 이음매(전환·방향 — 한 편에 방향 규칙 하나) / 소리 큐 / **제약(명시적 "하지 않는다" 하나 이상)** / 이유(메시지로 거슬러 올라가지 못하면 삭제).
- 요소마다 **동작 동사**(충격: 내리꽂다·찍다 / 방향: 미끄러지다·밀다·쓸다 / 드러냄: 그리다·채우다·자라다·조립하다·세다 / 유기: 뜨다·흐르다 / 기계: 타자·잠기다·딸깍). 동사가 없는 요소는 아직 설계되지 않은 것.
- 리듬을 이름으로 먼저 선언(예: 빠름-빠름-**느림**-빠름-정지). 가장 느린 장면은 가장 빠른 장면의 3배 길이. 첫 트윈은 0.1~0.3초 뒤에. 먼저 움직인 것이 가장 중요하게 읽힌다 → **중요도 순 스태거**.
- 빌더 규칙: **주인공 프레임의 끝 상태를 정적 CSS 로 먼저 만들고**, 그쪽으로 애니메이션한다. 감독 휴리스틱: 0.5초 안에 훅, 지배 모티프 하나, 2.5초 넘으면 정확히 한 가지를 바꾼다, 핵심 요소는 0.3초 이상 읽힌다.
- 자동 검사(`animation-map`): 트윈별 `paced-fast`(<0.2초) · `paced-slow`(>2.0초) · `offscreen` · `invisible` · `collision`(상자 겹침 >30%), **dead zone**(트윈 없는 1.0초 이상), **스태거 불균일**(간격 편차 >평균의 30%).
- 워커 브리프(패킷, 48KB 상한): 프로젝트 입력 / 배정된 스토리보드 블록(그대로) / 고른 블루프린트 본문 / 인용한 모션 규칙 본문. 역할 파일에 **"네가 정하지 않는 것"**(내레이션·길이·전환·소리·토큰·어떤 동작이 있는지) 절이 있다.

### 3-5. 다른 코드 애니메이션 엔진의 "안무 문법"

- **Motion Canvas** [W]: 흐름 제너레이터 `all`(동시) · `any` · `chain`(차례로) · `delay(초, 작업)` · `sequence(간격, …작업)`(앞 작업이 끝나길 기다리지 않고 일정 간격으로 시작 = 스태거) · `loop`. 트윈은 `속성(값, 초, 타이밍 함수)`, 기본 `easeInOutCubic`, `Vector2.arcLerp` 로 호 이동, `spring(프리셋, from, to, settleTolerance)`. (`waitUntil` 과 스프링 프리셋 수치는 받은 문서 본문에 없어 **미확인**.)
- **Manim** [W]: `LaggedStart(lag_ratio=0.05)` — 앞 애니메이션이 `lag_ratio` 만큼 진행됐을 때 다음이 시작하고, **묶음 전체 길이는 고정**(개별 길이가 조정됨). `AnimationGroup`(동시), `Succession`(차례로). 기본 rate function `smooth`, 그 밖에 `there_and_back`, `there_and_back_with_pause`, `rush_into`, `rush_from`, `running_start`, `wiggle`, `lingering`, `exponential_decay`.
- **Revideo** [W]: TypeScript 영상 렌더 엔진, 헤드리스 렌더 API·병렬 렌더(MIT, 약 4.1k★). Motion Canvas 포크라는 통설은 저장소 페이지에서 확인하지 못했다(**미확인**).
- 가져올 생각 [I]: 지금 MotionSpec 은 요소마다 절대 시각 `at` 을 적게 해서 에이전트가 **안무가 아니라 좌표표**를 쓴다. `par / seq / stagger(lag)` 묶음과 "묶음 길이 고정 + lag 비율"(Manim) 을 DSL 에 넣으면, 에이전트는 "제목 → (도형 셋이 가운데부터 lag 0.3) → 화살표 → 정지" 처럼 쓰고 `spec.py` 가 `at` 을 계산한다(§7-16).

## 5. 종합: "전문가처럼 보이게" 하는 규칙과 수치 (1차 제안값, 30fps)

> **이 장의 값은 1차 조사 시점의 제안이다. 채택값은 `docs/upgrade/06_모션_그래픽_v2.md` 6장 · `06b` · `prompts/skills/motion_craft.md` 다.**
> 다른 곳: 이징(06 은 `enter 0.22,1,0.36,1` · `move 0.2,0,0,1` · `exit 0.3,0,0.8,0.15`), 정지(`max(1.2초, 글자 수 ÷ 7)`), 오버슛(4% 이하, `pop` 은 펀치 구간만), 강조색(한 곳), 헤드라인 리빌(10~12f), 0.5초 잉크(35%).
> 출처별 수치의 비교표로만 읽는다.

출처가 서로 다른 맥락(UI·프로모·설명 영상)이라 값이 갈린다. 아래는 **차분한 교육 롱폼** 기준으로 고른 값이고 [I], 펀치 구간·숏폼·오프닝 하이라이트는 괄호 안 값을 쓴다.

### 5-3. 스태거

| 묶음 | 간격 | 상한 |
|---|---|---|
| 음절 | 1f | 묶음 전체 ≤ 15f → `each = min(토큰, 15/n)` |
| 낱말 | 2~3f | 같음 |
| 줄 | 3~4f | 같음 |
| 목록·카드 | 4~5f (차분: 60~120ms) | **말에 맞춘 목록은 예외** — 항목마다 그 말이 나올 때 |
| 큰 블록 | 6f | — |

- 순서는 **중요도 순 또는 읽는 순**. 대칭 배열(3열 카드, 점 격자)은 가운데부터(`from: center`).
- 간격이 일정한 스태거와 "앞 것이 끝나야 다음이 시작하는" 줄 세우기는 다르다. 뒤엣것이 앞엣것과 **겹쳐** 움직여야 한 박으로 읽힌다(Manim `lag_ratio`, HyperFrames).
- 스태거 간격이 들쭉날쭉하면(편차 > 평균의 30%) 린트.

### 5-4. 안무(시퀀싱)

1. **read 하나씩.** 독립된 두 요소를 동시에 드러내지 않는다. 동시에 움직이는 요소는 전체의 1/3 이하(iart).
2. **말한 순간에.** 요소는 그 낱말이 나오기 0~2프레임 전에 **착지**(시작이 아니라 착지). 앞 25%에 다 넣고 얼리지 않는다.
3. **첫 움직임은 3~9f 뒤**, 주인공은 15f 안에 보인다.
4. **예비 → 동작 → 안착.** 상태가 바뀌는 순간(도형이 갈라짐, 숫자가 바뀜, 강조가 옮겨 감)에는 2~4f 의 반대 방향 예비 동작과 감쇠 안착을 붙인다. 등장마다 붙이지는 않는다.
5. **부모 먼저, 자식 2~3f 뒤.** 판이 들어오고 → 제목 → 내용. 짝인 것(숫자와 막대, 화살표와 도착점)은 같은 구간·같은 이징.
6. **긴 장면은 3막**: 쌓기 → 초점 이동(카메라·강조·흐림) → 정리. 8초 넘는 장면이 처음 상태로 끝나면 안 된다(장면마다 **사건**).
7. **방향 규칙 하나.** 한 영상에서 "다음"은 늘 같은 방향(왼→오 또는 아래→위).
8. 가장 느린 장면은 가장 빠른 장면의 약 3배 길이 — 영상 전체의 리듬 대비.

### 5-5. 움직이는 글자

- **읽기는 착지에서.** 글자는 짧게·조금만 움직이고(이동 ≤ 24px 또는 제 줄 높이의 마스크), 큰 이동은 도형·이미지가 맡는다.
- 본문은 줄 단위, 헤드라인만 음절·낱말 단위. 10음절 넘으면 낱말 단위. 한글은 음절 블록 단위(자모로 쪼개지 않는다).
- 강조 장식(밑줄·형광펜·알약)은 글자가 **안착한 5f 뒤**에 시작. 헤드라인당 강조 낱말 하나.
- 숫자는 `tabular-nums`, 오버슛 없음, 접미사·라벨은 숫자가 멈춘 뒤.
- 타자 효과는 문자열을 잘라서, 폭은 전체 문자열(또는 가장 긴 낱말)로 미리 잡는다.
- `letter-spacing`·`font-size`·`width` 를 트윈하면 줄이 튄다(HyperFrames) → 카드의 `morph-to` 허용 속성에서 `fontSize`·`letterSpacing`·`width`·`height`·`padding`·`left`·`top` 은 주의 대상.
- 키워드를 화면 가득 확대하지 않는다 — 제자리에서 강조(HyperFrames news).

### 5-6. 정지와 읽는 시간

- 요소 하나의 최소 노출 = `0.5초(찾기) + 글자 수 ÷ 12 + 0.3초(여유)` — Netflix KR 12자/초(기존 조사)와 HyperFrames 식(0.6~1.5초 + 0.03~0.06초/자)의 사이 [I].
- 마지막 요소가 착지한 뒤 **1초 이상 정지**. 줌·교체 뒤에도 1초.
- 0.5초 미만의 상태는 읽히지 않는다. 0.15초 미만의 교체는 깜빡임이다.
- 정지 중에 허용하는 움직임은 **장면당 하나**: 카메라 드리프트(2~8px) 또는 사진의 느린 줌. 숨쉬는 카드·떠다니는 요소 여러 개는 금지.
- "정지 15~20f 뒤 다음 동작"(claude-remotion-skill)은 프로모 기준. 롱폼은 read 식으로 계산한다.

### 5-7. 퇴장과 전환

- 그래픽 뒤에 **다른 그래픽이 0.3초 안에** 오면 퇴장하지 않는다 — 전환(또는 공유 요소 모프)이 퇴장이다.
- 얼굴로 돌아갈 때만 퇴장: 요소별이 아니라 **묶음 하나로**, 6~10f, 등장의 반대 방향, 말하는 중이 아닐 때.
- 영상마다 **주 전환 하나(60~70%) + 보조 1~2개**. 그래픽마다 다른 전환을 쓰지 않는다.
- 차분한 기본은 blur-crossfade(18f, blur 10px, 나감 1.03·들어옴 0.97). 순서가 있는 단계는 push, 세부로 들어갈 때 zoom-through, 주제 전환은 하드 컷.

### 5-8. 모션 블러

- 프레임당 30px 넘게(또는 요소 폭만큼) 움직일 때만. 한 편에 1~3번, 펀치 구간·휩 전환에만.
- 읽고 있는 글자, 페이드, 느린 드리프트에는 걸지 않는다. 멈춘 뒤에 블러가 남으면 안 된다.

### 5-9. "AI 티" → 대체 → 자동 검출

| 티 | 대체 | 검출(린트·검수) |
|---|---|---|

## 6. 워크플로 패턴 — 무엇을 어떤 순서로 시킬 것인가

### 6-1. 영상 단위 "모션 바이블"을 감독이 먼저 쓴다

출처: ClaudeAnimationBase 스토리보드(세계·모티프·호), PDoomVideo(모델이 서브에이전트용 가이드를 직접 씀 [A]), HyperFrames `## Video direction` 블록, iart 모션 언어 명세.

`prompts/agents/director.md` 의 브리프에 아래 블록을 추가하고, 모션·카드·아트 디렉터 에이전트가 모두 받는다 [I]:

```
motion_bible:
  signature: "밑줄이 긋고 지나간 자리에 낱말이 남는다"   # 이 영상의 시그니처 동작 1개(모든 챕터에서 반복)
  motif: "원 → 점 12개"                                  # 반복 모티프 1개(오프닝과 엔드카드가 이걸로 닫힌다)
  flow: "ltr"                                            # '다음'의 방향 — 영상 내내 고정
  tone: "calm-sharp"                                     # 길이·스태거·오버슛 프리셋(§5)
  transitions: {primary: "blur", accents: ["push"]}      # 주 전환 60~70%
  camera: "도식은 한 판 위에서 카메라가 이동, 사진은 패럴랙스"
  hold: "마지막 요소 뒤 1.2초"
  bans: ["pop 은 숫자에만", "가운데 정렬 제목+아래 설명 구도 3회 이상 금지", "형광펜은 정의 카드에만"]
```

금지를 일반 지시("AI 티 안 나게")가 아니라 **구체 패턴 이름**으로 쓰는 것은 기존 조사와 같다. 여기서 더한 것은 금지와 짝이 되는 **긍정형 시그니처**(금지만 쓰면 한 가지 밋밋함으로 수렴).

### 6-2. 장면마다 "사건·동사·reads" 를 먼저, 좌표는 나중에

모션 디자이너의 출력 스키마(`studio/agents/schemas.py`)에서 `spec_json` 앞에 아래 필드를 **먼저** 쓰게 한다(구조화 출력은 필드 순서대로 생성되므로 계획이 좌표보다 앞선다) [I]:

```
event:  "점 12개가 세 무리로 갈라진다"          # 첫 프레임과 끝 프레임의 차이. 못 쓰면 장면을 만들지 않는다
hero:   "dots"                                   # 주인공 요소 1개 — 화면의 40~60%
verbs:  {title: "그어진다", dots: "모인다", note: "붙는다"}   # 요소마다 동작 동사(§3-2 (7))
reads:  [{say: "가까이 있으면", what: "점 12개가 한 줄"}, {say: "한 무리로", what: "세 무리로 갈라짐"}, {say: "같은 점 다른 간격", what: "설명 줄"}]
camera: "1.0 → 가운데 무리로 1.12 (갈라진 뒤)"
seam:   {in: "앞 그래픽의 원이 이 장면의 첫 점이 된다", out: "blur"}
```

`reads[].say` 는 대본의 낱말이라 파이프라인이 단어 타임스탬프로 `at` 을 계산할 수 있다(지금은 에이전트가 초를 추정). 이것이 HyperFrames 의 "정적 끝 상태 먼저, 그다음 애니메이션"과 ClaudeAnimationBase 의 "키 포즈를 정지 화면으로 먼저"에 해당한다 — Choi 에는 이미 `check.mjs` 가 정지 상태를 검사하므로, **1차 호출 = 끝 상태 레이아웃, 2차 = 타이밍** 으로 나눌 수도 있다.

### 6-3. 움직임을 실제로 본다 — 3배율 검수

지금은 그래픽당 안착 스틸 1장(D9). 이미 `RenderItem("frames", …, frames=[…])` 로 임의 프레임 목록을 뽑을 수 있으니 비용은 작다 [I]:

| 배율 | 무엇을 | 프레임 | 보는 것 |
|---|---|---|---|
| **sheet** | 모션 장면·카드마다 처음·read 마다 착지 직후·끝−1초 | 4~6장, 0.4배 | 사건이 시트만 보고 읽히나, 구도, 주인공 크기 |
| **strip** | 진입 구간과 상태 변화 구간의 **연속 프레임** | 사건마다 8~12프레임(2프레임 간격), 0.3배 | 동시에 움직이는가, 툭 튀는 프레임, 등속, 대칭, 예비·안착 유무, 번쩍임 |
| **crop** | 글자·접점(화살표 끝, 밑줄과 글자) | 원본 해상도 400×300 | 선이 닿는가, 글자 잘림, 마스크 가장자리 |
| **seam strip** | 그래픽 ↔ 얼굴, 그래픽 ↔ 그래픽 전환 앞뒤 | 컷 앞뒤 5프레임씩 | 딥이 낀 점프 컷, 전환 중 자막 |

- 시트는 Pillow 로 한 장에 붙이고 칸마다 시각 라벨(초)을 찍는다(ClaudeAnimationBase `renderSheet` 방식).
- 아트 디렉터 프롬프트에 **모션 문항**을 추가: ① 각 칸에서 시청자가 어디를 보는가 ② 연속한 두 칸 사이에 새로 나타난 요소가 둘 이상인가 ③ 요소가 한 칸 만에 완성되는가(너무 빠름) ④ 마지막 칸 앞에서 3칸 이상 아무 변화가 없는데 말은 계속되는가 ⑤ 모든 요소가 같은 방향에서 오는가.
- 스트립에는 "움직이는 중간 프레임 — 흐림·잘림은 결함이 아님" 라벨을 붙인다(기존 조사의 원칙 유지).
- `choi-motion-scene` 스킬 4절("정지 상태만 본다")을 "정지 1장 + 스트립 1장"으로 고친다.

### 6-4. LLM 없이 잡는 것 — 타이밍 린트

`studio/motion/spec.py` 에 `lint_spec(spec, dur, words)` 를 추가(§7-16 코드): 몰림·동시·마지막 정지·읽는 시간·스태거 불균일·닿지 않는 선·`pop` 남용·`dur` 범위. 실패하면 `motion_revise` 한 번, 그래도 실패하면 규칙으로 `at` 을 다시 배치(단어 타임스탬프에 스냅).

### 6-5. 예시를 늘리고, 종류별로만 넣는다

- 모션 예시 3개 → **12개 이상**, 각기 다른 사건 유형으로: 모이기 / 갈라지기 / 비교(전·후) / 과정(카메라 이동) / 위계(크기·굵기 변화) / 수치(롤 + 막대) / 주석(사진 위 동그라미) / 모프(도형 변화) / 격자 조립 / 타임라인 / 겹치기(레이어) / 인용.
- 전부 프롬프트에 붙이지 말고, 감독 비트의 `visual` 종류로 **분류해 해당 2~3개만** 주입(remotion-dev 템플릿의 방식). 예시가 3개뿐이면 에이전트는 그 셋을 베낀다.
- 예시에는 좌표뿐 아니라 `event`·`reads`·`camera` 를 같이 넣는다.

### 6-6. 그 밖

- **0.25배속 확인**: 새 템플릿·레시피는 Remotion Studio 에서 1/4 속도로 한 번 본다(이징 결함은 저속에서 보인다).
- **결정론 검사**: 같은 프레임을 두 번 렌더해 픽셀 비교 — 노이즈·보일·GSAP `random` 을 넣기 시작하면 필요(motionloom).
- **룩 증명 스틸 1장**: 영상마다 모션 바이블로 만든 대표 장면 1장을 먼저 렌더해 감독이 승인 → 나머지 병렬 생성(motionloom, HyperFrames 스케치 시트).
- **워커 브리프에 "네가 정하지 않는 것"**: 모션 디자이너에게 길이·전환·색·서체는 이미 정해졌고 바꿀 수 없다고 명시 → 에이전트가 매번 새 스타일을 발명하지 않는다.
- **효과음은 착지 2~3프레임 전** 에 시작(`studio/edit/grammar.py` 의 효과음 큐 시각에 −0.08초) — claude-remotion-skill.

## 7. 레시피 — 1차 스케치 (최종판은 `docs/upgrade/06d_애니메이션_레시피.md`)

> **이 장의 스케치는 실행하지 않은 1차 초안이다.** 06d 에서 채널 톤에 맞지 않는 것(감쇠 진동 `kick`, 정지 중 드리프트, 3D 기울임, 빛 스윕, 속도 블러, 긴 꼬리 리빌)을 빼고,
> 설치본으로 형 검사를 했다. 7-4 의 `tip.x` 는 `getPointAtLength` 가 `Point | null` 이라 그대로는 형 오류다. 7-6 의 `findLastIndex` 는 `lib ES2020` 에 없다.

모두 `useCurrentFrame()` + `interpolate()`/`spring()` 만 쓰고 CSS transition 은 쓰지 않는다. 스케치는 이 노트에서 새로 쓴 것이며 **실행해 보지 않았다**(타입·수치는 붙이면서 조정). 공통:

```ts
const clamp = {extrapolateLeft: 'clamp', extrapolateRight: 'clamp'} as const;
const h01 = (n: number) => { const x = Math.sin(n * 127.1 + 311.7) * 43758.5453; return x - Math.floor(x); }; // 0~1 해시
```

### 7-1. 역할 토큰 · 크기 비례 길이 · 스태거 상한 · 감쇠 킥 (`design/motion.ts`)

```ts
export const ROLE = {
  enter: Easing.bezier(0.16, 1, 0.3, 1), enterSoft: Easing.bezier(0.22, 1, 0.36, 1),
  move: Easing.bezier(0.83, 0, 0.17, 1), exit: Easing.bezier(0.7, 0, 0.84, 0),
  data: Easing.bezier(0, 0.55, 0.45, 1), sweep: Easing.linear,
} as const;
export const SPRING = {
  settle: {damping: 200},                           // 안 튐
  soft: {damping: 20, stiffness: 90, mass: 1},      // ζ≈1.05, 큰 면
  pop: {damping: 14, stiffness: 160, mass: 0.6},    // ζ≈0.71, 숫자·아이콘만
} as const;
/** 면적 비(0~1)와 이동 거리(px) → 진입 프레임: 라벨 9 · 본문 12 · 반 화면 18 · 전체 22 */
export const enterFramesFor = (areaRatio: number, travelPx = 0) =>
  Math.round(Math.min(22, Math.max(8, 8 + 14 * Math.sqrt(areaRatio) + travelPx / 60)));
/** 묶음 전체가 capF(15f = 0.5초) 안에 끝나는 간격 */
export const staggerEach = (n: number, tokenF: number, capF = 15) => Math.min(tokenF, capF / Math.max(1, n));
/** 순서: 읽는 순 / 가운데부터 / 가장자리부터 */
export const staggerOrder = (i: number, n: number, from: 'start' | 'center' | 'edges' = 'start') => {
  const c = (n - 1) / 2;
  return from === 'center' ? Math.abs(i - c) : from === 'edges' ? c - Math.abs(i - c) : i;
};
/** 사건(f0) 뒤 감쇠 흔들림, −1~1. 위치·회전·스케일에 '더해' 쓴다 */
export const kick = (frame: number, f0: number, fps: number, k = 6, w = 18) => {
  const t = (frame - f0) / fps;
  return t < 0 ? 0 : Math.exp(-k * t) * Math.sin(w * t);
};
/** 예비 동작: f0 직전 n 프레임 동안 0 → −amt → 0 */
export const anticipate = (frame: number, f0: number, n = 4, amt = 1) => {
  const p = (frame - (f0 - n)) / n;
  return p <= 0 || p >= 1 ? 0 : -amt * Math.sin(Math.PI * p);
};
```
출처: 토큰 = claude-remotion-skill·animation-forge·iart, 길이 = animate-skill·iart(√거리), 상한 = HyperFrames, `kick` = ClaudeAnimationBase `spring(t,t0,k,w)`.
쓰는 예: 점들이 갈라지는 순간 `gx += 6 * kick(frame, groupF + 24, fps)` — 멈출 때 한 번 출렁이고 선다.

### 7-16. 안무 묶음 → 절대 시각, 그리고 타이밍 린트 (`studio/motion/spec.py`)

```py
# node: {"seq":[…], "gap":0.15} | {"par":[…]} | {"stagger":[…], "lag":0.3} | {"el":"title", "on":"한 무리", "dur":0.4}
def resolve(node, t0, words):
    if "el" in node:
        dur = node.get("dur", 0.4)
        land = words.get(node.get("on"))                       # 그 낱말의 시작 시각(장면 기준 초)
        at = max(t0, land - dur) if land is not None else t0   # 낱말에 '착지'하도록 dur 만큼 앞당김
        return [(node["el"], at, dur)], at + dur
    out, t, end = [], t0, t0
    for child in node.get("seq") or node.get("par") or node.get("stagger") or []:
        got, e = resolve(child, t, words)
        out += got; end = max(end, e)
        if "seq" in node: t = e + node.get("gap", 0.15)
        elif "stagger" in node: t += node.get("lag", 0.3) * (got[0][2] if got else 0.4)   # 앞 것이 lag 만큼 진행됐을 때
    return out, end

def lint(timed, chars, dur, cps=12.0):                         # timed: [(id, at, dur)], chars: {id: 글자 수}
    issues, timed = [], sorted(timed, key=lambda x: x[1])
    for (a, at_a, d_a), (b, at_b, _) in zip(timed, timed[1:]):
        if at_b - at_a < 0.15: issues.append(("simultaneous", a, b))
        need = d_a + 0.5 + chars.get(a, 0) / cps               # 도착 + 찾기 + 읽기
        if chars.get(a, 0) >= 6 and at_b - at_a < min(need, 1.2): issues.append(("no_time_to_read", a))
    arrived = [at + d for _, at, d in timed]
    if dur > 4 and sum(t <= dur * 0.25 for t in arrived) >= 0.8 * len(arrived): issues.append(("front_loaded",))
    if dur - max(arrived) < 1.0: issues.append(("no_final_hold",))
    return issues
```
출처: Motion Canvas `sequence/all/chain`, Manim `LaggedStart(lag_ratio)`, ClaudeAnimationBase reads, HyperFrames `animation-map`(dead zone·front-loading)·dynamic-content-sequencing.

### 10-1. 출처끼리 충돌하는 지점과 이 노트의 선택

| 쟁점 | 한쪽 | 다른 쪽 | 선택 [I] |
|---|---|---|---|

### 10-2. 확인하지 못한 것

- **렌더는 한 번도 하지 않았다.** `Easing.spring`·`perceptual-scale`·`posterize` 는 문서의 도입 버전(4.0.476 / 4.0.490 / 4.0.470)과 설치본 4.0.530 의 형 정의로 확인했다. 06d 의 스케치는 형 검사만 통과했다.
- [A] 표시 항목은 보조 에이전트의 요약이다. 내가 원문과 직접 대조한 것은 HyperFrames 의 퇴장 금지 문장·"smooth beats bouncy"·읽기 시간 식(`BASE_DURATION + 글자 수 × SEC_PER_CHAR + hold`)·스프링 닫힌 식·모션 블러 표(셔터 720°/16샘플), GSAP 플러그인 무료 문장, iart Calm+Soft·Calm+Sharp 표와 1/3 규칙, PDoomVideo README 의 제작 경위, 각 저장소의 LICENSE 유무뿐이다. 나머지 수치는 코드에 넣기 전에 해당 파일을 다시 확인할 것.
- gsap 3.15.0 에 SplitText·DrawSVG·MorphSVG·CustomEase 파일과 형 정의가 있는 것은 설치본에서 확인했다. `card-anim.mjs` 는 검사 스크립트(`check.mjs`)에 고전 스크립트로도 주입되므로, GSAP 플러그인을 쓰려면 두 경로 모두에 등록해야 한다 — 그 방법은 검증하지 않았다.
- `@remotion/transitions` 의 기본 프레젠테이션 전체 목록(문서 페이지가 렌더되지 않음; 스킬 파일에서 `fade·slide·wipe·flip·clockWipe` 만 확인). `@remotion/animation-utils` 함수 목록, `@remotion/noise` 의 `noise3D/4D` 시그니처도 같은 이유로 **미확인**.
- `<HtmlInCanvasMotionBlur>`·`@remotion/effects` 가 Choi 가 쓰는 chrome-headless-shell 과 `rs.gl` 설정에서 동작하는지, 렌더 속도에 미치는 영향.
- Motion Canvas `waitUntil`·스프링 프리셋 수치, Revideo 와 Motion Canvas 의 관계.
- `interpolatePath` 가 명령 구성이 다른 두 경로를 어떻게 처리하는지.
- `studio/edit/grammar.py` 의 효과음 큐 시각(갭 표 39번)은 읽지 않았다. 구조화 출력이 필드 순서대로 생성된다는 전제(§6-2)도 검증하지 않았다.
- 감쇠비·오버슛 수치(ζ, "약 4%")는 내가 계산한 값이다.
- 웹 검색 한도에 걸려 추가 검색을 못 했다. "Claude 용 After Effects·Manim·Motion Canvas 스킬" 류는 찾아보지 못했고, 검색 결과에만 나온 저장소 3개(§3 표 아래)는 읽지 않았다.
- HyperFrames `hyperframes-animation` 의 규칙 약 25개·블루프린트 14개, `clawd.js`(ClaudeAnimationBase 캐릭터 코드)는 읽지 않았다.
