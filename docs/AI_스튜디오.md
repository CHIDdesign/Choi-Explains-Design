# 🎬 AI 스튜디오: 감독 한 명과 전문 에이전트 팀

Choi Studio 는 Claude 한 번에게 "알아서 편집해"라고 맡기지 않습니다. 영상 제작사처럼 **총괄 감독 한 명이 전문가 팀을 동시에 굴리고**, 마지막에 **아트 디렉터가 실제로 렌더된 화면을 보고** 고칩니다.

> **AI 연결**: 기본은 이 PC 의 **Claude Code**(Claude Pro/Max 구독 사용량에서 차감, API 결제 불필요)입니다. `setup_windows.bat` 이 설치하고 브라우저 로그인까지 안내합니다. 원하면 ☰ → 도구 → 환경 설정 → AI 연결에서 **Claude API 키**(종량제)로 바꿀 수 있습니다. 둘 다 없으면 대본 태그 기반 규칙 편집으로 동작합니다.

## 팀 구성

| 역할 | 하는 일 | 출력 | 사고 강도(기본) |
|---|---|---|---|
| 🎬 총괄 감독 | 전사본 전체를 읽고 **논지 한 문장**(`thesis`)·챕터 구조(챕터마다 **주장 한 문장** `claim` → 챕터 카드 부제)·연출 비트(8~15초마다, 얼굴만 보이는 구간 최대 12초)·숏폼 아이디어·자막 톤을 정한다 | 크리에이티브 브리프 | high |
| ✂️ 편집 감독 | 대본 밖 발화를 추가로 자르고(대본 문장은 앱이 거절), 논점 전환과 결론을 강조 순간으로 표시(천천히 당기는 글라이드 + 콜아웃). **펀치 구간**(`energy_spans`: 훅·클라이맥스·빠른 열거, 전체의 20% 이하)에서만 하드 펀치인·단어 슬램·휩·임팩트 효과음을 허용. **오프닝 하이라이트**(`highlights`: 앞뒤 없이 서는 임팩트 문장 2~4개, 각 ≤7초·합 ≤20초)를 고른다 | drop / moments / energy_spans / highlights | medium |
| 🎨 모션 디자이너 | 템플릿 도식 배치 + 템플릿으로 안 되는 개념은 **모션 DSL 로 새 장면을 직접 설계** + 챕터의 핵심 개념 1~2곳은 **자유 HTML 카드**(HyperFrames 카드 규약: HTML + 스코프 CSS + `data-anim`) | graphics / scenes / cards | high |
| 🎞 자료 리서처 | 구체적 장면·사물을 스톡 검색어로 만들어 Pixabay·Unsplash·Coverr·Pexels 를 한 번에 검색하고, **후보 썸네일을 직접 보고** 고른다 | 스톡 요청 → 선택 | medium / low |
| 🔤 자막 디자이너 | 강조어를 유형별로(전문용어·핵심어·숫자·대비) 고른다. 자막 모양은 채널 템플릿(흰 종이 상자 · 두 층 강조)으로 고정 | emphasis | medium |
| 📱 숏폼 PD | **제대로 된 한 편**을 먼저: 아이디어 하나를 연속 구간으로, 훅 → 왜 → 예시 → 페이오프, 시청자가 얻는 한 문장(`viewer_takeaway`), 이해 가능성 자기 검사. 둘째 편은 다른 아이디어·8점 이상일 때만. 후킹 리서치(14가지 훅) 적용 | shorts | high |
| ✍️ 카피라이터 | 유튜브 제목 5안, 설명란, 해시태그, 썸네일 문구, 고정 댓글 | youtube | medium |
| 🧐 아트 디렉터 | 렌더된 스틸만 보고(블라인드 비평) 넘침·가독성·과밀·강조색 남용을 지적 | 수정 지시 | high |

## 작업 흐름

```
전사본(+대본 태그, 메모, 편집 지시)
   │
   ▼
🎬 총괄 감독 ── 브리프(구조·비트·톤) ──┐
                                        ▼  (동시에, 같은 프롬프트 캐시 공유)
   ✂️ 편집   🎨 모션   🎞 자료   🔤 자막   📱 숏폼   ✍️ 카피
                                        │
                                        ▼
                     편집 계획(plan.json) ← 대본 태그는 항상 강제 반영
                                        │
   프록시·오디오 컷 → 자료 사진(위키미디어) → 🎞 스톡 통합 검색(Pixabay 등) → 후보 시트 → 비전 선택 → 다운로드·정리
                                        │
                                        ▼
   🧐 검수: 각 그래픽이 '도착한' 순간의 스틸 + 자막 스틸 → 문제 지적
        → 글자 줄이기 · 레이아웃 변경 · 삭제 · 🎨 모션 장면 재설계 → (설정한 라운드만큼 반복)
                                        │
                                        ▼
                             Remotion 최종 렌더(번들 재사용)
```

- **병렬 + 캐시**: 모든 에이전트가 같은 시스템 프롬프트(채널 헌장·스타일 가이드·후킹 가이드·카탈로그·모션 DSL·디자인 스킬 노트)와 같은 전사본을 공유합니다. 감독 호출이 캐시를 만들면 나머지 호출은 그 캐시를 읽어서 비용과 시간이 줄어듭니다. 에이전트별 토큰 사용량은 편집 리포트에 표로 남습니다.
- **실패에 강함**: 전문가 한 명이 실패해도 나머지 결과로 진행합니다. 총괄 감독이 실패하면 단일 디렉터 모드로, 그것도 실패하면 규칙 기반 편집으로 내려갑니다.
- **블라인드 비평**: 아트 디렉터에게는 설계 이유를 주지 않고 **렌더된 화면과 그 구간의 발화만** 줍니다. 설계자가 자기 설계를 변호하는 확증편향을 막는 방식입니다([remotion-director](https://github.com/anupamme/remotion-director)의 교훈).
- **정지 프레임 검수**: 움직이는 중간 프레임을 결함으로 오판하지 않도록, 진입 애니메이션이 끝난 순간(모션 장면은 모든 요소가 도착한 뒤)의 프레임을 뽑습니다.
- **틀린 B-roll 보다 없는 게 낫다**: 맞는 후보가 없으면 자료 리서처가 -1 을 고르고 그 컷은 빠집니다.

## 앱에서 쓰는 법

따로 켜고 끌 것이 없습니다. **① 주제 ② 원본 영상 ③ 대본**을 넣고 **영상 만들기 ▶** 를 누르면 팀 전체가 자동으로 일합니다.

진행 순서:
1. 🎨 컬러리스트(색)
2. 🎬 총괄 감독
3. 전문가 6명(병렬)
4. 🎞 자료 선택
5. 🧐 아트 디렉터 검수

진행 화면의 **AI 팀 작업 기록**에서 에이전트별 상태와 사용량을 볼 수 있습니다.

- 로그인 상태는 헤더 오른쪽 칩에서 확인합니다. `○` 이면 칩을 눌러 로그인하세요.
- 고급 설정(⚙):
  - 동시 에이전트 수(기본 4. 한도에 자주 걸리면 2로)
  - Pixabay 키(스톡 영상용, 선택. 사진은 키 없이 Openverse 로 검색) — [스톡 API 가이드](스톡_API_가이드.md)
- 팀이 정한 내용(제목·챕터·강조 순간·콜아웃·숏폼·음악 무드·색 룩)은 `부가자료/편집리포트.md` 와 `부가자료/plan.json` 에 남습니다.
- 편집 기술(프레이밍·소프트 컷·강조 글라이드·콜아웃·전환·효과음·덕킹)은 에이전트가 아니라 **편집 문법 엔진**(`studio/edit/grammar.py`)이 `PARAMS` 수치대로 입힙니다. 에이전트는 '어디를 강조할지'만 정합니다.
- 🎨 모션 디자이너는 장면 안에 `pixabay:<vector|illustration|photo>:<영어 검색어>` 이미지를 넣을 수 있고, 🎞 자료 리서처 단계가 실제 파일로 바꿉니다(못 구하면 그 요소만 빠짐).
- 📷 🎞 자료 리서처의 `photos`(인물·작품·사물·브랜드·장소·종교)는 스톡이 아니라 **위키백과 문서의 대표 이미지**로 채웁니다(ko → en, 자유 라이선스만, 크레딧). 대본의 라틴 문자 이름·『』 제목·종교는 규칙(`studio/broll/entities.py`)으로도 찾아 AI 가 놓친 것을 보탭니다. 위키백과에 없으면 스톡으로 넘기지 않고 뺍니다.
- 🃏 자유 HTML 카드는 기획 직후 **렌더 전 검사**(`renderer/scripts/check.mjs`, 렌더와 같은 Chrome)를 거칩니다: 글꼴 로드·글 넘침·캔버스 이탈·최소 글자 크기(26px)·WCAG 대비·런타임 오류. 걸리면 🃏 카드 디자이너(`card_revise`)가 검사 결과를 받아 한 번 고치고, 그래도 실패하면 키워드 카드로 대체합니다. 아트 디렉터도 `revise_card` 로 고칠 수 있습니다. 결과는 `plan.json` 의 `long.card_checks`.
- 📱 숏폼 기획은 3~5초마다 바뀌는 하단/카드 개념 텍스트(`beats`)도 씁니다. 숏폼은 롱폼의 그 구간 그래픽을 물려받습니다.

## 에이전트별 모델·사고 강도 바꾸기(고급)

`user/settings.json` 에서 에이전트별로 바꿀 수 있습니다.

```json
{
  "agent_effort": {"motion": "max", "copy": "low", "art_director": "xhigh"},
  "agent_models": {"copy": "claude-sonnet-5-5"}
}
```

키: `director`, `editor`, `motion`, `stock`, `stock_pick`, `captions`, `shorts`, `copy`, `art_director`, `motion_revise`, `card_revise`, `colorist`.

  - 📜 대본 충실도: 커버리지, 다시 말한 부분만 잘라 낸 테이크, 되살린 문장, 삭제 거절
  - 🎬 AI 스튜디오 브리프: 로그라인, 비트 표, 팀 메모
  - 🎛 자동 후반 작업: 목소리 레시피(잰 값과 고친 양), 오프닝 하이라이트 문장, 화면 구성
  - 🧐 아트 디렉터 검수: 라운드별 지적과 반영
  - 자료 사진·스톡 출처
  - 에이전트별 토큰 사용량
- `*_업로드정보.txt`: 설명란 맨 아래에 스톡 작가·제공처 크레딧이 자동으로 들어갑니다. 화면에도 ▣ 크레딧이 표시됩니다.
- `work/qa/r1/*.jpg`: 아트 디렉터가 실제로 본 스틸
- `work/stock.json`: 요청별로 고른 스톡 소재. 재실행하면 검색과 다운로드를 다시 하지 않습니다.
